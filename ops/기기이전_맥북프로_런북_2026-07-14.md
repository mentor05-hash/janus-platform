> 실행계획서 §2-2 전환 절차(①Docker+repo+.env ②DB 덤프/복원 리허설 ③터널 이관 ④헬스체크 후 맥미니 중지)의 구체 명령판.
> 원칙: **코드는 git(그냥 clone), 옮길 건 git 밖 3종(DB·배치표 데이터·업로드 볼륨) + 터널.** 저작권 데이터는 git·클라우드 금지 — 직접 전송만.
> 두 기기 사용자명이 다르면 경로의 `/Users/itall`을 각자 홈으로 바꾼다. compose 프로젝트명은 양쪽 모두 `itall-mentoring` 고정(볼륨명 일치).

## A. 맥북프로 사전 준비

1. **Docker Desktop 설치** → Settings → Resources: **메모리 8GB · CPU 6코어**(§2-2 상한). 한 번 실행해 초기 권한 승인.
2. 도구: `brew install git cloudflared` (Homebrew 없으면 먼저 설치).
3. **저장소 clone + 브랜치**:
   ```
   mkdir -p ~/janus/10_platform && cd ~/janus/10_platform
   git clone <레포URL> janus-platform
   cd janus-platform
   git checkout claude/connection-status-check-tm8we0
   ```
   (`<레포URL>` = 맥미니에서 `git remote -v`로 확인한 origin 주소.)

## B. git 밖 자산 이전 (핵심)

전송은 **AirDrop** 한 폴더로 묶는 게 가장 쉽다. 맥미니에서 `~/janus-migrate/` 를 만들어 아래 산출물을 모아 AirDrop → 맥북에서 받는다.

### B-1. DB — 두 경로 중 택1

**경로 1 (간단·권장): 신규 DB + 재시드** — 데모/시드 데이터만 필요하면 덤프 불필요.
- 맥북에서 C단계 `up --build` 하면 마이그레이션이 스키마를 만든다. 이후 시드가 필요하면:
  ```
  COMPOSE_PROJECT_NAME=itall-mentoring docker compose -f docker-compose.full.yml exec -T postgres \
    psql -U itall -d itall < apps/api/prisma/seed-sim.sql
  ```
  (다른 seed-sim-*.sql 도 동일 방식. 시뮬 계정 안내는 `시뮬레이션_계정_안내.md`.)

**경로 2 (충실·리허설): pg_dump 이관** — 현재 DB 상태를 그대로. §2 "덤프/복원 리허설"에 해당.
- 맥미니(스택 켠 상태):
  ```
  mkdir -p ~/janus-migrate
  COMPOSE_PROJECT_NAME=itall-mentoring docker compose -f docker-compose.full.yml exec -T postgres \
    pg_dump -U itall -d itall --clean --if-exists > ~/janus-migrate/db.sql
  ```
- 맥북(먼저 postgres만 기동 → 복원):
  ```
  COMPOSE_PROJECT_NAME=itall-mentoring docker compose -f docker-compose.full.yml up -d postgres
  # postgres healthy 될 때까지 10초쯤 대기 후
  COMPOSE_PROJECT_NAME=itall-mentoring docker compose -f docker-compose.full.yml exec -T postgres \
    psql -U itall -d itall < ~/janus-migrate/db.sql
  ```

### B-2. 배치표 데이터 (JANUS_DATA_DIR — 저작권, git·클라우드 금지)

- 맥미니의 `~/janus/20_data/` 를 **직접 전송**(AirDrop/rsync/외장). 예:
  ```
  # 맥미니 → 맥북 (같은 네트워크·SSH 켠 경우)
  rsync -av ~/janus/20_data/  <맥북사용자>@<맥북IP>:~/janus/20_data/
  ```
  또는 `~/janus/20_data` 폴더를 AirDrop.
- 맥북에서 최종 위치가 `~/janus/20_data/placement-hub/` 이면 override(아래 B-4)와 경로가 맞는다.

### B-3. 업로드 볼륨 (선택 — 자료·첨부 보존 시)

- 맥미니에서 볼륨을 tar로:
  ```
  docker run --rm -v itall-mentoring_storage:/d -v ~/janus-migrate:/b alpine tar czf /b/storage.tgz -C /d .
  docker run --rm -v itall-mentoring_rooms_storage:/d -v ~/janus-migrate:/b alpine tar czf /b/rooms_storage.tgz -C /d .
  ```
- 맥북에서 `up` 으로 볼륨이 생성된 뒤 복원:
  ```
  docker run --rm -v itall-mentoring_storage:/d -v ~/janus-migrate:/b alpine sh -c "cd /d && tar xzf /b/storage.tgz"
  docker run --rm -v itall-mentoring_rooms_storage:/d -v ~/janus-migrate:/b alpine sh -c "cd /d && tar xzf /b/rooms_storage.tgz"
  ```
- 데모만 볼 거면 생략 가능(첨부 이력만 비게 됨).
- ⚠ 512G 대응(§2-2): 앞으로 녹화·업로드는 로컬 대신 **Cloudflare R2**(StorageProvider)로 조기 전환 권장 — 이전 시점에 함께 검토.

### B-4. override compose 재생성 (배치표 허브 마운트)

맥미니에서 만든 `docker-compose.override.yml` 은 커밋 안 돼 있으니 맥북에서 다시 만든다(경로는 맥북 홈에 맞게):
```
cd ~/janus/10_platform/janus-platform
cat > docker-compose.override.yml <<'YAML'
services:
  api:
    environment:
      JANUS_DATA_DIR: /data/janus
    volumes:
      - /Users/<맥북사용자>/janus/20_data:/data/janus:ro
YAML
```

## C. 기동 + 검증

```
cd ~/janus/10_platform/janus-platform
COMPOSE_PROJECT_NAME=itall-mentoring docker compose -f docker-compose.full.yml -f docker-compose.override.yml up -d --build
```
- 마이그레이션 로그 확인(신규 테이블 적용): `... logs api | grep -E '0049|0050'` → `ok` 2줄.
- 헬스: `curl -s http://localhost:3000/api/v1/health` → `{"status":"ok"}`
- 허브 API: `curl -s http://localhost:3000/api/v1/placement-hub/list` → `available:true`(파일 있으면) 또는 `false`.
- 화면: `open http://localhost:8080` (관문 홈) · `/placement` · `/placement/hub`.

## D. 터널 이관 + 컷오버

- **퀵터널(임시 URL)**: `cloudflared tunnel --url http://localhost:8080` — 실행마다 URL 바뀜.
- **네임드 터널(고정 도메인, §2-2 "DNS 무변경 전환")**: 맥미니에서 쓰던 **같은 터널 토큰/자격증명**(`~/.cloudflared/*.json` + `config.yml`)을 맥북 `~/.cloudflared/` 로 복사 → `cloudflared tunnel run <이름>`. DNS 레코드 그대로라 도메인 무변경.
- **컷오버 순서**: 맥북 헬스체크 통과 확인 → 맥미니 스택 중지(`COMPOSE_PROJECT_NAME=itall-mentoring docker compose -f docker-compose.full.yml down`) → 맥미니 터널 종료.

## E. 롤백·주의

- 이전이 어긋나면 맥미니 스택을 다시 `up -d` 하면 즉시 복귀(맥미니 볼륨은 `down`으로 안 지워짐 — `down -v` 절대 금지).
- **공개 터널 켠 상태로 실제 배치표(저작권) 데이터 노출 금지** — 확인은 localhost, 공개는 무료 예시까지만(CLAUDE.md §4·W2 D6 점검표).
- `.env` 별도 파일 쓰는 경우 함께 이전(현재 compose는 인라인 env라 대부분 불필요). 시크릿은 git·AirDrop 로그에 남지 않게 주의.
- DB 덤프/볼륨 tarball 은 이전 완료 후 `~/janus-migrate/` 에서 삭제(PII·데이터 잔존 방지).
