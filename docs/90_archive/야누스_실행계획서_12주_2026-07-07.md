# 야누스 실행계획서 — 12주 체크리스트 (v1)

작성 2026-07-07(화) · 상위 문서: 통합 사업종합기획서 v2 · 실행 주체: 1인 개발(클로드 코드) + 외부 서비스 접합
사용법: **이 문서 자체가 체크리스트.** 매일 세션 종료 시 체크·갱신하고, 매주 일요일 주간 리뷰에서 다음 주를 확정한다.

태스크 유형 태그:
- **[CC]** 클로드 코드로 개발/작성 (세션에 그대로 지시 가능한 단위)
- **[EXT]** 외부 서비스 가입·연동 (사람이 계정/결제/협의 처리 필요)
- **[OPS]** 인프라·서버·백업
- **[DEC]** 의사결정 (Decision-Register에 번호·일자 기록)
- **[BIZ]** 사업·법률·영업
- 각 태스크에 ✅완료 기준 명시 — 기준 통과 전에는 체크 금지.

## 0. 운영 원칙 (1인 + 클로드 코드 체제)

1. **하루 1~3태스크 원칙.** 태스크는 "클로드 코드 한 세션에 끝나는 크기"로 쪼갠다. 안 끝나면 태스크를 쪼갠 것이지 실패가 아니다.
2. **매 세션 리추얼(고정):**
   - 시작: `CLAUDE.md` + `프로젝트_현황_이어가기.md` + 본 실행계획서의 "오늘" 항목을 컨텍스트로 로드.
   - 종료: ① 커밋+push ② `프로젝트_현황_이어가기.md` 갱신 ③ 본 문서 체크박스 갱신 ④ 결정 발생 시 Decision-Register 기록.
3. **금요일은 접합의 날, 주말은 버퍼.** 새 기능은 월~목, 금요일은 외부 연동·배포·테스트, 주말 태스크는 밀린 것 처리+주간 리뷰만.
4. **"완료"의 정의 = 실측.** 기존 프로젝트 관례(E2E·시뮬·부하 실측) 유지. 화면 캡처 또는 테스트 통과 로그가 없으면 미완료.
5. **한글 파일 패치 규칙 유지:** .cjs/HTML은 heredoc/python replace(정규식 깨짐 방지), Design 툴 산출물은 영문 파일명.

## 1. 깃허브 전략 — 올릴 것 / 절대 안 올릴 것

### 1-1. 저장소 구성 (3분리)

| 저장소 | 공개 | 내용 |
|---|---|---|
| `janus-platform` (**private**) | 비공개 | 모노레포 전체: apps/api·web·mobile·realtime-rooms, packages/*, 배치표_DDD_v2(엔진 코드+테스트), 티어 빌드 **파이프라인 코드**, 문서(docs/) |
| `janus-data` (**로컬 전용, 깃허브 미업로드**) | 없음 | 저작권·민감 데이터 일체(아래 1-2). git 저장소로 만들되 remote 없음(이력 관리만), 백업은 §2-4 암호화 경로로 |

### 1-2. 절대 깃허브 미업로드 목록 (유출 시 사업 리스크 직결)

- **저작권 데이터 원본·파생 전부**: `adiga_정시_2026결과_*.json`, `esteacher_*_3개년_*.json`, `고속_다년_*_INTERNAL.json`, `고속_어디가_병합_*.json`, `보정_calib_*.json`, `고속_표점_누백_환산.json`, `adiga_units_2026.json`, 수시 `admission-data.json` — 어디가/esteacher/고속 자료는 재배포 금지 조건이므로 **private repo도 불가**(깃허브 서버 복제 자체가 리스크). `janus-data` 로컬 전용.
- **티어 빌드 산출 HTML 중 회원 이상**(임베드 데이터 포함) — 무료판만 배포 대상.
- `.env*`, LiveKit/PG/Claude API 키, rooms api-key, JWT/HMAC 시크릿.
- 업로드 파일(생기부 등 PII), DB 덤프, 시뮬 계정 실데이터.
- 클로드 디자인 핸드오프 중 유료 폰트·외부 이미지 원본.

### 1-3. 강제 장치 [CC, W1에 구현]

- 모노레포 루트 `.gitignore`에 `data/`, `*.env*`, `seed-restricted/`, `dist-tier/{member,paid,consultant}/` 등 규약 경로 등록. 코드에서 데이터 경로는 전부 `JANUS_DATA_DIR` ENV로 참조(하드코딩 금지).
- **gitleaks** pre-commit 훅(시크릿 스캔) + 커밋 전 `git status` 확인을 세션 종료 리추얼에 포함.
- 최초 push 전 1회: 전체 트리에서 금지 패턴 스캔(파일명·"INTERNAL"·키 패턴). 과거 커밋에 섞였으면 히스토리 정리(BFG) 후 push.

## 2. 인프라 계획 — 맥미니 → 맥북프로(M1 Pro 16G/512G) → 클라우드

### 2-1. 원칙
- 어댑터 원칙 덕에 **이식은 ENV 교체 문제**다. 기기 전환·클라우드 전환 모두 "코드 무변경"을 완료 기준으로 삼는다.
- **정적(배치표·마케팅)과 동적(API·DB)을 분리**: 정적은 Cloudflare Pages/CDN에 올려 **내 기기가 꺼져 있어도 서빙**되게 한다. 동적만 자가 호스팅. → 맥북프로 전환기의 다운타임 리스크를 정적 트래픽(=획득 장치)에서 제거.

### 2-2. 맥북프로(M1 Pro 16G) 운용 스펙
- Docker 리소스 상한: 메모리 8G(pg 2G·redis 512M·api 2G·rooms 1G·web 정적), CPU 6코어. 나머지는 개발(클로드 코드)용으로 남긴다. 개발과 서빙을 같은 기기에서 할 때는 **compose 프로파일 분리**(serve/dev)로 이중 기동 방지.
- 512G 대응: 녹화·업로드는 처음부터 로컬 디스크에 쌓지 말 것 → StorageProvider를 **Cloudflare R2**(S3 호환, egress 무료)로 조기 전환[EXT]. LiveKit Egress 대상도 R2.
- Cloudflare Tunnel은 기기 이동이 쉬움: 새 기기에 `cloudflared` 설치 → 동일 터널 토큰 실행 → DNS 무변경 전환. 전환 절차(체크): ①맥북에 Docker+repo+`.env` 복원 ②DB 덤프/복원 리허설 ③터널 토큰 이관 ④헬스체크 후 맥미니 중지.

### 2-3. 클라우드 전환 기준 (미리 정해두는 트리거)
| 트리거 | 조치 |
|---|---|
| 지금 즉시 | 정적 사이트 → Cloudflare Pages · 파일 스토리지 → R2 (둘 다 무료 티어) |
| 실 PG 연동 시(W9~) | DB만 관리형으로 우선 검토(Neon/Supabase PG 등) — 결제·PII의 백업/가용성 책임 분리 |
| 동시접속 상시 500+ 또는 다운타임 민원 | API·rooms 컨테이너를 저사양 클라우드(Fly.io/작은 VPS)로, 맥은 개발기로 복귀 |
| 컨설턴트 티어 오픈 | Cloudflare Access(SSO) 적용 — 자가 호스팅 그대로 두고 접근만 클라우드 게이트 |

### 2-4. 백업 (W1에 자동화, 이후 매주 검증)
- 코드: 깃허브 private(=오프사이트 백업 겸용).
- 데이터(`janus-data`)·DB 덤프·`.env` 금고: **일 1회 자동** — ① Time Machine(외장) ② `restic`/`rclone`으로 암호화하여 R2 별도 버킷. 3-2-1 충족.
- 매주 일요일 리뷰에서 **복원 리허설 로그** 확인(백업은 복원이 검증돼야 백업).
