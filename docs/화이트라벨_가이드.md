# 화이트라벨 가이드 — 브랜드 설정화 + 에셋 자동생성

> 기능·동작은 그대로. **브랜드 값만 설정 한 곳에서 바꾸면 전체에 반영**됩니다.
> 새 사업자 세팅 = `branding.config.json` 수정 + `apply-branding` 실행 + 배포.

## 1. 단일 소스 — `branding.config.json`

```jsonc
{
  "appName": "멘토링 플랫폼",     // 앱명·헤더·스토어·약관
  "logoMark": "멘",               // 아이콘·스플래시·사이드바 로고 글자
  "tagline": "학습센터 선생님과 1:1 상담·멘토링",
  "company": "○○(주)",           // 약관·개인정보 회사명
  "contactEmail": "privacy@REPLACE",
  "supportEmail": "support@REPLACE",
  "colors": { "primary": "#0E5C7C", "primaryDark": "#0A4A64", "primary500": "#1A7FA8", "accent": "#F3B34D", "ink": "#16242B" },
  "ids": { "bundleId": "com.example.mentoring", "scheme": "mentoring", "slug": "mentoring-platform" },
  "urls": { "apiBase": "https://api.REPLACE/api/v1", "webOrigin": "https://app.REPLACE", "privacyUrl": "...", "termsUrl": "..." }
}
```

## 2. 적용 — `node scripts/apply-branding.mjs`

읽어서 자동 반영:
- **생성 파일**: `apps/web/src/branding.generated.ts`, `apps/mobile/src/branding.generated.ts` (앱 코드가 import: `APP_NAME`·`LOGO_MARK`·`COLORS`)
- **에셋 자동생성**(headless Chrome): `apps/mobile/assets/{icon,adaptive-icon,splash-icon,notification-icon}.png`, `apps/mobile/store/feature-graphic.png` — 로고 글자 + primary 컬러로 렌더
- `--no-assets` 옵션: TS 생성만(에셋 스킵)

## 3. 값이 흘러가는 곳 (설정 → 코드)

| 설정 | 반영 위치 |
|---|---|
| `appName` | 웹 사이드바 헤더(AppLayout·StudentLayout·AdminLayout), 모바일 app.config.js `name`, 약관·개인정보 서비스명 |
| `logoMark` | 아이콘·스플래시·피처그래픽, 웹 사이드바 로고 |
| `colors.primary/…` | 웹 CSS 변수 `--teal`(main.tsx 주입), 모바일 theme.ts 팔레트, app.json 스플래시·adaptiveIcon 색 |
| `company`·`contactEmail` | 약관·개인정보(API `legal.content.ts` — ENV `BRANDING_COMPANY`·`BRANDING_CONTACT_EMAIL`) |
| `ids.bundleId/scheme/slug` | 모바일 `app.config.js`(iOS bundleIdentifier·Android package·scheme·slug) |
| `urls.apiBase/webOrigin` | `app.config.js` extra(앱 API·임베드 세션 주소) |

> app.config.js 가 app.json(권한·플러그인 등 **기능 설정**)을 베이스로 **브랜드 필드만** 덮어씀 → 기능 불변.

## 4. API(약관·회사명) ENV

```bash
BRANDING_APP_NAME="○○ 멘토링"
BRANDING_COMPANY="○○ 주식회사"
BRANDING_CONTACT_EMAIL="privacy@○○.com"
```
docker-compose/서버 env 에 넣으면 약관·개인정보에 반영(미설정 시 현재 기본값).

## 5. 새 사업자 세팅 순서

```bash
# 1) 브랜드 값 편집
vi branding.config.json            # 앱명·로고글자·색·회사·도메인·번들ID

# 2) 적용(생성파일 + 에셋)
node scripts/apply-branding.mjs

# 3) API env(약관 회사명)
#    docker-compose / 배포 env 에 BRANDING_* 설정

# 4) 빌드·배포
(cd apps/web && npm run build)
(cd apps/mobile && npx expo export -p web)   # 또는 eas build
```

## 6. 남는 사업자별 확정(코드 아님)

- 스토어 개발자 계정(Apple/Google)·앱 심사 제출
- 실 도메인·HTTPS, 관리형 DB·스토리지·푸시(FCM/APNs) 자격증명 → 어댑터에 주입(코드 불변)
- PG·카카오 알림톡 등 연동 자격증명, 개인정보/약관 법무 검토
- (인프라 식별자: `DATABASE_URL`·`COMPOSE_PROJECT_NAME` 등은 배포 환경에서 설정 — `docs/백엔드_프로덕션_준비.md`)

## 참고
- **기능·동작 불변** — 이 설정은 브랜드 표현만 주입합니다. 기본값 = 현재값이라 미변경 시 화면 동일.
- `branding.generated.ts`·에셋은 **생성물**(커밋됨). 값 바꾸면 `apply-branding` 재실행으로 재생성.
