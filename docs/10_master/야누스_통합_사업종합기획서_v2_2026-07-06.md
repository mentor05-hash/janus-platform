# 야누스(Janus) 통합 사업 종합기획서 v2 — 미래 청사진

작성 2026-07-06 · **v2 개정: 학습 상품 라인(과외·클리닉·라이브·자체 VOD 인강)과 '레벨 기반' 진단·학습설계를 상위 기획에 편입. "좌석"=온라인 강의실 정원(오프라인 아님) 명시.** · 통합 대상: ① 잇올 멘토링 플랫폼(모노레포, feat/consulting-intake) ② 야누스 입시 데이터 도구군·관문 사이트
용도: 두 프로젝트를 하나의 상위 기획으로 묶는 마스터 플랜. 이후 모든 개별 기획의 상위 참조 문서.

---

## 0. 한 문장 정의

> **야누스는 "치열한 현재"의 데이터를 읽어 "안정된 미래"로 가는 문을 여는 관문 플랫폼이다.**
> 진단(무엇이 부족한가) → 처방(무엇을 하면 되는가) → 실행(누구와, 어떤 도구로) → 통과(목표 달성) → 다음 관문.
> 이 사이클을 **수요자(학생·학부모)와 공급자(선생님·컨설턴트·학원·교육기업)** 양쪽 모두가 야누스 위에서만 완결할 수 있게 만든다.

야누스가 파는 것은 개별 기능이 아니라 **"최적화된 솔루션 + 그것을 실제로 수행하게 하는 도구"의 묶음**이다. 이를 위해 자체 개발 기능과 외부 툴·서비스를 가리지 않고 통합하며(어댑터·파트너 허브·SSO), 서비스를 받으려는 쪽과 제공하려는 쪽을 하나의 플랫폼에 아우른다. 시작은 대입배치표·상담 매칭·온라인 상담 툴이고, 종착은 모든 대상(학생·학부모·선생님·학원·교육기업)이 이 플랫폼에 묶여 돌아갈 수밖에 없는 구조다.

핵심 명제: **경쟁자들은 "도구"나 "매칭" 중 하나만 판다. 야누스는 진단 데이터가 실행 서비스를 부르고, 실행 결과가 다시 진단 데이터를 좋게 만드는 폐쇄 루프를 가진 유일한 플랫폼이 된다.**

## 1. 왜 지금 통합인가 — 두 자산의 상보성

| | A. 잇올 멘토링 플랫폼 | B. 야누스 데이터 도구군 |
|---|---|---|
| 본질 | **실행 인프라** (매칭·예약·실시간수업·강의·컨설팅·정산) | **진단 엔진** (합격예측·배치표·입결·계산기) |
| 강점 | 계정/역할/결제/실시간/화이트라벨까지 프로덕션급 완성 | 실측 데이터+검증된 예측(계열보정 MAE 4.96, 다년 앵커) |
| 약점 | "왜 상담을 받아야 하는가"의 **동기(진단)** 부재 | 진단 후 "그래서 뭘 하지"의 **실행 경로** 부재 |
| 수익 | 크레딧(상담)·원화(컨설팅)·좌석(강의) — 구조는 있으나 유입 부족 | 무료 미끼로 강력하나 자체 수익화 약함 |

**A의 파이프에 B의 물을 흘리는 것**이 이번 통합의 전부다. B(배치표)는 최고의 고객 획득 장치, A는 최고의 수익화 장치이며, 둘을 잇는 관로(성적 브리지·SSO·추천 커리큘럼)는 양쪽에 이미 절반씩 구현되어 있다.

## 2. 현재 보유 자산 총람 (즉시 가동 가능 수준)

### 2-1. 진단 레이어 (야누스)
- 정시 정밀배치표 v22: 입력 3모드, 고속 예측↔어디가 실측 토글, 추천 4구간+성향, 신뢰도 배지, 3개년 추세, **성적 자동연동(janus_score)**
- DDD v2 엔진(순수 도메인, 테스트 34개) + 2026 실측 정본 6,852 유닛
- 수시 입결 인터랙티브(16,129 모집단위·191대학, 생기부 세부입력판), 반영교과 등급 계산기(73개대)
- 검증 완료: 백테스트(다년 MAE 8.4, "작년 70%컷=합격률 37%" 등 상담 콘텐츠화 가능한 인사이트 다수)

### 2-2. 실행 레이어 (잇올 플랫폼)
- 예약·상담: 매칭→견적→예약 상태머신, 휴게버퍼, 크레딧 경제(1크레딧=0.5원, share 60%), 급여·평가·대시보드
- 실시간: 채팅+화이트보드(확정 2000획 <1ms 렌더)+음성, 세션 시간창, **1:다 강의실**(서버권위 판서 게이팅, LiveKit 음성/녹화, ENV만 넣으면 가동 — 녹화 파이프라인(egress→S3)은 그대로 **자체 VOD 인강의 제작 라인**이 됨)
- 대입 컨설팅 접수: 신청→업로드→결제 게이트→배정→**LLM 3산출물(마스킹)**→검수, 220건 시뮬 0실패
- 성적 수집: scores 모듈 + **Claude 비전 OCR**(성적표 사진→과목/점수)
- 화이트라벨 룸 서비스: API-key 프로비저닝, HMAC 토큰(epoch 폐기), Redis 수평확장 실측(전달 100%)

### 2-3. 유통·브랜드 레이어
- 야누스 브랜드(로고·스토리·컬러 확정), 관문 홈(자유서술→의도분류→커리큘럼 카드, LLM 훅), 서비스 허브 7종 페이지
- 4단계 티어 배포 설계(무료/회원/유료/컨설턴트, 빌드 분리로 데이터 유출 원천 차단)
- 인프라: 맥미니+Cloudflare Tunnel 계획, 마케팅 정적 사이트 생성기

**결론: "0→1"은 끝났다. 남은 것은 접합(§4)과 상품화·유통(§6~7)이다.**

## 3. 대상 통합 — 양면 플랫폼 구도

수요자와 공급자를 하나의 계정 체계·데이터 규약 위에 올린다.

| 대상 | 야누스가 주는 것 | 야누스가 얻는 것 | 잠금(lock-in) 장치 |
|---|---|---|---|
| **학생** | 무료 진단(배치표)→맞춤 커리큘럼→상담/강의/컨설팅 | 성적·목표·행동 데이터 | 성적 1회 입력이 전 서비스에 연동(janus_score), 기록 누적 |
| **학부모** | 자녀 통합 리포트(배치표+출석+상담기록 주간) | 결제 결정권자 확보 | 리포트는 야누스에서만 생성됨 |
| **선생님/컨설턴트** | 매칭 유입, 수업 도구(화이트보드·강의실), share 60% 정산 | 공급 capacity, 상담 기록 데이터 | 정산·평가·등급(S/A/B)이 플랫폼 내 이력 |
| **학원(센터)** | 센터 관리(예약·평가·대시보드), 화이트라벨 룸/배치표 | B2B SaaS·API 매출 | 운영 데이터·학생 계정이 플랫폼에 귀속 |
| **교육기업** | 허브 입점(인강·모의고사·자소서·플래너), SSO 트래픽 | 제휴 수수료·데이터 파트너십 | 야누스 커리큘럼 추천에 노출되는 유일 경로 |

"모든 대상이 묶여 돌아갈 수밖에 없는" 구조 = **데이터 귀속**(성적·기록·정산 이력이 야누스 계정에 쌓임) + **추천 관문 독점**(진입 트래픽이 관문 홈의 커리큘럼 추천을 통해 배분됨).

## 4. 통합 제품 아키텍처 — "야누스 OS" 3층

```
┌────────────────────────────────────────────────────────┐
│ L3 서비스: 배치표·입결 │ 상담·멘토링 │ 강의실 │ 컨설팅 │ 파트너(인강 등) │
├────────────────────────────────────────────────────────┤
│ L2 공통 데이터 규약:                                     │
│   · janus_score (성적 단일 규약: OCR/수기 → 전 도구 자동주입)  │
│   · janus_goal  (목표대학/전형 — 상담기록·배치표·컨설팅 공유)   │
│   · janus_report(진단·격차·추천 — LLM 산출물 표준 스키마)      │
├────────────────────────────────────────────────────────┤
│ L1 플랫폼 코어: SSO(HMAC 토큰 일반화) · 계정/역할 · 결제      │
│   (크레딧+원화) · 알림 · StorageProvider · LlmProvider ·    │
│   실시간 룸(화이트라벨) · 티어 게이트(무료/회원/유료/컨설턴트)   │
└────────────────────────────────────────────────────────┘
```

접합 작업 4개가 통합의 전부이며, 모두 기존 자산의 연장이다:

1. **SSO 일반화** — 룸 서비스 HMAC 토큰 패턴(스코프·만료·epoch 폐기)을 서비스 간 SSO 토큰으로 승격. 3티어(링크→SSO→데이터 연동) 로드맵은 이미 랜딩에 소구됨.
2. **성적 파이프 연결** — scores 모듈(OCR 포함) 출력 ↔ `janus_score` 규약 상호 변환. 성적 1회 입력 → 배치표·수시입결·계산기 자동 반영(입결 도구 ingest 스니펫만 추가하면 됨, 야누스 미결 #4).
3. **추천 엔진 실연결** — 관문 홈 LLM 훅을 플랫폼 LlmProvider(Claude 어댑터)에 연결. 입력에 janus_score·상담기록을 넣어 커리큘럼 카드의 정확도를 격상(야누스 미결 #3).
4. **컨설팅 LLM에 배치표 근거 주입** — 3산출물에 "배치표 근거(지원가능선·격차·다년추세)" 필드 추가 → 진단 초안이 데이터 기반으로 격상(잇올 보고서 §6-B).

배치표 코드베이스 이식은 어댑터 원칙대로 **② 독립 서비스+SSO/API 연동으로 시작 → ① 데이터 모듈(ext-ranking) 흡수로 수렴**. 정적 HTML 티어 빌드는 그대로 두고, 유료·컨설턴트 티어부터 플랫폼 계정 게이트로 전환한다.

## 5. 고객 여정 · 성장 플라이휠

**여정 1 — 대입(고2~N수):**
성적표 사진 1장(OCR) 또는 관문 홈 한 줄 질문
→ ① 무료 배치표: 지원가능선 + **격차 리포트**("목표까지 누백 X 부족, 작년 70%컷은 실제 합격률 37%")
→ ② 커리큘럼 카드: 격차 원인별 처방(과목 상담 / 1:다 강의 / 종합 컨설팅)
→ ③ 상담 예약(크레딧) — 상담사는 학생의 배치표·격차를 이미 보고 들어옴(상담 질 상승)
→ ④ 필요 시 컨설팅(원화 15만~, 생기부 업로드·LLM 초안·컨설턴트 검수) / 정기 강의(좌석)
→ ⑤ 성적 재입력 → 격차 변화 확인 → 재추천 (리텐션 루프)

**여정 2 — 레벨 미스매치(중·고 전학년, 신규 웨지 시장):**

- (후행) 고1인데 중학 기초 결손 → 학년제 학원은 받아줄 곳이 없고, 인강은 뭘 들어야 할지 모른 채 "빠른 진도" 욕심으로 이도저도 못 하고 실패.
- (선행) 초·중 최상위인데 3~4살 위와 수업해야 함 → 개인지도·인강밖에 없는데 보호자 포함 정보 부족으로 시간 낭비.

야누스 여정: 수준 진단(진단 상담+성적 OCR, 학년 무관 단원별 위치 파악)
→ **예산·기간 입력** → 온·오프라인 조합 학습설계(예: 월 30만 = 주1 소그룹 클리닉 + VOD 자습 + 월1 점검 상담)
→ 실행(플랫폼 내 과외/클리닉/VOD) → 주기 재진단으로 **진도 페이싱 가드**(과속·과욕 실패 패턴 차단) → 격차 해소 확인.

이 세그먼트는 **학년제 학원이 구조적으로 못 푸는 시장**(공급 공백)이라, 레벨 기반 온라인만이 해법 = 야누스의 차별화 진입점(웨지). 대입 배치표가 '고2~N수'를 부른다면, 레벨 진단은 '중·고 전학년+보호자'를 부른다 — 획득 깔때기의 입구가 2배로 넓어진다.

**플라이휠:** 무료 진단이 사용자를 부른다 → 사용자가 성적·결과 데이터를 남긴다 → 데이터가 예측(보정)과 추천을 좋게 만든다 → 진단·추천의 질이 더 많은 사용자와 공급자를 부른다 → 공급자가 늘면 실행 선택지가 늘어 전환율이 오른다.

**전환율이 이 사업의 심장이다.** 관리 지표: 성적입력→배치표 사용률, 배치표→상담 전환율(핵심), 상담→컨설팅/강의 전환율, 재입력(리텐션)율.

## 6. 학습 상품 라인 — "학년"이 아니라 "수준"

### 6-1. 전달 형태 4종 (모두 자체 인프라, 대형 인강업체 비경유)

| 상품 | 형태 | 정원 | 과금(안) | 기술 기반 현황 |
|---|---|---|---|---|
| **1:1 온라인 과외** | 실시간(화이트보드+음성+기록) | 1 | 크레딧·시간제 | 멘토링 룸 그대로 — **즉시 가동** |
| **소그룹 클리닉** | 실시간 1:3~8, 회차 패키지 | 3~8 | 정원제 패키지(원화) | 강의실 정원 파라미터 축소만 — **즉시 가동** |
| **라이브 강의** | 1:다(~수백), 판서+음성 | ~수백 | **좌석당**(=온라인 강의실 정원 1석) 또는 멤버십 | 완성(LiveKit ENV만) |
| **자체 VOD 인강** | 라이브 녹화→편집→상시 판매 | 무제한 | 수강권·구독 | 녹화(egress→S3) 완성 / 플레이어·수강권·목차화 **신규 필요** |

- ※ 용어 확정: 본 기획의 "좌석"은 **온라인 강의실의 정원 단위**를 뜻함(오프라인 학원 좌석 아님).
- 4종은 하나의 제작 라인: **라이브 강의를 찍으면 VOD가 남는다.** 강사는 한 번 가르치고 두 번 판다(라이브 좌석 + VOD 수강권) — 이것이 대형 인강업체를 거치지 않고도 강사가 야누스에 들어올 유인이자, 콘텐츠 원가를 0에 수렴시키는 구조.
- 클리닉은 과외(고단가)와 라이브(저단가) 사이의 중간 가격대를 메워 **예산 사다리를 촘촘하게** 만든다.

### 6-2. 수준 진단(레벨링) — 진단 레이어의 2번째 축

현재 진단은 "대입 위치"(전국 누백). 여기에 "학습 수준"(학년 무관, 단원별 성취 위치)을 추가한다.

- **v1(즉시, 콘텐츠 불필요):** 진단 상담 상품화 — 상담사(선생님)가 성적 OCR+짧은 구술/문답으로 결손·선행 지점을 판정, LLM이 상담 기록을 표준 진단서(janus_report)로 정리. 기존 상담 인프라 재사용.
- **v2(중기):** 지식맵(단원 선수관계 그래프) + 자가 진단 문항 은행 → 자동 레벨 판정, 재진단으로 진도 추적.
- 진단 결과는 배치표와 동일 규약(janus_score/goal/report)에 실려 학습설계·매칭·학부모 리포트에 자동 공급.

### 6-3. 예산 최적화 학습설계 (처방 엔진)

입력: 수준(진단) · 목표 · **월 예산** · 기간 → 출력: 온·오프라인 조합안 + 주간 실행 플랜.

- 규칙 베이스(가격표×효율 매트릭스) + LLM 해석(관문 홈 훅 재사용)으로 시작, 실행 데이터가 쌓이면 조합별 성과로 보정.
- **페이싱 가드 원칙:** "빠른 진도=성공"이 아님을 시스템이 강제 — 재진단 통과 전 다음 단계 미추천, 과속 시 경고. (백테스트의 "작년 70%컷=합격률 37%"처럼, 통념을 데이터로 교정하는 것이 야누스의 브랜드다.)
- 오프라인 옵션(지역 학원)은 초기엔 정보 제공, Phase 3에서 B2B 제휴 센터 연결로 확장.

### 7-1. 수익원 매트릭스

| B2C 학습 | 수준 진단+학습설계 | 진단 상담(크레딧) → 설계서 발급 | v1 즉시(상담 재사용) |
| B2C 실행 | 대입 컨설팅(종합/부분) | 원화 전용(15만~, full은 맞춤 견적) | 가동 가능(수동 PG) |

### 7-2. 경제 설계 원칙
- **무료(배치표·간이진단) → 크레딧(상담·과외) → 원화(클리닉·VOD·컨설팅) → 좌석(라이브)** 의 촘촘한 단가 사다리. 무료 티어는 절대 훼손하지 않는다(획득 장치). VOD는 한계비용 0 상품으로 사다리 전 구간의 마진을 받친다.
- 공급자 정산은 share 60% 유지하되, **배치표-발 전환 매출의 귀속 규칙**(추천으로 유입된 상담·컨설팅 매출의 소개 크레딧/수수료)을 신설 — 공급자가 배치표를 자기 영업 도구로 쓰게 만드는 게 목적.
- 크레딧 소멸률(가정 30%)이 마진의 핵심 변수 → 대시보드 상시 관측 지표로 승격.
- 컨설팅은 원화 전용 유지(고단가 상품의 크레딧 침식 방지). 크레딧 허용은 Premium+ 한정 부분할인 정도만 추후 검토.

### 7-3. 가격 미결(결정 필요)
① 유료 티어 가격대(월 구독 vs 멤버십 등급 포함) ② 무료판 노출 학과 수(3 vs 5) ③ 강의 좌석 단가 vs 멤버십 포함 ④ B2B 배치표 라이선스 구조.

## 8. 단계별 로드맵 (청사진)

### Phase 0 — 접합·개통 (지금 ~ 1개월) : "한 몸 만들기"
- [기술] SSO 토큰 일반화(HMAC 패턴 승격) · janus_score ↔ scores 상호 변환 · 입결 도구 ingest 추가 · 관문 홈 LLM을 LlmProvider에 연결
- [기술] LiveKit ENV 투입(실음성·녹화 개통, 코드 변경 0) · git 원격 연결/push · 마케팅 사이트 웹 실라우트 이식
- [배포] 맥미니+Cloudflare 개통(Phase 0~5 체크리스트) · 무료/회원 티어 빌드 파이프라인(TIER+FLAGS+마스킹)
- [브랜드] 히어로 확정 로고 교체·배경 택1 적용(클로드 디자인 결과 반영)
- **출구 기준: 성적 1회 입력 → 배치표 자동 반영 → 커리큘럼 카드 → 상담 예약까지 한 계정으로 끊김 없이 통과.**

### Phase 1 — 첫 매출 루프 (1~3개월) : "퍼널 검증"
- 무료 배치표 공개 배포(수능/모평 시즌 타이밍) + 격차 리포트 → 상담 전환 CTA
- 컨설팅 접수 실운영(수동 PG로 시작) · 상담사/컨설턴트 초기 공급단 온보딩(잇올 센터 인력 활용)
- **1:1 과외·소그룹 클리닉 파일럿**(레벨 미스매치 세그먼트 우선 — 즉시 가동 가능) · **수준 진단 v1**(진단 상담 상품화+LLM 진단서)
- 실 PG(토스 등) 연동 · 유료 티어 게이트(RedemptionCode 또는 CF Access) 오픈
- 학부모 주간 통합 리포트 v1(배치표+출석+상담기록)
- **출구 기준: 배치표→상담 전환율 실측치 확보, 유료 결제 첫 사이클 완주.**

### Phase 2 — 실행 상품 확장 (3~6개월) : "단가 사다리 완성"
- 라이브 강의 상용화(좌석 SKU 확정) · **자체 VOD 상품화**(녹화→편집→플레이어·수강권, 다시보기=회원 혜택에서 정식 SKU로) · 모바일 강의실/음성
- **예산 최적화 학습설계 엔진**(규칙+LLM) · 지식맵 v1(주요 과목 단원 그래프)
- 컨설팅 LLM에 배치표 근거 필드 → "데이터 기반 진단서"로 상품 격상 · 환불 플로우
- 수시 라인 통합(수시 입결+생기부 계산기 → 수시 컨설팅 퍼널) — 정시·수시 양대 시즌 대응
- 추천 엔진 고도화(상담기록·행동 데이터 반영) · 대시보드 피벗 정교화
- **출구 기준: ARPU 성장 확인, 시즌(9월 수시·12월 정시) 트래픽 처리 검증.**

### Phase 3 — 양면 개방 (6~12개월) : "플랫폼화"
- B2B API 상품화: 룸 서비스(완성) + 배치표 API(데이터 권리 협의 후) — 타 학원·에듀테크에 판매
- 파트너 허브 실입점(인강·모의고사·자소서·플래너) — SSO 3단계(링크→SSO→데이터 연동) 순차 개방
- 공급자 셀프서브(선생님/컨설턴트 직접 입점·심사·정산) · 배치표-발 매출 귀속 정산 가동
- **VOD 마켓플레이스화**(강사 직접 등록·정산 — 대형 인강 비경유 유통망) · 자가 진단 문항 은행 v2 · 오프라인 제휴 센터 연결(학습설계의 오프라인 옵션 실집행)
- 데이터 제휴·수급 합법화(대교협 협의 등) 병행
- **출구 기준: 외부 파트너 매출 발생, 공급자 수가 운영자 개입 없이 성장.**

### Phase 4 — 다음 관문 (12개월~) : "야누스의 본뜻"
- 2028 대입 개편(5등급제·수능 개편) 대응 — 엔진 파라미터화로 선제 대비(진로선택 P 처리 반전 등)
- 관문의 확장: 대입 통과자의 **다음 문** — 편입·유학·취업·자격 등 "진단→처방→실행" 프레임의 수평 복제
- 축적 데이터 기반 자체 예측 모델(외부 데이터 의존도 축소) — 저작권 리스크의 근본 해결책

## 10. 핵심 지표(KPI) 체계

- **획득**: 성적 입력 수(OCR 포함) / 관문 홈 질문 수 / 무료 배치표 MAU
- **전환(심장)**: 배치표→상담 전환율 / 상담→컨설팅·강의 전환율 / 회원→유료 전환율
- **수익**: ARPU, 크레딧 소멸률(마진), 컨설팅 건단가, B2B MRR
- **품질**: 예측 MAE(연 1회 백테스트 갱신), 상담 만족(평가 모듈), 강의 출석률
- **공급**: 활성 선생님/컨설턴트 수, share 정산액, 공급자 리텐션
- **학습 라인**: 진단→학습설계 채택률, 설계안 완주율(페이싱 가드 준수), 재진단 성취 상승폭, VOD 수강 완주율
- **플랫폼**: 재입력율(성적 2회+), 학부모 리포트 열람률, SSO 크로스서비스 이동률

2. 유료 티어 가격·게이트 방식(자체 코드 vs CF Access)
3. 무료판 노출 학과 수(3 vs 5)
4. 강의 좌석 과금 vs 멤버십 포함(크레딧 체계 편입 여부)
5. 배치표-발 전환 매출의 share 귀속 규칙
6. 컨설팅 크레딧 결제 허용 범위·환불 정책
7. 학부모 통합 리포트의 우선순위·과금 여부
8. 잇올 코드베이스 재사용의 권리 관계 정리
9. 클리닉 정원(3 vs 5 vs 8)·회차 패키지 가격, 과외 시간당 크레딧 단가
10. VOD 가격 모델(수강권 vs 구독)·강사 정산율·콘텐츠 보호 수준(워터마크/DRM)
11. 수준 진단 v1의 상품 포지션(유료 진단 상담 vs 무료 미끼) — 획득 vs 수익 트레이드오프
12. 지식맵 초기 과목 범위(수학 단일 시작 권장 — 선수관계가 가장 명확)
