## 2. 저장 규칙 (작업물을 "바로바로" 저장하는 법)

1. **모든 산출물은 생성 즉시 위 5폴더 중 하나로.** 어디인지 3초 안에 답이 안 나오면 `40_workbench/`에 넣고 일요일 리뷰에서 승격(00_docs)하거나 삭제한다 — 방치 금지.
2. **파일명 규약**: `주제_버전_YYYY-MM-DD.md` (예: `야누스_QnA_커뮤니티_리그_기획서_2026-07-07.md`). 디자인 폴더만 영문.
3. **살아있는 문서는 항상 1개**: 실행계획서·Decision-Register·각 기획서는 최신본만 제자리에 두고, 버전 갱신 시 구버전을 즉시 `90_archive/`로 이동. "v2가 어디 있더라" 검색이 필요 없는 상태 유지.
4. **문서의 서열**: 종합기획서(전략) > 확장청사진(장기 지도) > 실행계획서(전술·체크) > 기능 기획서(명세) > 디자인 브리프. 충돌 시 상위 문서가 이기고, 하위를 고친다.
5. **매 세션 종료 리추얼**(실행계획서 §4와 동일): 산출물 제자리 저장 → 커밋+push(00_docs 포함) → 실행계획서 체크 갱신.

## 3. 클로드 프로젝트(웹) 지식과의 동기화

- 클로드 프로젝트 지식에는 **최신 4종만** 유지: 종합기획서 v2 · 실행계획서 v2 · QnA 기획서 · 확장청사진. (기존 잇올 기능총괄보고서·야누스 종합보고서·디자인프롬프트 3종은 본 폴더 `90_archive/legacy_reports/`로 이관 완료 — 프로젝트 지식에서 교체 권장.)
- 문서를 v-업 할 때마다 프로젝트 지식도 같은 날 교체(일요일 리뷰 체크 항목).
