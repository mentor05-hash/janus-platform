> 목적: 외부 검토(타 프로젝트/AI 리뷰)용 단일 문서. 구현 완료 범위·작동원리·검증 상태·미결 사항을 총괄하고,
> 별도 프로젝트였던 **대입배치표**와의 통합 상위 기획을 위한 접점을 정리한다.

## 1. 제품 개요

**무엇**: 약 100개 학습센터(입시학원) 대상 **선생님–학생 1:1 멘토링/상담 예약 플랫폼**에서 출발해,
실시간 수업 도구(채팅·화이트보드·음성), **1:다 온라인 강의실**, **대입 컨설팅 접수**, 화이트라벨 실시간 룸 서비스,
마케팅 허브(랜딩+연계 서비스)까지 확장된 **입시 서비스 허브**.

**역할 5종**: 학생 · 학부모 · 선생님 · 센터관리자 · 인력관리(HR). 관리자 권한레벨 L1/L2/L3.

**스택**: NestJS(TypeScript, DDD 모듈) · PostgreSQL 16 · Redis 7 · React(웹, Vite) · React Native/Expo(모바일)
· 독립 실시간 룸 서비스(NestJS+socket.io) · Docker Compose. 모노레포(apps/api·web·mobile·realtime-rooms, packages/*).

**아키텍처 원칙(§CLAUDE.md)**: 12-factor 설정 외부화, **외부 의존은 어댑터 인터페이스 뒤로**
(StorageProvider local/S3 · LlmProvider mock/Claude · PaymentProvider manual/PG · MediaProvider mock/LiveKit ·
NotificationProvider · ZoomProvider), 마이그레이션 코드화(원시 SQL 48개), 무상태(수평확장), 로컬→클라우드 코드무변경 이식.

## 2. 기능명세 — 도메인별

### 2.2 실시간 수업 도구 (이번 확장의 기반)
- **채팅**: 답장(reply)·이모지 반응·낙관적 전송·읽음·타이핑·날짜구분선·무한스크롤(keyset cursor)·링크.
- **화이트보드**: 벡터 스트로크(필압)·펜/형광펜/지우개·이미지/촬영/PDF 배경·페이지 넘김·줌(1~8x)/팬(핀치·휠)·자동저장 스냅샷.
- **음성(1:1)**: WebRTC P2P 시그널 중계 + 통화 UI.
- **세션 시간창**: 라이브 세션(chat 제외)은 예약 [start−5분, end+5분]에만 쓰기 가능. 창 밖=열람 전용, 종료 시 서버발 강제 종료. 기록은 양측 열람 가능.

### 2.3 독립 실시간 룸 서비스 (화이트라벨 · apps/realtime-rooms)
다른 앱에도 판매 가능한 셀(채팅+화이트보드+음성 번들).
- 자체 DB 스키마(rooms), **API-key 프로비저닝** REST(`POST /rooms`, `/rooms/:id/tokens`, `/participants`, `/revoke`)
- **HMAC 룸 토큰**(참가자·룸·만료·epoch 서명) — epoch 증가로 일괄 폐기(revoke)
- 기능 플래그{chat,whiteboard,voice}·시간창(opens/closes)·만료정책·첨부 저장·메트릭(prometheus)·Redis 어댑터(수평확장)
- 멘토링 앱과는 **rooms-bridge**(플래그 REALTIME_ROOMS_ENABLED)로 점진 이관.

### 2.4 온라인 강의실 (1:다 판서 강의 · 이번 세션 신규)
- **강의 모드**(`mode=lecture`): **서버 권위 역할 게이팅** — DB의 참가자 role을 서버가 확인, host/presenter만 판서(wb:stroke/image/clear/save). 학생(viewer) 발신은 거부+전파 차단(토큰 위조 무력).
- **클래스 도메인**(멘토링 앱): `class_session`(개설·정원 기본100·상태 scheduled→live→ended)·`class_enrollment`(등록·역할·입장/퇴장=출석). 개설 시 룸 자동 프로비저닝, 학생 입장 시 참가자 **지연 발급**.
- **상호작용**: 손들기(hand:raise), **발표권 위임/회수**(lecture:grant/revoke — DB role 변경+lecture:sync로 다중 인스턴스 안전), roster:join/leave(참석 명단).
- **음성(SFU)**: `MediaProvider` 어댑터 — **관리형 LiveKit** 구현(HS256 video-grant 토큰: 선생님 canPublish / 학생 구독전용, 룸 스코프). 웹 `livekit-client`+`useLiveKitAudio`+`LectureAudioBar`(송출/수신 UI). ENV만 넣으면 실음성.
- **녹화(필수)**: `class_recording`(av/whiteboard·상태·URL) + LiveKit Egress(audio room composite→S3) 시작/종료/목록 API.
- **UI**: 웹 선생님 화면 `/app/classes`(개설·목록·시작/종료·명단(출석)·학생 검색초대 picker·입장=판서+음성 새 탭). 학생 열람전용 화면(도구 숨김·강의 배지·손들기) — 웹·모바일 동일.
- API: `POST /classes`, `/:id/enroll·join·start·end`, `GET /classes(:id)·roster·media-token·recordings`, `POST recording/start·stop`.

### 2.5 대입 컨설팅 접수 (이번 세션 신규 · apps/api/modules/consulting)
신청 1건 = 신청자·업로드 자료(생기부)·신청시간·결제여부·LLM 분석을 **하나의 애그리거트**로.
- **Phase1 신청/업로드**: `consulting_application/document`(0046). 동의 필수, 자료 **PDF·Word만**(mime+확장자, 20MB), 상태머신 draft→submitted→awaiting_payment→paid→in_review→completed.
- **Phase2 결제·게이팅·배정**: `PaymentProvider`(manual, **원화 전용 — 크레딧 결제 불가(추후 정책)**), full(종합)은 맞춤 견적 금액 필수. **열람 게이트**: 배정 컨설턴트는 결제 완료 후에만 자료 다운로드. 배정은 상품별(at_application/manual).
- **Phase3 LLM 분석**: 결제 완료 후, **식별정보 마스킹** 입력 → Claude(또는 mock) 3산출물(요약·강점/약점 / 진단 리포트 초안 / 서류 체크·정합성) JSON 저장. "검수용 초안" 명시, 신청자에겐 비공개.
- **Phase4 운영**: 역할별 인박스(GET /consulting/inbox), 알림(결제완료/배정/분석완료).
- 웹 공개 폼 `/consulting/apply`.

### 2.6 마케팅 · 허브
- 랜딩(잇올 브랜드, 컨스텔레이션 히어로, 역할별 시작, 반응형+스크롤 리빌) + **연계 서비스 허브 7종**

## 3. 작동원리 — 핵심 메커니즘

### 3.1 도메인 불변규칙 (테스트 시드 고정)
- **휴게 버퍼**: 모든 예약 앞뒤 10분. 유효슬롯 = 학생 체류 ∩ 선생님 근무 ∩ (예약+버퍼 제외).
- **요금 단일 소스**: cost=round(perHour×min÷60), S급 +20% 할증 후 계산.
- **크레딧**: 월 00:00 주간부여 / 일 24:00 소멸(이월 없음), **Premium(3등급)↑는 월간 풀**(end_of_month, 월1회 멱등). 소비순서 = 부여분(만료임박)→구매분. 동시성은 DB 트랜잭션+행잠금(advisory lock)+조건부 updateMany.
- **경제 설계**: **1크레딧=0.5원**(CREDIT_WON_RATIO, 급여 환산에만 적용). 급여 = 확정매출(크레딧×0.5)×**분배율 60%**(share 모델). 소멸률 30% 가정 시 마진 ≈ 30%. 등급 부여: Basic 0/Standard 3만/Premium 21만/VIP 35만 크레딧.

### 3.2 실시간·화이트보드 렌더
- socket.io 룸(`room:{id}`) 브로드캐스트, 부분 스트로크 20Hz 스트리밍(라이브 잉크)+최종 확정, 후발 참여는 join 스냅샷.
- **렌더 O(1)**: 확정 스트로크는 오프스크린 캐시에 1회 렌더 → 매 프레임 "배경+캐시 복사+진행 획"만 합성. **rAF 코얼레싱**(프레임당 1회) + **getCoalescedEvents**(초고속 획 중간점 복원). 지우개는 잉크 레이어에만 destination-out(배경/PDF 보존). 벡터라 확대해도 필기 선명.
- 벤치: 확정 2000획에서 기존 20.6ms/frame(49fps)→최적화 후 <1ms.

### 3.3 보안·게이팅 계층
- 전역 가드 체인: RateLimit→JWT→Roles→PermLevel. 응답 {data,meta} 엔벨로프, 오류 {error{code,message}}.
- 룸 토큰: HMAC 서명(참가자·룸·만료·epoch). **역할은 토큰이 아니라 서버가 DB에서 재확인**(강의 판서·컨설팅 열람 동일 원칙).
- 컨설팅 PII: 생기부=미성년 민감정보 — 접근은 결제완료+역할 게이트, LLM 입력 마스킹, 파일은 StorageProvider(로컬→S3 암호화 전제).
- 데모 안전장치: 더미 데이터만, 자동로그인 URL은 DEMO_MODE 플래그 뒤, 시크릿 git 금지.

### 3.4 확장성 (실측)
- 룸 서비스 부하테스트(룸당 2인, 20Hz 판서 스트리밍, 전달률·지연 실측):
  단일 인스턴스 **~1,200 동시 저지연(p95 59ms)** / 2,000에서 지연 증가(손실 0).
  **Redis 어댑터 2인스턴스** 크로스인스턴스: 같은 1,600 연결에서 p95 170→42ms(≈4배), 2,400 연결 p95 149ms, **전 구간 전달 100%** → 인스턴스 수에 준선형 확장.
- 강의(1송출:N수신)는 위 시나리오(전원 송출)보다 가벼움 → 강의실당 수백 명 무리 없음. 음성 상한은 LiveKit(관리형 스케일).

### 3.5 컨설팅 처리 흐름
신청+동의 → 자료 업로드(형식검증, 결제 전 허용) → 결제 생성(원화) → **결제확인=게이트**(스태프/웹훅)
→ 배정(상품별) → LLM 분석(마스킹, 3산출물) → 컨설턴트 열람·검수 → 완료. 220건 동시 시뮬 0실패(평균 1.2ms/건).

## 6. 대입배치표 통합 — 상위 기획 접점 (검토 요청 포인트)

현 플랫폼은 배치표를 받아들일 **접속·데이터·수익 인프라가 이미 있음**:

**A. 계정/SSO** — 잇올 계정 1개로 연계 서비스 진입(랜딩 허브에 이미 소구). 룸 서비스의 HMAC 토큰 패턴
(참가자 스코프·만료·epoch 폐기)을 **서비스 간 SSO 토큰**으로 일반화 가능. 3티어: 링크→SSO→데이터 연동.

**B. 데이터 파이프라인** — 배치표의 입력(내신/모의고사 성적·백분위)은 이미 **scores 모듈(+Claude 비전 OCR)**로
수집 중. 상담 기록(목표 대학)·컨설팅 분석(강점/약점) → 배치표 지원가능선과 상호 연동:
- 성적 입력 1회 → 배치표 자동 계산 → 격차 리포트 → 상담/강의/컨설팅 추천 (허브 선순환)
- 컨설팅 LLM 3산출물에 "배치표 근거" 필드 추가 → 진단 초안이 데이터 기반으로 격상.

**C. 수익 모델 결합** — 배치표 무료/등급제(멤버십 크레딧과 연동) ↔ 유료 컨설팅(원화) 업셀 동선:
배치표(무료 미끼) → 격차 확인 → 상담(크레딧) → 컨설팅(원화 15만~) → 강의실(1:다, 좌석당 과금 가능).
급여 share 60% 모델에 배치표-발 전환 매출 귀속 규칙 필요(검토 포인트).

**D. 기술 이식** — 배치표가 별도 코드베이스라면: ① 데이터(대학·학과·입결 테이블)만 이식해 새 모듈
(ext-ranking 자리)로 흡수, ② 또는 독립 서비스로 두고 SSO+API 연동(룸 서비스 패턴 재사용). 어댑터 원칙상 ②로 시작해 ①로 수렴 권장.

**E. 상위 기획 질문(리뷰어에게)**

2. 배치표 결과의 책임 범위 고지(예측 면책)와 컨설팅 업셀의 윤리적 경계?
3. 강의실 좌석 과금 vs 멤버십 포함 — 크레딧 체계에 넣을지 별도 SKU 인지?
