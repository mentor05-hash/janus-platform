# 백엔드 프로덕션화 준비 (스토어 앱 = 실서버)

> 스토어 앱은 로컬 docker가 아닌 **HTTPS 고정 도메인 실서버**에 붙습니다.
> CLAUDE.md §10(클라우드 이식)을 따르며, 코드 재작성 없이 설정·인프라만 전환합니다.

## 1. 필수 (출시 차단 항목)

- [ ] **HTTPS 고정 도메인 배포** — API `https://api.REPLACE/api/v1`. 앱은 `EXPO_PUBLIC_API_BASE`(eas.json production)로 주입. 자가서명·평문 HTTP 불가(ATS/Play 차단).
- [ ] **데모 모드 차단** — 프로덕션 빌드에서 `EXPO_PUBLIC_DEMO_MODE` 미설정(자동 false). 확인: 로그인 화면 데모 계정·`?u=&p=` 자동로그인 비노출. (웹 `VITE_DEMO_MODE`도 동일 차단)
- [ ] **JWT 시크릿 교체** — 로컬 `dev-jwt-secret-please-change` → 시크릿 매니저의 강한 값(`JWT_SECRET`). 리프레시 만료·회전 점검.
- [ ] **DB 관리형 PostgreSQL** — 로컬 docker → RDS/Cloud SQL. 로컬 비밀번호 `janus_local_pw` 폐기. 마이그레이션 0001~0043 순차 적용.
- [ ] **CORS·소켓** — 허용 오리진을 앱/웹 도메인으로 제한. 소켓 경로 `/api/v1/socket.io` 프록시·WSS 확인.
- [ ] **푸시 자격증명** — FCM(Android)·APNs(iOS) 키를 EAS/서버에 구성. expo-notifications 토큰 등록 경로 점검.

## 2. 데이터·보안

- [ ] **파일 스토리지** — 로컬 디스크 → S3/Cloud Storage(StorageProvider 교체). 첨부·화이트보드 이미지.
- [ ] **민감정보** — 학생·보호자 PII·상담내용·결제·급여는 DB에만. 저장소(git)엔 더미만(현행 준수). 응답 마스킹 유지.
- [ ] **레이트 리밋·차단** — 로그인 브루트포스, 파일 업로드 크기·형식 제한.
- [ ] **PG 결제(O2)** — `PgProvider` 어댑터에 실 PG사 연동(현재 추상화만). 웹훅 서명 검증(0038 웹훅 기반).

## 3. 운영·관측

- [ ] **구조적 로그 + 헬스체크** — `/health` 존재. 오토스케일·모니터링 연결.
- [ ] **스케줄러 단일화** — 주간 크레딧(월 00:00/일 24:00), 자동배정 채우기(15분), 역상담 스캔(새벽 3시)이 다중 인스턴스에서 중복 안 되게 cron-lock 확인(구현됨).
- [ ] **백업·마이그레이션 코드화** — 수동 SQL 금지, `migrations/` 버전관리.

## 4. 법무·컴플라이언스

- [ ] **개인정보처리방침·이용약관** 공개 URL 게시(앱 `LegalDocPage` 내용) + 법무 검토.
- [ ] **계정 삭제** 경로 노출(앱 내 회원 탈퇴 + 웹 안내) — 양대 스토어 필수.
- [ ] **결제·환불 정책**, 미성년자 결제 동의(보호자) 흐름 점검.

## 5. 환경 프로파일 (12-factor)

| 값 | local | production |
|---|---|---|
| API_BASE | http://localhost:3000/api/v1 | https://api.REPLACE/api/v1 |
| DEMO_MODE | true | (미설정=false) |
| DATABASE_URL | docker postgres | 관리형 PostgreSQL(시크릿) |
| JWT_SECRET | 로컬 상수 | 시크릿 매니저 |
| 파일 스토리지 | 로컬 디스크 | S3/Cloud Storage |
| 푸시 | 스텁 | FCM/APNs 실키 |

> 코드는 동일, 설정만 분기. 이식 = 배포 전환(재개발 아님).

## 수평 확장(다중 인스턴스) 체크리스트

API 인스턴스를 2대 이상으로 늘릴 때 필요한 설정(코드 변경 없음, 기본값=단일 인스턴스 무변화):

| 항목 | 설정 | 효과 |
|---|---|---|
| **소켓 실시간 공유** | `WS_REDIS_ADAPTER=true` (+ `REDIS_URL`) | 채팅·화이트보드·음성 시그널링이 인스턴스 경계를 넘어 전달(socket.io Redis pub/sub 어댑터). **미설정 시 in-memory=단일 인스턴스 전용.** |
| **Cron 이중실행 방지** | `CACHE_PROVIDER=redis` (+ `REDIS_URL`) | 모든 스케줄 잡이 `withCronLock`(Redis `SET NX EX` 분산 락)으로 1개 인스턴스만 실행. **이미 코드에 내장** — Redis 캐시만 켜면 활성. (특정 인스턴스만 스케줄러로 쓰려면 나머지에 `SCHEDULER_ENABLED=false` 도 가능) |
| 로드밸런서 | WebSocket 지원 + (권장) sticky session | 소켓 업그레이드 통과 |
| 음성 NAT | TURN 서버(coturn 등) | P2P 실패 시 미디어 릴레이(1:1) |
| 무거운 집계 | 월별 피벗 등 앱-메모리 O(N) 집계 → SQL/뷰 이전 | 이벤트 루프 블로킹 방지 |

검증: 두 인스턴스(Redis 어댑터 on)에서 A에 그린 화이트보드 획을 B의 참가자가
실시간 수신함을 E2E로 확인. 단일 인스턴스(기본, 어댑터 off)는 동작 불변.
