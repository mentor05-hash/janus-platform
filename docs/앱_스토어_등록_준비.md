# 앱 스토어 등록 준비 (iOS App Store · Google Play)

> 잇올 멘토링 모바일(Expo SDK 51 / RN 0.74) 스토어 출시 준비 문서.
> 최종 갱신: 2026-07-03

## 0. 핵심 판단 — 웹 우선(현재) vs 네이티브

현재 모바일은 **expo-web 우선**으로 구현돼, 몰입형 기능이 브라우저 API에 의존합니다.

| 기능 | 현재 구현 | 순수 네이티브 빌드 |
|---|---|---|
| 음성통화 | `getUserMedia`/`RTCPeerConnection`(WebRTC 웹) | ❌ → `react-native-webrtc` 필요 |
| 화이트보드 | DOM `<canvas>` | ❌ → `@shopify/react-native-skia` 등 필요 |
| 채팅 사진/카메라 | `getUserMedia`·DOM | ❌ → `expo-camera`/`expo-image-picker` |
| 토큰 저장 | localStorage(웹)/SecureStore(분기) | ⚠️ SecureStore 경로만 사용하도록 정리 |
| 실시간 | socket.io(웹소켓) | ✅ 네이티브 동작 |
| 푸시 | expo-notifications | ✅ 네이티브 동작 |

→ **경로 선택이 선행돼야 함**(§1). 아래 등록 준비물(§3~)은 경로와 무관하게 공통.

## 1. 출시 경로 옵션

- **A. 네이티브 WebView 래핑 (최속)** — 호스팅된 웹앱을 네이티브 셸(react-native-webview)로 감싸고 **푸시만 네이티브**. 웹 기능(음성·필기·카메라)은 WebView 권한(카메라·마이크)으로 그대로 동작. 심사 리스크: "단순 웹" 반려 → 푸시·오프라인·네이티브 UX로 방어. 1~2주.
- **B. 하이브리드 (권장)** — Expo 네이티브 셸 + 핵심 화면은 RN 네이티브, 몰입형(음성·필기)은 WebView 임베드 또는 단계적 네이티브 포팅. 균형. 3~6주.
- **C. 완전 네이티브 리라이트** — 음성(webrtc)·필기(skia)·카메라(expo-camera) 전면 포팅. 최고 품질·최대 비용. 6~10주+.

권장: **B(하이브리드)** — baseline은 네이티브, 음성·필기는 WebView로 우선 출시 후 네이티브 전환.

## 4. 스토어별 필수 준비물

### 공통
- **개인정보처리방침 URL**(필수, 공개) — 앱 내 `약관·개인정보` 화면 있음 → 웹 공개 URL로도 게시 필요
- **지원(문의) 이메일/URL**, 앱 아이콘(1024), 스크린샷(폰·태블릿)
- **연령 등급** 설문 — 본 앱: 사용자간 채팅/사진 공유 있음 → 안전 정책 명시

### Apple App Store
- Apple Developer Program 가입(연 $99)
- App Store Connect 앱 생성(bundleId `com.itall.mentoring`)
- 스크린샷: 6.7"(1290×2796) 필수 + iPad 12.9"(2048×2732, supportsTablet=true)
- App Privacy(수집 데이터 명시): 연락처·사용자콘텐츠(사진·메시지)·식별자·이용데이터
- **App Tracking Transparency**: 추적 없음(광고SDK 미사용) → 미해당
- **계정 삭제 경로**(필수, 2022~): 앱 내 `약관·개인정보 → 회원 탈퇴` 있음 → 심사노트에 경로 기재
- 심사 대응: 데모 계정(리뷰어용) 제공, WebRTC 권한 사유 명확화

### Google Play
- Google Play Console 등록(1회 $25)
- **데이터 보안(Data safety)** 폼: 수집 항목·목적·암호화·삭제요청 경로
- **개인정보처리방침 URL**(콘솔 필수)
- 스크린샷(폰 2장+), 512×512 아이콘, 1024×500 피처 그래픽
- **타깃 API 레벨** 최신 준수(SDK51 = 대응), 권한 사용 사유(카메라·마이크) 선언
- 콘텐츠 등급 설문(IARC), 앱 카테고리: 교육
- **계정 삭제**(Play 정책): 앱 내 + 웹 삭제 경로 URL 제출

## 6. 실행 순서

```bash
# 1) EAS 프로젝트 초기화(계정 로그인 필요 — 사용자가 직접)
cd apps/mobile
npx eas login
npx eas init            # → app.json extra.eas.projectId 자동 기입

# 2) 프로덕션 API 도메인·자격증명 반영
#   eas.json production env.EXPO_PUBLIC_API_BASE = 실제 API URL
#   submit.ios/android = 실제 자격증명

# 3) 빌드
npx eas build -p ios --profile production
npx eas build -p android --profile production

# 4) 제출
npx eas submit -p ios --profile production
npx eas submit -p android --profile production
```

## 7. 백엔드 전제 (스토어 앱 = 실서버)

- API를 **HTTPS 고정 도메인**으로 배포(현재 로컬 docker). §CLAUDE.md §10 클라우드 이식.
- 데모용 자동로그인(`?u=&p=`)·`VITE/EXPO_PUBLIC_DEMO_MODE`는 **프로덕션 빌드에서 비활성** 필수(보안).
- 소켓 경로 `/api/v1/socket.io`·CORS·푸시 자격증명(FCM/APNs) 실계정 구성.
- 개인정보·결제 실서비스 전 **개인정보처리방침·이용약관 법무 검토**.
