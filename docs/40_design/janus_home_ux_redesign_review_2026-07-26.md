## 0. 요약 (TL;DR)

1. **레퍼런스(jailbrain.ai/workspace)는 이 환경에서 접근 불가**(WebFetch 403·직접 curl 차단·검색엔진 미인덱싱). 확인이 필요하면 스크린샷 또는 저장 HTML을 `40_workbench/design/`(영문 파일명)에 반입해 달라. 다만 "workspace"형 AI 제품의 공통 문법(중앙 단일 입력창 + 최근 작업 피드 + 얇은 아이콘 레일)은 이미 우리 브리프의 **관문 홈**("무엇을 준비하고 있나요?" 입력 + 즉시 행동 타일 3)과 동형이므로, 방향 자체는 레퍼런스 없이도 확정 가능하다.
2. **진단 — 복잡도의 실체는 "기능 축적형 평면 내비"다.** 웹 학생 사이드바 12항목·선생님 14항목·관리자 22항목이 전부 1단계 나열이고, 메뉴가 사실상 백엔드 도메인(테이블) 목록을 미러링한다. 학생 로그인 첫 화면이 '내 예약 목록'(가치가 아닌 관리 화면)이며, 웹은 반응형 CSS가 **0줄**(모바일 대응 부재), 비로그인 랜딩은 구 잇올 정적 HTML iframe이라 앱과 단절돼 있다.
3. **처방 — 새 발명이 아니라 기존 브리프의 5탭 IA를 웹·모바일에 일관 적용 + 홈 신설.** ① 학생 웹 내비를 [홈·질문·진단·일정·내정보] 5그룹으로 수납(라우트 URL 불변, 표현만 재편 = 저위험) ② 로그인 첫 화면을 "나의 관문" 카드 대시보드로 신설 ③ 비로그인 랜딩 실라우트 이식(기존 지시서 스텝 3 그대로) ④ 모바일 학생 7탭 → 5탭 정합. 총 규모 4~6 클로드 코드 세션, 단계별 롤백 가능.
4. **결정 필요 3건([DEC] 후보)**: D-a 학생 로그인 랜딩을 예약목록 → 홈 대시보드로 변경 / D-b Q&A·커뮤니티를 "질문" 탭 하나로 통합(세그먼트) / D-c 웹 모바일 뷰포트에서 사이드바 → 하단 탭 전환. §6 참조.

## 1. 레퍼런스 검토 — jailbrain.ai/workspace (실물 분석 완료)

> 2026-07-26 사용자가 저장 페이지 4종(`workspace`·랜딩/로그인·고객센터·약관) 반입 → **실물 기준으로 §1 전면 재작성**. 초기 접근 시도(WebFetch 403·curl 차단·검색 미인덱싱)는 봇 차단 때문이었음.

### 1.1 제품 정체 — 무엇을 벤치마킹하는가

**제일브레인(Jail Brain.ai)** = "AI 워크스테이션 + AI 전문 커뮤니티". 멀티 오케스트레이션 엔진으로 여러 전문 AI가 협업·교차검증하는 작업 공간(범용·코딩·이미지·영상·3D·금융 6모드), 개인 지식저장소 JBM, 소셜(피드·팔로우·공개범위·신고), 크레딧·구독(무료/Lite/Pro/Ultimate). Next.js + Tailwind(HSL 토큰) + Pretendard.

**야누스와 구조적으로 닮은 지점**: ① 서비스가 계속 늘어나는 다기능 플랫폼 ② 크레딧·구독 티어제 ③ 커뮤니티 병설 ④ 무료 체험 → 로그인 → 유료 전환 퍼널 ⑤ 한국어 우선. 즉 **"기능이 늘어도 첫 화면이 안 무너지는 법"의 직접 사례**로 유효하다.

### 1.2 실측한 IA — 1차 내비가 단 3~4개

| 영역 | 구성 |
|---|---|
| 데스크톱 좌측 레일 | **폭 64px 아이콘 전용**, hover 시 240px로 확장하며 라벨 노출(`w-16 hover:w-60`). 상단=화면모드·언어(유틸), 중앙=**제일브레인(워크스페이스)·[대시보드]·소셜·[프로필]**, 하단=더보기 |
| 더보기(시트) | JBM-RAG · 고객센터 · 설정 · 약관 및 정책 — **저빈도 전부 수납** |
| 모바일 | 하단 **플로팅 pill 탭바**(rounded-full·backdrop-blur·shadow-xl), 44×44 아이콘, safe-area 패딩, 스와이프 인덱스(`data-navidx`) |
| 워크스페이스 본문 | 브랜드마크 애니메이션 → 타이틀 → 한 줄 설명 → **"현재 모드 · 일반" 상태 칩** → (하단 고정) 모드 칩 행 + 대형 입력창 |
| 우측 작업 패널 | 접기·크기조절 가능(기본 접힘), 라이브러리 + 대화 내역. 접힘 시 가장자리 손잡이 버튼으로 펼침 |

**핵심 관찰**: 기능은 6개 모드 + JBM + 라이브러리 + 소셜 + 대시보드 + 구독 + 고객센터로 우리보다 적지 않은데, **1차 내비는 로그인 상태에서도 4개**다. 나머지는 전부 ① 더보기 시트 ② 본문 안의 칩·패널로 흡수한다. 우리가 §2에서 진단한 "축적형 평면 내비"의 정반대 해법이며, 이번 개편의 5탭 고정 원칙과 같은 결론이다 — **개편 방향이 레퍼런스로 검증됨**.

### 1.3 즉시 적용 가능한 요소 (실물에서 추출)

| # | 레퍼런스 요소 | 야누스 적용 판단 |
|---|---|---|
| R1 | `word-break: keep-all; text-wrap: pretty` (`.dash-typo`) | **✅ 즉시 채택 — 실측 결함 수정.** 우리 개편 캡처에서 "상담으로 이어가/세요", "사진 한 장이면 충분해/요"처럼 어절 중간이 깨졌다. 한글 서비스의 조판 기본기 |
| R2 | `@media (pointer:coarse)` 입력 글자 **16px 강제** | **✅ 즉시 채택 — 실측 결함 수정.** 우리 `.input`은 14px이라 iOS Safari가 포커스 시 화면을 자동 확대한다. 학생·학부모 모바일 중심 서비스에서 치명적 |
| R3 | `clamp()` 유동 타이포(`.fluid-*`) + 모바일 축소 오버라이드 | **✅ 채택(헤드라인).** 375~1280px 사이를 미디어쿼리 계단 대신 매끄럽게 |
| R4 | 하단 탭 `aria-current` + `prefers-reduced-motion` 전면 대응 | **✅ 채택.** 접근성 — 스크린리더가 현재 탭을 인지 |
| R5 | 비로그인 체험 허용 + "저장하려면 로그인" 고지 칩 | **✅ 원칙 채택 → N3(관문 홈).** 로그인 벽을 세우지 않고 가치를 먼저 보여주는 퍼널 — 브리프의 "성적 없이 예시로 둘러보기"와 동일 사상 |
| R6 | 중앙 대형 입력창 + 상단 모드 칩 행 + 첨부·전송 3버튼 | **✅ N3에서 구현 참조.** 관문 홈 "무엇을 준비하고 있나요?"의 구체 레이아웃 레퍼런스 |
| R7 | 저빈도 메뉴 = "더보기" 시트로 전량 수납 | **✅ 이미 반영.** 우리는 '내정보' 그룹이 같은 역할 |
| R8 | HSL 삼중값 토큰(`--primary: 256 92% 62%`) + `hsl(var(--x) / alpha)` | **⏸ 제안만 — 디자인통합 스텝 1로.** 알파 변형(primary/15, fg/5)을 변수 폭발 없이 쓸 수 있어 우리 hex 토큰보다 확장성이 낫다. 지금 바꾸면 스텝 1과 충돌 |
| R9 | 도메인 슬롯 색(`--jbm` 전용 색 세트) | **⏸ 스텝 1 제안.** 브리프 원칙 5(팩 확장성)와 동형 — 버티컬 추가 시 색 슬롯만 교체 |
| R10 | 64px 아이콘 레일 hover 확장 | **⏸ defer.** 학생은 라벨 상시 노출이 학습성에 유리. 항목이 많은 **선생님·관리자 콘솔에는 유효** → 백로그 |
| R11 | 우측 접이식 작업 패널(목록+본문 동시) | **⏸ 백로그.** Q&A 답변·상담 기록처럼 목록↔본문을 오가는 화면에 유효 |
| R12 | 모드 칩으로 컨텍스트 전환(일반/Flash/에이전트) | **⏸ 백로그.** 진단 화면의 "고속↔실측 토글"과 같은 문법 — 배치표 v23에서 참고 |

## 2. 현재 상태 진단 (코드 실측)

### 2.1 초기화면(진입) 흐름

| 진입 | 현재 동작 | 문제 |
|---|---|---|
| 비로그인 `/` | 구 잇올 마케팅 정적 HTML을 **iframe**으로 표시(`SitePage.tsx` → `public/site/landing.html`, 9파일) | 구 브랜드 잔재(감사 매트릭스에서 이미 **rebuild** 판정) · SPA와 스타일 단절 · 관문 입력 없음 |
| 학생 로그인 직후 | `/student` → **`bookings`(내 예약 목록)로 리다이렉트** (`App.tsx:165`) | 첫 화면이 "관리 화면". 신규 가입자는 빈 목록만 봄 — 가치 제시·다음 행동 없음(브리프 원칙 1 '막다른 화면 금지' 위반) |
| 선생님 로그인 직후 | `/app/dashboard` (대시보드 존재) | 방향은 맞음 — 밀도형 유지(§5.4) |
| 모바일(RN) 학생 | 첫 탭 = '선생님'(검색) | 홈 개념 부재 — 검색이 홈을 대행 |

### 2.2 메뉴 복잡도 실측

| 셸 | 1차 내비 항목 수 | 구조 |
|---|---|---|
| 웹 학생 `StudentLayout` | **12** (선생님찾기·예약·성적·자료실·QnA·커뮤니티·멤버십·크레딧·알림·역상담·자동배정·약관) | 평면 나열, 그룹 없음 |
| 웹 선생님 `AppLayout` | **14** | 평면 나열 |
| 웹 관리자 `AdminLayout` | **22+** | 평면 나열 |
| 모바일 학생 | **7 하단 탭** (선생님·내예약·강의실·자료실·QnA·커뮤니티·마이) | 탭 과다(엄지 도달·터치 타깃 축소), 브리프의 5탭 기준 초과 |
| 모바일 학부모/선생님 | 5 탭 | 기준 부합 |

**구조적 원인**: 메뉴가 기능(=API 도메인) 추가마다 1개씩 늘어나는 **축적형**이다. 역상담·자동배정·크레딧·약관처럼 이용 빈도가 월 1회 이하인 항목이 '질문 게시판'과 같은 서열로 노출된다. 브리프가 최우선 요구로 못박은 "**새 서비스가 추가되어도 첫 화면·내비가 재설계되지 않는 확장 구조**"와 정반대 방향으로 자라고 있다 — 지금 손대지 않으면 W5(Q&A)·W8(유료 티어) 기능 추가 시 13, 14번째 항목이 또 붙는다.

### 2.3 기타 실측

- **반응형 부재**: `apps/web/src/styles/*.css`에 `@media` 쿼리는 `prefers-reduced-motion` 1건뿐. 사이드바 셸은 모바일 브라우저에서 그대로 깨진다(학생·학부모는 모바일 중심 고객층 — 브리프 §1).
- **토큰·브랜딩 파이프라인은 건재**: `tokens.css` + `branding.config.json` → `branding.generated.ts` 주입 구조(감사 1a 결론 keep). 내비 개편은 이 파이프라인을 건드리지 않는다.
- **알림**: 학생 셸에서 '알림'이 사이드바 항목(페이지 이동)이다. SNS 문법은 상단 벨 아이콘+배지+드로어.

## 3. 벤치마킹 — SNS·소비자 앱의 검증된 문법

사용자가 요구한 "기존 SNS 등의 서비스와 비슷하게 느껴지는" UX의 실체는 아래 6개 문법으로 수렴한다. (레퍼런스별 → 야누스 이식)

| # | 문법 | 대표 사례 | 야누스 이식 |
|---|---|---|---|
| B1 | **하단 5탭 고정, 절대 늘리지 않음** | 인스타그램·유튜브·토스 — 10년간 기능이 수십 배 늘어도 탭은 5개 | [홈 · 질문 · 진단 · 일정 · 내정보] (브리프 확정안). 새 버티컬은 홈 카드로 흡수 |
| B2 | **홈 = 개인화 피드(카드 스트림)** | 인스타 피드, 토스 홈(계좌·소비 카드 나열) | "나의 관문": 지금 위치→다음 할 일→바로가기 3단을 카드 피드로(§5.2) |
| B3 | **핵심 생성 행동 = 중앙 대형 버튼** | 인스타 [+], 유튜브 [만들기], **콴다(QANDA) 중앙 카메라 버튼** | "질문 올리기"(사진 1장 → AI 초안). 교육 도메인 직접 선례가 콴다 — 카메라 퍼스트가 학생 마찰 최소 진입임이 검증됨 |
| B4 | **알림 = 벨 아이콘+배지+드로어, 설정·결제 = 프로필 수납** | 전 SNS 공통, 토스(결제수단·인증서를 전부 '전체' 탭에) | 알림을 사이드바 항목에서 상단 벨로 승격, 멤버십·크레딧·약관·역상담 옵트인을 '내정보'로 수납 |
| B5 | **복잡 도메인의 리스트 홈** | 토스 — 금융 전 상품을 홈의 접을 수 있는 리스트로, 1차 내비는 안 늘림 | 관리자·선생님 콘솔에 적용: 항목 수는 유지하되 그룹 헤더로 수납(§5.4) |
| B6 | **공급자·소비자 UI 분리** | 유튜브 스튜디오, 배민 사장님앱 | 선생님 콘솔은 SNS화 대상이 **아님** — 큐 처리 밀도 유지(브리프 원칙 3), 그룹핑만 |

**반면교사(하지 말 것)**: 페이스북식 햄버거 만능 서랍(발견성 최악) · 기능별 탭 증식(현 상태) · 홈에 배너 슬라이더 나열(구 교육앱 문법 — 학원 홍보판처럼 보임).

## 4. 사용자 여정 재설계 (변수별)

핵심 변수: 역할(학생/학부모/선생님) × 상태(비로그인/신규/재방문) × 기기(모바일/데스크톱) × 시점(진단 전/커리큘럼 중/시험 직후). 대표 여정 5개의 현재 vs 개선:

| 여정 | 현재 (실측) | 개선안 |
|---|---|---|
| J1 학생 신규·비로그인 (모바일) | 구 잇올 iframe 랜딩 → 정체성 혼란 → 가입해도 빈 예약 목록 | 관문 홈 입력("고2 수학 미적분이 무너졌어요") → 의도분류 → 진단/질문/선생님찾기 타일 → **가입 전 가치 체험**(무료 배치표·예시 모드) → 가입 → 홈에 첫 커리큘럼 카드 |
| J2 학생 재방문 (모바일, 매일) | 앱 열면 '선생님 검색' 탭 — 오늘 뭘 해야 하는지 알 수 없음 | 홈 피드 최상단 = "오늘 할 일 2개"(수업 19:00·질문 답변 도착) → 탭 1회로 실행 |
| J3 학생 시험 직후 (성적 입력 피크) | 사이드바에서 '내 성적·배치' 찾아야 함(12개 중 3번째, 플래그로 숨겨지기도) | 홈 피드가 시점 인지("6월 모평 결과 나왔나요?") → 진단 탭 딥링크 → 격차 리포트 → 처방 CTA 3 |
| J4 학부모 (결제 결정) | 웹 학생 셸에 학부모 개념 없음(모바일만 존재) | 웹도 자녀 리포트·결제 중심 '나의 관문' 변형(브리프 P1) — 본문 17px+·고대비 |
| J5 선생님 (공급자, 데스크톱) | 14항목 중 인박스·예약·QnA를 오가며 처리 | 대시보드=오늘 큐(답변 대기 n·오늘 수업 n·정산 예상) 유지, 내비만 4그룹 수납 — 여정 자체는 불변 |

## 5. 개선안 — IA·화면 설계

### 5.1 학생 웹 내비: 12항목 → 5그룹 (라우트 URL 전부 불변)

| 새 1차 내비 | 수납되는 기존 항목 (라우트 유지) | 비고 |
|---|---|---|
| **홈** `/student/home` (신설) | — | §5.2 카드 대시보드 |
| **질문** | `qna` + `community` | 세그먼트 탭(질문/커뮤니티) — [DEC D-b] |
| **진단** | `scores` (성적·배치) | 격차 리포트(브리프 P0-4)의 자리. 접근 플래그 로직 유지 |
| **일정** | `bookings` + `search`(선생님 찾기) + `auto-assign` | '선생님 찾기'는 일정 탭 상단 CTA + 홈 타일 양쪽 진입 |
| **내정보** | `membership` · `credits` · `materials` · `reverse` · `legal` + 프로필 | 저빈도 전부 수납. 자료실은 수업 상세에서도 컨텍스트 진입 |
| (1차 내비 밖) | `notifications` → 상단 벨 아이콘+배지 | B4 문법 |

- 데스크톱: 5그룹 아이콘+라벨 레일(하위 항목은 그룹 진입 후 좌측 2차 리스트 or 페이지 내 탭).
- 모바일 뷰포트(`@media ≤768px`): 사이드바 숨기고 **하단 5탭** — RN 앱과 동일 문법 [DEC D-c].

### 5.2 로그인 홈 "나의 관문" (신설 — 이번 개편의 심장)

브리프 확정 3단 프레임을 카드 피드로 구현. 위에서부터:

1. **지금 위치** — 진단 상태 1카드: 최근 성적 기준 "현 위치 → 목표 격차" 미니 게이지 + 신뢰도 배지(모노 숫자, 근거 병기 — 원칙 2). 진단 전이면 "성적으로 진단받기" CTA 카드로 대체.
2. **다음 할 일** — 0~3카드: 오늘 수업(입장 버튼)·답변 도착한 내 질문·커리큘럼 다음 스텝. **항상 최소 1개의 다음 행동 카드 보장**(막다른 화면 금지).
3. **바로가기·소식** — 서비스 타일(도메인 색·아이콘 슬롯 교체형 컴포넌트 — 원칙 5, 새 버티컬은 여기에만 추가) + 공지·커뮤니티 인기글 소량.

역할 적응: 같은 프레임에서 학부모=자녀 리포트·결제 카드, 선생님(웹 대시보드)=인박스 큐·오늘 일정·예상 정산.

### 5.3 비로그인 관문 홈

기존 디자인통합 지시서 **스텝 3과 동일 작업**이므로 재정의하지 않는다(의도분류·LLM 훅 로직 보존, iframe 제거, 관문 히어로+근거 4종+행동 타일 3). 본 개편에서는 순서만 확정: 로그인 홈(5.2)보다 **먼저 해도 되고 뒤에 해도 되며**, W3 이식 태스크에 이미 귀속.

### 5.4 선생님·관리자: SNS화 제외, 수납만

- 선생님 14항목 → 4그룹 헤더(오늘: 대시보드·인박스·예약·근무 / 수업: 강의실·자료실·기록 / 답변·평가: QnA·받은평가·역상담 / 정산·계정: 예상급여·프로필·알림·약관). 항목 삭제 없음.
- 관리자 22항목 → 동일 방식 5그룹(사람·운영·정책·분석·시스템). 이번 범위에서 최하순위 — 내부 사용자라 학습비용 감수 가능.

### 5.5 모바일(RN) 학생 7탭 → 5탭

[선생님·내예약·강의실·자료실·QnA·커뮤니티·마이] → **[홈(신설)·질문(QnA+커뮤니티)·진단(신설: 성적)·일정(내예약+강의실+선생님찾기)·마이(자료실 포함)]**. 웹과 문법 통일. RN 탭은 자체 구현 상태라 라벨·매핑 교체 수준으로 가능.

## 7. 리스크·변수 체크

1. **기존 사용자 학습비용**: 항목 삭제가 아니라 수납이므로 기능 상실 없음. 전환 첫 주 "메뉴가 이렇게 이동했어요" 1회 안내 배너.
2. **화이트라벨 파이프라인**: 내비 개편은 `branding.config.json` 주입 구조를 그대로 사용 — 토큰 교체(스텝 1)와 독립적으로 진행 가능하나, **스텝 1(야누스 토큰) 이후에 N1을 하면 이중 리스킨을 피함**. 권장 순서: 스텝 1 → N1.
3. **티어 게이팅과 내비**: 무료/회원/유료 티어별로 탭 내용이 달라져도 탭 5개 자체는 불변이어야 함(잠금 상태를 탭 안에서 표현 — 업셀 CTA는 카드 레벨).
4. **성적 접근 플래그**(`showTrend`): 진단 탭은 플래그 off 시 숨기지 말고 "진단받기" 유도 상태로 표시할지 [DEC] — 숨기면 신규 사용자가 핵심 가치를 영영 못 봄. (권고: 유도 상태 노출)
5. **접근성**: 하단 탭 44px 터치 타깃·색맹 대응 AI 라벨(브리프 원칙 4)·`prefers-reduced-motion` 유지.
