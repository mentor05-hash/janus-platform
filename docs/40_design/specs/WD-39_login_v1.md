# WD-39 · 로그인 스펙 시트

> **[draft] 정본·[DEC] 확정 시 개정.** (토큰은 confirmed 2026-07-08.) 원본 목업: `40_workbench/mockups/janus_login_v1.html`.
> §2-A 로그인 · **리스킨** · 라우트: `/login` (실측: apps/web 실라우트 존재). **역할 선택 강요 금지**(관문 IA).

## 개념
관문 우선 진입 — 로그인 시 역할을 먼저 고르게 하지 않는다(계정이 역할을 안다). "3초 로그인 + 게스트 우회"로 마찰 최소화. 티어 서비스(배치표 회원판 등)는 SSO로 이어짐.

## 구성
1. **로그인 폼** — loginId + password(코드 계약: `POST /auth/login {loginId,password}` → `data.accessToken`). 자동입력·표시 토글.
2. **게스트 우회** — "먼저 둘러보기"(온보딩/관문 홈으로) — 가입 강요 금지.
3. **가입 유도** — "3초 가입"(signup, WD-30) 링크. 비밀번호 찾기.
4. **크로스서비스 진입** — 외부 서비스(배치표 등)에서 온 경우 SSO 게이트 배지("플랫폼 계정으로 열기").

## §1 컴포넌트 계약 대조표
| §1 계약 | 이 화면 적용 | 확인 |
|---|---|---|
| 티어게이트 `free<member<paid<consultant` | SSO 진입 시 "회원부터" 안내(배치표 등) | ✅ |
| CTA `data-janus-cta` | "로그인"=`auth_login` · "게스트"=`guest_enter` · "가입"=`to_signup` | ✅ |
| 상태칩(오류) | 인증 실패 = `--chip-danger`/error 스타일 | ✅ |
> ⚠ **금지**: 로그인 화면에서 역할 선택 UI(관문 IA 위반). 비밀번호·토큰은 브라우저 저장 API 미사용(정적 목업).

## CTA 위계
골드 채움 = "로그인" `data-janus-cta="auth_login"`. 블루/고스트 = 게스트·가입. 텍스트 = 비번 찾기.
