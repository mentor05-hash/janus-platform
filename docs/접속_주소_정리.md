## 공개 고정 주소 — Tailscale Funnel (2026-08-06 개통·실측)

도메인 없이 얻은 **고정 주소**. 다시 띄워도 안 바뀐다.

| 주소 | 로컬 | 용도 |
|---|---|---|
| **https://janus-demo.taildfe36f.ts.net/demo** | :8080 | 체험 입구(회원 선택 → 바로 로그인) |
| `https://janus-demo.taildfe36f.ts.net` | :8080 | 야누스 메인·전 역할 웹 |
| `https://janus-demo.taildfe36f.ts.net:8443` | :8090 | 모바일 웹(학생·학부모) |
| `https://janus-demo.taildfe36f.ts.net:10000` | :3100 | 실시간 룸 — `.env` 의 `ROOMS_PUBLIC_URL` 이 이 값 |

- Funnel 공개 포트는 **443·8443·10000 셋만** 허용된다(그래서 이 배치).
- 데몬은 **userspace 모드**(root·VPN 구성 불필요). launchd 에 등록돼 로그인 시 자동 기동하고,
  Funnel 설정은 tailscaled 상태에 저장돼 함께 복원된다 — `~/Library/LaunchAgents/com.janus.tailscaled.plist`.
- ⚠ **Docker 스택이 떠 있어야 한다.** Funnel 은 로컬 포트를 중계할 뿐이라, 컨테이너가 없으면 502.
  compose 전 서비스에 **`restart: always`** 를 걸어 두었으므로 Docker 데몬이 살아나면 컨테이너가 따라 온다.
  `docker compose down` 은 컨테이너를 지우므로 여전히 확실한 off 스위치다(다시 켜려면 `up`).
  > `unless-stopped` 로는 안 된다 — Docker Desktop 이 종료하며 컨테이너를 stop 상태로 만들고,
  > `unless-stopped` 는 "데몬 종료 시점에 멈춰 있던 컨테이너"를 되살리지 않는다. 실측으로 확인(2026-08-06):
  > `unless-stopped` → Docker 재시작 후 6개 전부 Exited 유지 / `always` → 3초 만에 6개 복구, 주소도 200.
- **Docker Desktop 의 "로그인 시 시작"은 GUI 설정이라 사람이 직접 켜야 한다**(2026-08-06 사용자 설정 완료).
  재부팅 후 복구 사슬: Docker Desktop 자동시작 → 컨테이너 `restart: always` → Funnel 은 launchd 가 복원.
- ⚠ **맥이 꺼지거나 잠들면 죽는다.** 상시 가동은 클라우드 VM 이 답 —
  [고정주소 배포계획 §4](20_exec/야누스_고정주소_배포계획_2026-08-06.md).
- ⚠ **URL 을 아는 사람은 누구나 들어온다.** Funnel 에는 Cloudflare Access 같은 앞단 게이트가 없다.
  관리자·HR 계정은 화면단에서 잠갔지만(아래) 그건 인증이 아니다 — 계획서 §6-1 참조.

```bash
tailscale --socket=/tmp/tailscaled-janus.sock funnel status          # 현재 공개 상태
tailscale --socket=/tmp/tailscaled-janus.sock funnel --https=443 off # 웹 공개 중단
launchctl unload ~/Library/LaunchAgents/com.janus.tailscaled.plist   # 전체 중단
```

## 임시 터널 — cloudflared quick tunnel
```bash
bash ops/demo-public-link.sh          # 스택 기동 + 프런트 최신화 + 터널 3개 + 링크 출력
bash ops/demo-public-link.sh --stop   # 터널만 종료(외부 접속 즉시 차단, 스택은 유지)
```
- 웹(8080)·모바일(8090)·상담룸(3100) 각각 cloudflared quick tunnel. 웹/모바일 origin 의 nginx 가 `/api` 를 api 컨테이너로 프록시하므로 백엔드 터널은 따로 필요 없다.
- 상담룸은 브라우저가 룸 서비스에 직접 붙으므로 스크립트가 `ROOMS_PUBLIC_URL=<룸터널>` 로 api 를 재기동한다.
- **quick 터널은 프로세스가 사는 동안만 유효** — 맥이 잠들거나 재실행하면 주소가 바뀐다. 고정 주소가 필요하면 named tunnel(도메인 필요).
- ⚠ **배치표 허브 데이터는 기본으로 붙는다** — 루트 `.env` 의 `JANUS_DATA_DIR_HOST=~/janus/20_data` 를 compose 가 자동으로 읽어, full.yml 단독 기동만으로도 20_data **전체**가 api 컨테이너에 읽기전용 마운트된다. "안 붙였다"고 가정하지 말고 `GET /api/v1/placement-hub/list` 의 `available` 로 확인할 것.
  - 공개 터널에서 실제로 나가는 것: `tier=free` 표(격차 리포트)는 **비로그인 공개**, `tier=paid` 표는 로그인+티어/상품권한+1회용 티켓+워터마크+감사+일일 40회 상한. manifest 밖 파일·`audience=internal` 자료는 안 나간다.
  - `/demo` 가 `paidall` 계정을 아무에게나 내주므로, **링크를 아는 사람은 유료 배치표까지 열람 가능**하다(워터마크·감사는 남음). 감수할 수 없으면 아래 범위 축소를 쓰거나 터널을 닫는다.
  - 범위 축소(공개 시 권장) — 컨테이너에 `placement-hub/` 만 넣고 raw·internal·dist_restricted 는 제외:
    ```bash
    mkdir -p janus-data/placement-hub   # 겹쳐붙일 마운트지점(최초 1회)
    docker compose -f docker-compose.full.yml -f docker-compose.hub.yml up -d api
    ```
- ⚠ **씬-슬라이스 검색은 사실상 빈 상태** — `placement-hub/slices/jeongsi-2027.json` 이 4행짜리 샘플이고 `susi`·`jeongsi-2026` 슬라이스 파일은 아예 없다. 허브의 검색 탭은 "일치하는 항목이 없어요"만 뜨고, 실제 열람은 `전체표로 보기`(티켓 → 전체 HTML) 경로로만 된다. O76 이 의도한 "전체 파일 대신 검색 행만" 방어가 데이터 미비로 작동하지 않는 상태 — 슬라이스 생성이 데이터 트랙 숙제로 남아 있다.
- 공개 URL 을 아는 사람은 마스터관리자까지 아무 회원으로나 들어올 수 있다. 데모가 끝나면 `--stop`.

## 프런트 반영 두 가지 경로
- **이미지에 굳히기(정식)** — `docker compose -f docker-compose.full.yml build web mobile` 후 `up -d web mobile`. 컨테이너를 새로 만들어도 유지된다. base 이미지(`nginx:alpine`·`node:20-alpine`)가 로컬에 없으면 pull 에 십수 분 걸릴 수 있다(막힌 게 아니라 느린 것 — 기다리면 된다).
- **컨테이너에 바로 넣기(빠름)** — 위 스크립트가 자동 수행. 워킹트리를 즉시 반영하지만 컨테이너 수명 동안만 유효.
```bash
VITE_DEMO_MODE=true npm run build --workspace apps/web
docker cp apps/web/dist/. janus-platform-web-1:/usr/share/nginx/html/
```
- 모바일은 `EXPO_PUBLIC_DEMO_MODE=true npm run export:web --workspace apps/mobile` 로 export 해야 역할 칩·`?u=&p=` 자동 로그인이 살아난다(플래그 없이 export 하면 데모 분기가 트리셰이킹돼 사라짐).
