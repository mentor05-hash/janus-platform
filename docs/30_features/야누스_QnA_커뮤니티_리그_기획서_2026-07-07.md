## 0. 현행 기능 확인 (정직한 기준선)

- **문서로 확인됨**: 기능총괄보고서 consultation 모듈에 "게시판/Q&A(**지정/공개**·**채택**)" 명시 — 지정 질문·공개 질문·채택 구조는 존재.
- **문서로 확인 불가(코드 감사 필요)**: "선생님이 질문을 가져가기(클레임)"와 "상담 공백 시간 전임 선생님 강제 배정"의 구체 로직은 보고서에 상세 기재가 없음. 잇올 구 시스템 히스토리에는 "다른 선생님이 답변 중 안내(중복답변 방지)"가 있었음. → **실행계획 첫 태스크 = 코드 감사**로 현행 배정 로직·데이터 모델을 확정하고 본 기획서 §2와의 갭을 목록화한다.

## 0-1. 전략적 위치 — 왜 Q&A가 초기 최대 수요인가 (동의 + 근거)

1. **마찰 최저의 진입점**: 예약제 상담은 "시간 약속"이라는 큰 결심이 필요하지만, 질문 1건은 사진 한 장이면 된다. 획득→첫 활동→첫 결제의 최단 경로.
2. **매칭의 발견 채널**: 학생은 답변을 통해 선생님을 "겪어보고" 지정 질문→상담→과외로 올라간다. Q&A는 그 자체가 수익원이면서 **상위 상품의 시착(試着) 장치**.
3. **공급자 팜 시스템**: 리그(3→2→1부)는 대학생·우수 수험생을 답변자로 키워 검증된 공급자(멘토·과외·클리닉)로 승격시키는 파이프라인 — 공급단 확장 문제의 구조적 해법.
4. **크레딧 소비처 확대**: 2부 질문이 크레딧을 태우는 신규 소비처가 되어 크레딧 구매 동인과 소멸률 경제를 강화.
5. **커뮤니티=리텐션+관측소**: 게시판 활동 데이터가 다음 버티컬(멘탈 등) 분화 시점을 알려준다.

## 1. 질문 모델 — 스코프 3종 × 배정 2방식

### 1-1. 스코프 (질문자가 선택)
| 스코프 | 대상 | 특성·고지 | 과금(리그 연동) |
|---|---|---|---|
| **전체 공개** | 답변 자격자 전원 | 최속 응답 기대 | 리그 등급 규칙(§3) |
| **범위 한정** | 학생이 지정한 선생님 그룹(즐겨찾기/단골 목록) | 게시 시 고지 문구 필수: **"선택한 선생님들에게만 공개되어 전체 공개보다 응답이 느릴 수 있습니다"** | 동일 + 한정 프리미엄 검토 |
| **1:1 지정** | 특정 선생님 직접 질문 | 상담의 경량판. 해당 선생님 부재 시 대기/전환 제안 | 지정 프리미엄(크레딧 가산) |

### 1-2. 배정 (공급이 붙는 방식)
- **(a) 클레임(가져가기)**: 답변 자격자가 질문을 잠금 — 잠금 중 타인 답변 차단(중복답변 방지, 구 시스템 검증 기능의 정식화), 제한시간 내 미해결 시 자동 해제·재공개.
- **(b) 강제 배정**: 상담 공백 시간대의 전임 선생님에게 시스템이 배정(availability 모듈 연동 — 빈 슬롯=배정 가능 시간). 배정 알림→수락/불가(불가 시 사유·재배정). 미응답 타임아웃 시 자동 재배정.
- 우선순위: 지정 > 범위 한정(그룹 내 클레임→타임아웃 시 그룹 내 배정) > 전체 공개(클레임 우선, 미클레임 경과 시 강제 배정).

### 1-3. 관계 피드백 루프 (해결 시마다 2문항)
1. **만족도 별점**(기존 별점 재사용)
2. **"이 선생님에게 계속 답변을 받을까요?"** 예/아니오
   - **아니오 → 소프트 블록**: 이후 이 학생의 질문이 해당 선생님에게 **비노출 + 배정 제외**(양방향 필터). 선생님에게는 사유·사실 비공지(관계 보호), 학생은 설정에서 해제 가능. 관리자는 블록 통계만 열람(특정 선생님 블록 급증 = 품질 신호).
   - **예 누적 → 단골 승격**: 즐겨찾기 자동 제안 → 범위 한정·지정 질문의 기본 그룹 → 상담·과외 전환 CTA. (Q&A→상위 상품 전환의 핵심 동선)

### 1-4. 불만족 후속 경로 2종 (답변이 마음에 들지 않을 때 — 이탈 대신 전환/재시도)

답변 확인 화면에 [채택] 외 두 버튼을 상시 제공한다:

**① 상담으로 승격(escalation)** — 이 질문을 그대로 실시간 상담(채팅/화이트보드/화상 중 선택)으로 전환.
- **컨텍스트 자동 이관**: 질문 본문·첨부(사진/PDF)·기존 답변이 상담 세션에 사전 첨부되어, 학생이 다시 설명할 필요 없음(화이트보드 배경으로 질문 이미지 자동 로드).
- 상담 상대 선택: 답변했던 선생님에게 이어가기(단골 동선) 또는 다른 선생님 매칭. 과금은 일반 상담과 동일(크레딧) — **Q&A→상담 전환 매출의 정식 트랙**이며 전환 대시보드의 핵심 지표.

**② 재답변 요청(re-answer)** — 다른 선생님에게 다시 답변 받기.
- 기존 답변자·소프트 블록 대상 **제외 후 풀에 재공개**(스코프 유지: 한정 질문은 그룹 내 잔여 인원, 소진 시 전체 공개 전환 제안).
- **한도: 기본 3회 — 단, 하드코딩이 아니라 정책값**. pricing-policy(정책 단일 소스)+기능토글 패턴으로 `qa.reanswerLimit`을 전사/센터 단위에서 **관리자가 설정**(0=비활성 포함). 잔여 횟수를 학생 화면에 표시.
- 남용·품질 신호 관리: 재요청 시 사유 택1(이해 안 됨/질문과 다름/더 자세히 등) — 사유는 새 답변자에게 전달(개선 힌트)되고, 이전 답변은 새 답변자에게 참고로 노출(중복 방지). 특정 선생님의 재답변 유발률은 풀별 품질 지표에 반영하되, 재답변 자체는 페널티가 아닌 신호로만.
- 한도 소진 시: 상담 승격(①) 또는 공개 게시판(3부) 전환을 제안 — 어떤 경우에도 막다른 길 없음.

## 2. SLA·품질 지표 — 풀(pool)별 분리 관리 (요구사항 핵심)

- **타임스탬프 4점**: 접수 → 클레임/배정 → 첫 응답 → 해결(채택 또는 만족 확인). 모든 질문에 기록.
- **지표**: 첫응답 시간, 해결 시간, 만족도(별점), 채택률, 재질문율, **재답변 유발률, 상담 승격률**, 블록 발생률.
- **풀별 분리 원칙**: 동일 선생님이라도 ①전체 공개 ②범위 한정 ③지정 풀의 응답속도·만족도를 **별도 집계**한다. 한정 풀은 모수가 작아 응답이 느린 것이 구조적으로 정상이므로, 전체 풀 기준으로 평가하면 부당 불이익 — 평가/등급(S/A/B)·급여 가중 반영 시 풀별 벤치마크 대비 상대평가로 처리.
- 노출: 학생에게는 선생님 프로필에 풀별 "평균 첫응답 시간·만족도" 배지(신뢰도 표기 — 배치표 relTier와 같은 문법), 운영 대시보드에는 풀×선생님 피벗.

## 3. 리그 시스템 — 2024 승강 기획 수용 + 야누스 경제 접목

3부 체제를 수용하되, 별도 포인트 화폐를 만들지 않고 **포인트=크레딧으로 통합**(경제 단일화, 기존 크레딧 계좌·거래 인프라 재사용)한다.

| | **3부 · 공개 게시판** | **2부 · 크레딧 게시판** | **1부 · 프리미엄 게시판** |
|---|---|---|---|
| 답변 자격 | **전원**(학생 포함) | 3부 승급자 + 검증 대학생·선생님 | 2부 승급자(우수 답변자) |
| 질문 비용 | 무료(일 3건 제한 — 구 시스템 검증 규칙 승계) | 크레딧 소모 | 크레딧 상위 or 원화 |
| 채택 | **질문자가 복수 답변 중 1건 단일 채택**(채택=리그 실적의 기준, 마감시한 경과 시 미채택 종료 — 시한은 정책값) | 동일 | 동일+관리자 검토 병행 |
| 답변 보상 | 없음(채택·별점 **실적만 축적**) | 크레딧 획득(채택/별점 기준) | **금전 수당 = 기존 share 정산 엔진 재사용**(건당 확정매출 분배) |
| 승급 | 채택 수 N + 평균 별점 기준(수치는 [DEC], 운영 데이터로 보정) | 크레딧 획득량 + 별점 기준 | — |
| 강등 | — | 활동 미달 또는 별점 하락 → 3부 | 별점 하락·관리자 검토 → 2부 |
| 관리 | 신고·모더레이션 | 중복답변 방지·미답변 보기 | **관리자 품질 검토**(저품질 → 보상 조정·강등) |

**AI 답변 규칙(전 리그 공통, 2024 기획 승계·강화)**
1. 질문 등록 즉시 **AI 초안 답변 자동 등록**(LlmProvider 재사용) — "AI 생성" 라벨 필수, 질문자에게 즉시 1차 응답 제공(SLA 첫응답을 AI가 받쳐줌).
2. 답변자는 AI 초안을 [보완/수정/새 답변] 중 택1로 처리 — **보완 정도에 따라 보상 차등**(AI 그대로=최저, 실질 보완=정상, 순수 자작=가산).
3. AI 활용 미표기 부정행위 = 자동 경고→반복 시 활동 제한(감지: 유사도 검사 보조).
4. 질문자 옵션: "사람 답변만 받기" 선택 가능.

**승급의 종착지 = 공급자 스카웃**: 1부 상위 답변자에게 멘토/과외/클리닉 공급자 온보딩 제안(자격 심사 간소화 트랙) — 리그 실적이 곧 심사 자료.

## 4. 커뮤니티 게시판 — "한 보드에서 시작, 데이터로 분화"

- **v1**: 공개 게시판(3부)과 한 몸인 단일 "학습 Q&A" 보드로 시작. 글=질문/자유글 구분, 댓글·채택·별점 공통.
- **분화 규칙(요구사항: 속도 기반 조정)**: 태그별 주간 글·댓글량이 임계(예: 주 30건, [DEC]로 확정) 2주 연속 초과 시 독립 보드로 분화 — 예상 경로: 학습법 → 입시전략 → 학부모 → **멘탈**. 반대로 저활동 보드는 통합(빈 보드 노출 금지 — 커뮤니티 냉각 방지).
- **멘탈 보드 특칙**(확장청사진 L1과 접속): 분화 전이라도 멘탈 태그 글에는 ①"전문 상담 대체 아님" 고지 ②위기 표현 감지 시 전문기관 안내 자동 고정 노출 ③의료적 조언 금지 모더레이션 규칙 적용. LLM은 분류·신고 보조까지만(심리 판정 금지 — 확장청사진 §2-2 준수).
- 커뮤니티 지표: 글/댓글 속도, 첫 댓글까지 시간, 재방문율 — 분화·통합 판단과 버티컬 확장 트리거(T1)의 관측 데이터.

## 5. 데이터 모델 개요 (코드 감사 후 확정)

- `question`(scope[open|scoped|direct], scoped_group_id, status, ts_created/claimed/first_reply/resolved, board_id, **reanswer_count, escalated_booking_id**)
- `answer`(ai_flag[ai|ai_assisted|human], adopted, rating)
- `assignment`(type[claim|forced], ttl, state) — availability 연동
- `relation_pref`(student→teacher, state[favorite|blocked], source) — 노출·배정 필터의 단일 소스
- `league_profile`(tier, adopt_count, rating_avg, credit 흐름은 기존 billing 재사용)
- 정책값(pricing-policy): `qa.reanswerLimit`(기본 3, 관리자 설정) · `qa.dailyFreeLimit`(기본 3) · `qa.adoptDeadline`
- `board`(tag, 분화 상태) · 지표는 기존 ops 피벗에 풀 차원 추가

## 6. 수익 사다리 재배치 (Q&A 편입)

무료: 3부 질문(일 3건)·커뮤니티 → **크레딧: 2부 질문·지정 질문 가산** → 원화/상위: 1부 프리미엄 질문 → 상담(크레딧) → 과외·클리닉 → 컨설팅 — Q&A가 사다리 최하단 2칸을 신설하여 "첫 결제"의 문턱을 크게 낮춘다. 1부 수당·2부 크레딧 보상률은 소멸률 경제(마진 30% 가정)를 깨지 않는 범위에서 [DEC].

## 7. 단계 요약 (실행계획서 v2에 주차 배정)

- **Q1(감사·보강)**: 코드 감사 → SLA 타임스탬프·풀별 집계 → 관계 피드백 2문항+소프트 블록.
- **Q2(스코프)**: 범위 한정·지정 질문 + 고지 문구 + 클레임/강제배정 정비.
- **Q3(공개·AI)**: 3부 공개 게시판(전원 답변)+AI 초안 자동 등록+표기·차등 규칙 — 커뮤니티 v1 겸용.
- **Q4(리그)**: 승급(3→2부, 크레딧 보상) + 프로필 배지 + 미답변 보기·중복 방지 정식화.
- **Q5(1부·정산)**: 금전 수당(share 재사용)+관리자 검토 — 시즌 후.
- **Q6(분화)**: 커뮤니티 태그 분화 자동화 + 멘탈 특칙 — T1(멘탈 코칭)과 연동.
