> 작성 2026-07-19 · 원천: 본부 브리핑 「오디오 녹음+자동 요약 리포트 v1」(업로드본).
> 브리핑 §3 규약("표와 코드가 다르면 코드가 우선, 차이는 본부 확인 필요로 보고")에 따라 **코드 실사 결과와 차이 보고**를 포함한다.

## 1. 브리핑 전제 자산 실사 결과 (코드 기준)

| 브리핑 전제 | 실사 결과 | 판정 |
|---|---|---|
| LiveKit egress→S3 라인 "코드 완료" | ✅ `livekit-media.provider.ts` — `StartRoomCompositeEgress`(audio_only)·S3 출력·twirp, ENV `LIVEKIT_EGRESS_S3` | 일치 |
| S3 저장소 | ✅ `S3StorageProvider` 존재(로컬 디스크 프로바이더와 어댑터 교체형) | 일치 |

| booking 조인 키·상태머신 무변경 | ✅ `/media/token`(consult) 이 이미 booking 당사자·confirmed·시간창 검증 | 일치 |

| **차이②** funnel_event 신규 이벤트 5종 | ⚠ track() 는 event enum('view'\|'cta') 고정(C3 계약) | 전례(consult_media)와 동일하게 **meta.ev 방식** — 서버 계약 무변경 |
| **차이③** egress 파일 경로 | ⚠ 현행 provider 는 `lectures/{room}-{time}.mp4` 고정 | consult 용 `consult-audio/{bookingId}-{time}.ogg` 분기 추가(provider 옵션 확장 — 계약 비파괴) |

## 2. 데이터 모델 (신규 4종 — 코드베이스 컨벤션 snake_case, 기존 테이블 무변경)

```
consult_recording { id, booking_id, egress_id, s3_key, duration_sec, size_bytes,
                    consent_student_at, consent_teacher_at, consent_policy_version, consent_guardian_at?,
                    status: consented|recording|stored|purged|aborted, expires_at, purged_at, created_at }
consult_transcript{ id, recording_id FK, engine, lang, text, created_at }
consult_report    { id, booking_id, transcript_id?, board_snapshot_file_id?,
                    body jsonb {covered[], diagnosis, next_actions[]}, status: draft|approved|sent,
                    approved_by, sent_at, opened_at, created_at }
media_access_log  { id, target_type, target_id, actor_id, action(read|download|purge), at }
```

- 마이그레이션 0072+ 로 추가. 오디오 파기는 S3 lifecycle 위임(brief §6 — 앱 크론 금지), `expires_at` 은 조회·표시용.
- 보관 기본값(🟡): 오디오 30일 / 전사문 30일 / 리포트 영구 — system_setting `consult_recording_policy` 로 분리.

## 3. 인터페이스 (신규만)

| 지점 | 설계 |
|---|---|
| 동의 | `POST /media/consent {bookingId, recording: boolean}` — 당사자 검증 후 consult_recording upsert(양측 시각 기록). 철회 = recording:false → egress 중단+파기. 상담룸(WhiteboardPanel LK 헤더)에 동의 체크 UI + 녹음 중 배지 + 철회 버튼 |
| 녹음 시작 | 서버 전용 — 양측 동의 성립 시에만 `provider.startRecording` 호출(§4 서버 차단 원칙). 클라이언트 직접 제어 경로 없음 |
| egress 완료 | `POST /media/egress-webhook` — LiveKit webhook(서명 검증, pg-webhook 패턴) → s3_key·duration 기록 → STT 잡 큐 |
| STT | `SttProvider` 어댑터(🟡 엔진 설정 교체형). **외부 API 위탁 적합성은 미결 1 — 본부 확정 전 기능 플래그 OFF** |
| 요약 | 기존 `LlmProvider` 재사용. 프롬프트 가드레일(브리핑 §4) 상수 분리. 컨텍스트: 전사문+janus_score(읽기)+격차 리포트 요지+보드 스냅샷 메타 |
| 검수·발송 | 선생님(상담사) 검수 페이지: draft 목록→수정→승인→발송(학생 알림). 기본 전건 검수(미결 5) |
| 계측 | track meta.ev: consult_record_started / consent_declined / stt_done / report_sent / report_opened |

## 4. 기능 플래그 (전부 OFF 기본 — 본부 확정 전 안전)

- `consult_recording.enabled` (마스터 스위치 — R1 완료 후에도 기본 OFF, Mac 실측 시에만 ON)
- `consult_recording.sttEnabled` (미결 1 확정 전 OFF — OFF 여도 녹음·보관·수동 메모 리포트는 동작)
- `consult_recording.guardianConsentRequired` (미결 2 — 훅만, OFF)

## 6. 본부 확인 필요 (브리핑 §8 + 실사 차이)

1. (§8-1) ✅ **본부 결정(7/19, O86)**: 외부 STT 전송은 보호자 동의 학생 한정 — consent_grant·/media/guardian-consent·sttAllowed 로 구현. 엔진 선택(위탁처 데이터 정책 비교)만 잔여.
2. (§8-2) ✅ **본부 결정(7/19, O86)**: 보호자 동의 = 학생 단위 상시 동의(학부모 리포트 화면), 철회 가능. 문안 최종본만 잔여(policy_version 관리).
3. (§8-3) 전사·리포트 보관 기간 — 기본값으로 구현, 설정 분리.
4. (§8-4) 발송 채널 — 계정 내 열람만, 훅만.
5. (§8-5) 자동 발송 조건 — 전건 검수 기본.
6. **(실사 차이①) 동의 이벤트 위치**: 브리핑의 `rtc:consent`(룸 게이트웨이)와 달리 상담 화상은 API+LiveKit 경로 — REST `/media/consent` 로 구현함. 룸(이관) 경로 상담이 부활하면 그때 rtc:consent 추가.
7. **(실사 차이②)** funnel 이벤트는 meta.ev 방식(서버 계약 무변경) — 이벤트명은 브리핑 그대로.
