# 채팅 기능 확장 제안 — 유사 서비스 벤치마크 (2026-07-19)

> 요청: "큐브 채팅부분을 참조해서 채팅창도 추가기능이 있어야 할 것 같은데, 비슷한 서비스들을 검색하고 우리 채팅기능에 추가해야 할 기능들을 제안해줘."
> 성격: **제안서** — 구현은 순위 지시 후 착수. 화이트보드 벤치마크(기능로드맵 문서)와 동일한 "이후에 추가하지 않아도 되는 수준" 기준.
> **상태(2026-07-19): ①~⑦ 전부 구현 완료** — 사용자 지시 "1번부터 7번까지 순서대로". 4패널 전수 반영(웹 ChatPanel·RoomChatPanel + 모바일 ChatScreen·RoomChatScreen — Session* 2종은 선택기 래퍼). 정정: ②는 실사 결과 예약 경로(웹·모바일)에 이미 있었고(📎 onDoc — 초기 실사 누락), 룸 경로에 이식으로 완결.

## 2. 우리 현행 실사 (2026-07-19 코드 기준)

채팅은 **6파일 가족**: 웹 `ChatPanel`(예약)·`RoomChatPanel`(룸)·`SessionChatPanel` + 모바일 3종. 공통 수정은 전수 반영 필요(화이트보드 4파일 규칙과 동일).

이미 있는 것 — 텍스트 · 이미지 전송 · 답장 인용 · 이모지 반응(`chat:react`) · 읽음 표시(`chat:read`) · **타이핑 표시(`chat:typing`)** · **새 메시지 배너**("새 메시지 N ↓" 점프 버튼) · 자동 스크롤 · 날짜 마커 · 미읽음 배지 · IME 가드 · C1 직거래 경고 배너 · 세션 시간창 게이팅 · 재전송(실패 시).

→ 상용 메신저 대비 이미 상위권. 아래 갭만 남음.

## 3. 갭 및 제안 (우선순위 순)

| 순위 | 기능 | 근거 | 구현 요지 | 상태 |
|---|---|---|---|---|
| **1** | **사진 다중 선택 전송** | 큐브 핵심 UX — 긴 지문·여러 페이지 문제를 한 번에. 현행은 `files[0]` 1장씩만 | `input multiple` + 순차 업로드(기존 `sendImage` 루프). 서버 계약 무변경 | ✅ 4패널 |
| **2** | **일반 파일 첨부(PDF·HWP 등)** | 학습지·프린트 공유 요구 필연 | 예약 경로엔 기존재(📎 onDoc) 확인 — 룸 경로에 이식(룸 파일 업로드 재사용) | ✅ 룸 이식 |
| **3** | **메시지 삭제(회수)** | 메신저 표준. 오타·잘못 보낸 사진 대응. 미성년 서비스 특성상 실수 회수 필요성 큼 | `chat:delete` 이벤트 + soft delete(`deleted_at` — 원문 DB 보존: C1 직거래 감사·분쟁 대응 위해 물리삭제 금지). 마이그 0074(api)·0003(rooms). 삭제 첨부는 상대 ACL 도 차단 | ✅ |
| **4** | **음성 메시지** | 설탭·큐브류 대면감 보완. 수식 없는 개념 설명에 텍스트보다 빠름 | MediaRecorder(웹 런타임 공용) → files 업로드 → `kind:'audio'` 재생 버블. ⚠ 상담 녹음(R1)과 별개 — 학생 자발 전송이라 보호자 동의 게이트 불요 판단(본부 확인 1건) | ✅ |
| **5** | **시스템 메시지** | 큐브 운영방식 — 세션·정책 안내를 채팅 흐름 안에서 | `kind:'system'` 중앙 회색 칩. 1차 소스: 녹음 시작/중단(R1 연동)·세션 종료 안내(창 마감 타이머, 멱등). C3 예상시간류 확장 여지 | ✅ |
| **6** | **자주 쓰는 문구(선생님)** | 인사·과제 안내 등 반복 입력 — 선생님 응답속도(P5 SLA 배지)와 직결 | localStorage 칩(기본 4종, 최대 8) — 탭=입력창 채움, 관리 모드 삭제. 룸은 host 역할 게이팅. 서버화는 수요 확인 후 | ✅ |
| **7** | **사진·파일 모아보기** | 지난 자료 다시 찾기 — 스크롤 발굴 비용 제거 | 헤더 🗂 토글 — 사진 그리드 + 파일·음성 리스트(다운로드). 서버 계약 무변경(kind 필터) | ✅ |

### 도입하지 않음 (근거 포함 — "이후 추가 불요" 판단)

- **과외티콘(브랜드 이모티콘)**: 제작·유지 비용 대비 효과 낮음. 기존 이모지 반응으로 감정표현 충족.
- **해시태그 검색**: 1:1 상담 채팅엔 부적합 — 질문 아카이브 검색은 Q&A 트랙(P3 유사질문 재사용, 9월)이 정위치.
- **메시지 수정(편집)**: 삭제(회수)로 충분. 편집 이력 관리 복잡도 대비 이득 낮고, 직거래 감사 관점에서 원문 불변이 더 안전.
- **링크 미리보기**: 외부 유도·직거래 우회 리스크(C1 정책과 상충). 미도입.
- **대화 내 검색**: 세션 단위 채팅이라 대화량이 메신저 대비 짧음 — 모아보기(7)로 실수요 커버.

## 4. 공통 원칙

- 모든 신규 메시지 유형은 **C1 직거래 감지 대상 유지**(음성 메시지는 텍스트 아님 — STT 미적용, 수동 신고로 커버).
- 서버 chat 계약은 가능한 무변경(다중 사진 = N회 전송, 파일 = 기존 kind:'file' 활용). 삭제·시스템 메시지만 스키마 소폭 추가.
- 6파일 전수 반영 + 회귀 방지 주석(화이트보드 전례).
