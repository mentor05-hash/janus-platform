## 1. 부록 B-3 실사 결과 — 상담 음성은 LiveKit이 아니다 (전제 무효)

코드 실사(파일 근거):

| 사실 | 근거 |
|---|---|
| 상담(예약 룸) 음성 = **자체 P2P WebRTC** | `apps/web/src/utils/voiceCall.ts`(웹)·`apps/mobile/src/voiceCall.ts`(모바일), `WhiteboardPanel`이 사용 |
| 시그널링 = rooms 게이트웨이 중계(자작 완료·프로덕션 동작) | `apps/realtime-rooms/src/rooms/rooms.gateway.ts` — `call:join/signal/leave` |
| ICE = 구글 공개 STUN 1개, **TURN 없음**(→ O78에서 ENV 후결합으로 보강) | 종전 4파일 하드코딩 → `iceServers.ts` 로 단일화 |
| LiveKit = **강의(classroom) 라인 전용**, 어댑터·media-token·egress 코드 완비 | `apps/api/src/modules/media/*`, `GET /classroom/:id/media-token` |
| 단, `MEDIA_PROVIDER` ENV 미설정 → **mock 폴백**(실개통 전) | `media.module.ts` |

**함의**: ①스택 이원화(상담 P2P + 강의 LiveKit)는 미래 리스크가 아니라 현재 상태 ②기획서가 B안 비용으로 꼽은 "시그널링 자작"은 이미 존재 ③결제가 일어나는 상담 음성에 TURN이 없어 CGNAT/LTE 연결 실패 구멍이 화상 이전부터 열려 있었음.

## 2. 판정 — 결론(A안=LiveKit)은 유지, 작업 정의를 수정

**수정 A안: 화상 도입 시점에 상담 미디어(음성+화상)를 LiveKit으로 "동시 이관".**
"화상 = 트랙 하나 추가"가 아니라 "상담 음성 이관 + 화상 도입" 한 묶음이 실작업이다. 근거:

1. 화상만 LiveKit이면 한 상담에 미디어 경로 2개(음성 P2P+화상 SFU) — 기획서가 A안을 권고한 바로 그 반례.
2. 이관 비용은 작다 — 서버는 classroom `MediaProvider.issueToken` 재사용(§2.1 설계 그대로), 클라이언트는 `useVoiceCall`→LiveKit 룸 조인 교체(통화 UI 유지). 신규 인프라 0.
3. TURN 운영 항목 소멸(LiveKit 내장 TURN/TLS) + 녹화·그룹·관측 옵션 가치.

**M1 완료 기준에 추가할 것**: "상담 음성 LiveKit 이관 완료(기존 P2P 코드는 보존·폴백 플래그)".
**전환 임계 추가 제안**: 기존 "미디어비>매출 5% 시 셀프호스트" + **"P2P 연결 성공률 실측 <95% 시 이관 착수 앞당김"**.

## 3. 시즌 전 선행 조치 (플랫폼 트랙에서 완료 — O78 커밋)

| 조치 | 내용 | 사용법 |
|---|---|---|
| **TURN ENV 후결합** | ICE 하드코딩 4파일 → 앱별 단일 소스(`utils/iceServers.ts`·`src/iceServers.ts`). ENV 미설정 시 종전과 동일(구글 STUN) | 웹 `VITE_TURN_URL/VITE_TURN_USERNAME/VITE_TURN_CREDENTIAL`(+`VITE_STUN_URL`) · 모바일 `EXPO_PUBLIC_*` 동명. Cloudflare TURN(무료 1TB) 권장 |
| **P2P 연결 성공률 계측** | funnel `page:'consult_media'`, `meta.ev: join_attempt→connected / failed(afterConnect 구분)` — C3 enum(view/cta) 무변경으로 서버 무접촉 | 성공률 = connected/join_attempt. 시즌 실측치가 이관 시급성의 근거 |

M0 스파이크(기획서 미결 8)는 그대로 유효 — LiveKit이 mock 폴백 상태라 Cloud 실개통 검증이 어차피 선행 필수.

## 4. M-계약 — "별도 화상툴로 분리 가능" 설계 (지금은 계약만 동결, 구현은 M1)

원칙: 야누스 상담의 기능이 아니라 **야누스가 첫 고객인 독립 미디어킷**으로 짓는다. 상담·강의·클리닉·(미래)과외·화이트라벨 어디서나 아래 4계약만으로 소비.

| 계약 | 내용 | 기존 선례 |
|---|---|---|
| **M1 토큰** | `POST /media/token {context:'consult'\|'lecture'\|'clinic', refId}` → `{url, token, expiresAt}`. 발급 조건(예약 confirmed·세션 시간창·epoch)은 context별 정책 | classroom media-token |
| **M2 권한** | sso_service 에 `rtc` 등록, scope `rtc.consult` 등. **service_entitlement(O74)로 유료 게이팅 재사용** — 화상 자체를 상품화 가능 | SSO 레지스트리·O74 |
| **M3 이벤트** | 미디어 제어면은 `rtc:*` 네임스페이스(게이트웨이는 중계만·`wb:*` 무변경) + 계측 `consult_media_*` 스키마(§3 선행 계측이 그 전신) | `wb:*`·funnel |
| **M4 임베드** | ⓐ 자사 앱: `packages/media-kit` 임포트(웹·모바일 공용 — useMediaSession·프리플라이트·강등·PIP UI) ⓑ 외부: `/room/:id?token=` 독립 URL·iframe | RoomStandalonePage·계산기 iframe |

분리 시나리오: 소비자가 늘면 `packages/media-kit`(클라이언트)과 미디어 제어면(서버 모듈→:3200 서비스 승격)만 뜯으면 됨 — 계약이 HTTP/이벤트라 소비자 무변경. 벤더 교체(LiveKit Cloud↔셀프호스트)는 MediaProvider 어댑터 뒤에서 무통증.

## 5. 줌 패리티 기능 로드맵 (미디어킷 기획 확장)

방침: 줌 복제가 아니라 **"상담·교육 도메인에서 줌을 쓸 이유가 없게"** — 보드 중심·janus_score 컨텍스트·미성년 보호 기본값이 차별점. 줌 패리티는 기본기 체크리스트로 관리.

### 이미 보유 (줌 대비 동급·우위)
채팅(게이트웨이) · **화이트보드(우위 — 상담 특화·레이저·자료첨부)** · 손들기(`hand:raise`) · 예약/결제(줌 스케줄링 대응·크레딧 연동) · 세션 시간창/휴게버퍼 · 자료실 연계 · 상담 컨텍스트 주입(janus_score·격차 리포트 — **줌에 없는 것**)

### 단계별 추가 (구현 난도: ⓛLiveKit 기본기능=설정 수준 / ⓖ게이트웨이 이벤트=소 / ⓑ별도 개발=중 / ⓟ정책 선행)

| 단계 | 기능 | 난도 | 비고 |
|---|---|---|---|
| **M1** | 화상 타일+PIP(3상태)·마이크/카메라 토글·장치 선택 | ⓛ | 기획서 §3.1 |
| M1 | 프리플라이트(장치 점검·간이 대역 측정·"음성만 시작") | ⓑ | 완주율 1차 방어 |
| M1 | 자동 재접속·강등(화상→음성+보드→채팅+보드) | ⓛ+ⓖ | `rtc:mode`/`rtc:issue` |
| **M2** | 화면 공유(보드와 탭 배타)+생기부 경고 인터스티셜 | ⓛ+ⓑ | 학생 측 기본 비활성(미결 5) |
| M2 | **배경 블러** | ⓛ | LiveKit track processor — **미성년 프라이버시 기본값 후보**(입장 시 기본 on 제안) |
| M2 | 노이즈 억제 | ⓛ | SDK 옵션 |
| M2 | 판서 잠금 토글·모바일 세로 UX | ⓖ/ⓑ | 기존 게이팅 재사용 |
| **M3** | 연결 품질 인디케이터·세션 품질 요약 | ⓛ+ⓖ | getStats 30s 샘플→종료 요약 |
| M3 | 반응 이모지(👍 등 소수) | ⓖ | `rtc:react` — 데이터채널 금지 원칙 유지 |
| M3 | 대기실(상담사 admit) | ⓑ | 시간창 게이트와 결합 — 조기입장 대기 UX |
| M3 | 갤러리/스피커 뷰 | ⓛ | 그룹 클리닉(1:3~8)과 함께 |
| **M4+** | 녹화(egress→S3)·상시 배지·동의 UX | ⓟ | 미결 1·2 확정 후에만 |
| M4+ | **STT 자막·AI 상담 요약** | ⓑ+ⓟ | LlmProvider 재사용. **미녹화 정책과 궁합** — 영상 박제 없이 "상담 요약 산출물"(보드 스냅샷+전사 요약) 제공. 전사도 PII — 동의 필요 |
| M4+ | 브레이크아웃(그룹 클리닉 소그룹) | ⓑ | rooms 서비스가 룸 스폰 — 구조 이미 적합 |
