감사 대상: `apps/api/src/modules/qna`, 웹(`StudentQnaPage.tsx`·`TeacherQnaPage.tsx`), 모바일(`QnaScreen.tsx`), 스키마·연관 배정 로직. 기준일 2026-07-13, 읽기 전용.
기준 기획서: `docs/30_features/야누스_QnA_커뮤니티_리그_기획서_2026-07-07.md` §1~2.

## 1. 현행 데이터 모델

**실제 Q&A 모듈이 쓰는 모델은 `qna_post`·`qna_answer` 2종** — 별도의 유사 스키마 `board_question`은 코드 참조 0건인 휴면(dead) 모델.

### qna_post (`schema.prisma:634-649`)
| 컬럼 | 타입 | 비고 |
|---|---|---|
| id | uuid PK | |
| student_id | uuid | → student_profile.account_id |
| subject | String? | 과목 |
| difficulty | String? | 난이도(하/중/상) — 답변블록 시간 산정에 사용 |
| scope | board_scope? = open | enum `{assigned, open}` (`schema.prisma:945-948`) |
| assigned_teacher_id | uuid? | 지정/클레임된 교사 → teacher_profile |
| body / attachments | String? / Json? | 이미지 첨부 최대 3장(DTO 강제) |
| status | String? = "open" | open / resolved |
| scheduled_booking_id | uuid? | 답변블록 예약 연동(마이그레이션 0043) |

### qna_answer (`schema.prisma:619-632`)
| 컬럼 | 비고 |
|---|---|
| post_id → qna_post (Cascade) · teacher_id → teacher_profile | |
| accepted Boolean=false · pay_eligible Boolean=false | 채택 시 true → payroll 정산 합산 |
| similarity Decimal(3,2)? · similar_to_id · sim_flagged | AI 유사도(표절/중복) 기록 |

### board_question (`schema.prisma:158-174`) — 미사용
`consult_type`·`q_type(board_qtype)`·`charge`·`taken_teacher_id`(가져가기)를 가진 더 풍부한 모델이나 **코드 참조 0건**. 기획 §5 목표 모델과 개념적으로 가깝지만 죽어 있음.

- enum `board_scope = {assigned, open}` — 기획 §1-1의 3종 스코프 중 "범위 한정(scoped)" 부재.
- enum `board_qtype = {item, general}` — 과금 단가 구분용. 리그 개념과 무관.

## 2. 현행 로직 흐름

1. **요금 안내** — `GET /qna/pricing` → `pricingInfo`(`qna.service.ts:44-50`), 문항/일반 건당 크레딧(`pricing.quoteBoard`).
2. **질문 등록** — `createQuestion`(`qna.service.ts:53-126`): scope=assigned 면 지정교사 검증 → 트랜잭션 `qna_post.create` + `credit.consumeWithin` 건당 과금. 부족 시 `ShortfallError` → 결제요청 + HTTP 402.
3. **목록** — `listPosts`(`:129-171`): 학생=본인 / 교사=`open+open` 또는 나에게 지정 / admin·hr=전체(take 200).
4. **클레임(가져가기)** — `claim`(`:173-211`): 교사 전용, unfit 게이트, `updateMany` 원자적 open→assigned 전환, 경쟁 시 409.
5. **답변** — `answer`(`:214-269`): unfit + `canAnswerQuestion`(`domain/qna.ts:15-27`) 게이트 → `llm.checkAnswerSimilarity` 표절/중복 검사(`:246-255`) → `qna_answer.create`.
6. **채택** — `acceptAnswer`(`:272-294`): 소유 학생만, 트랜잭션 `status=resolved` + `accepted=true, pay_eligible=true`.

프론트는 6개 엔드포인트에 1:1 대응. 재답변·상담승격·관계 피드백 버튼은 UI 에도 없음.

### 엔드포인트 (`qna.controller.ts`)
| 메서드·경로 | 권한 |
|---|---|
| POST `/qna/posts` | student (건당 과금) |
| GET `/qna/pricing` | student |
| GET `/qna/posts` | 인증 전체(역할 분기) |
| POST `/qna/posts/:id/claim` | teacher (선착순) |
| POST `/qna/posts/:id/answers` | teacher (§5-9 게이트+유사도) |
| PATCH `/qna/answers/:id/accept` | student |

(연관) POST `/assignment/run-fill` (admin, `assignment.controller.ts:55-59`) — 아래 §3 수동 트리거.

## 3. 공백시간 강제배정·클레임

- **클레임: 존재 ✅** (`qna.service.ts:173-211`) — 단, 기획 §1-2(a)의 **TTL 자동해제·재공개 없음**(잠금=영구 assigned).
- **공백시간 강제배정: 부분 구현 ⚠** — `assignment.service.ts:203-232`(runFill ②)가 **이미 배정된 미답변 질문**의 답변블록(booking, `charge:'free', origin:'질문배정'`)을 전임 빈 슬롯에 꽂는 것까지만. 15분 cron(`:46-52`) + admin 수동.
  **갭**: 미클레임 **공개(open·미배정)** 질문의 강제배정, 배정 알림→수락/불가·미응답 타임아웃 재배정 전무.

## 4. AI 초안 연동 상태

- LlmProvider 주입 ✅ (`qna.module.ts:13`, `qna.service.ts:40`) — **사용처는 유사도 검사 1곳뿐**.
- **AI 초안 자동 등록 ❌** — LlmProvider 인터페이스에 답변 초안 생성 메서드 자체가 부재.
- **✦ 초안 / ✦✎ 보완 / ✓ 선생님 라벨 ❌** — `qna_answer.ai_flag` 없음, 보상 차등 없음. "사람 답변만 받기" 옵션 ❌.

## 6. 다음 스프린트 백로그 후보 (우선순위 3)

1. **SLA 타임스탬프 4점 + 풀별 집계 기반** — `claimed_at`/`first_reply_at`/`resolved_at` 추가, claim·answer·accept 시점 기록. 모든 지표·리그·평가의 전제, 소급 불가라 최우선. `board_scope`에 `scoped` 추가 여부도 같은 마이그레이션에서 결정 권장.
2. **강제배정 정식화** — 미클레임 공개질문 → 공백 전임 자동배정 + 알림·수락/불가·타임아웃 재배정 상태기계. 클레임 TTL(§1-2a)과 한 세트로 배정 루프 완성.
3. **불만족 후속 경로 2종(상담 승격·재답변)** — `escalated_booking_id`·`reanswer_count` + `qa.reanswerLimit` 정책값, 이전 답변자 제외·사유 수집, 3면(웹 학생/교사·모바일) 버튼.

보조: AI 초안 자동 등록(§3~4)은 LlmProvider 초안 메서드 + `qna_answer.ai_flag` 선행 필요 — 리그·보상 차등과 함께 Q3 이후 배치가 실행계획 단계 요약(§7)과 정합.
