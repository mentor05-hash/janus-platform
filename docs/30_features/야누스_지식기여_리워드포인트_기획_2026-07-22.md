# 야누스 지식기여 리워드 포인트 — 기능 기획서 (가칭 "기여 포인트 / Contribution Point, CP")

> 생성 2026-07-22 · 문서 서열 4(기능 기획서). 발단: 커뮤니티 Q&A에 고학력 학부모를 지식 공급자로 전환하는 아이디어.
> 방향 확정(사용자, 7/22): **① 크레딧과 별도 통화 ② 양도 시 수수료 ③ 콘텐츠·인강 구매 전용 사용.** 수치·명칭은 [DEC] 미결.

---

## 1. 배경·기회
- 교육열 높은 지역일수록 **학부모 학력 수준도 높다**(대부분 대졸+). 이들이 커뮤니티 Q&A에 답하면 **양질의 지식 공급이 공짜로 늘어난다**.
- 야누스는 이미 커뮤니티 답변을 **로그인 전원(학부모 포함)**에게 열어둠 → 공급 채널은 존재. 남은 건 **참여 동기(보상)**와 **보상의 안전한 순환(양도·사용)**.
- 목표: **참여·리텐션↑, 콘텐츠(인강·자료) 소비↑** 를 얻되 **핵심 유료 매출(상담·과외)은 방어**.

## 2. 핵심 개념 (한 줄)
> 커뮤니티 답변이 **채택**되면 답변자에게 **기여 포인트(CP)** 적립 → **연결된 자녀에게 양도(수수료 차감)** → **콘텐츠·인강·자료 구매에만** 사용.

## 3. 왜 크레딧과 분리하나 (사용자 결정)
| | 크레딧(기존) | 기여 포인트 CP(신규) |
|---|---|---|
| 취득 | **결제 충전** | **지식 기여(채택)** |
| 사용처 | 상담·과외 등 **핵심 유료 서비스** | **콘텐츠·인강·자료**(디지털 재화)만 |
| 성격 | 현금성(매출 직결) | 비현금·비환불·기간제 |
- CP를 크레딧으로 주면 **상담 매출을 직접 잠식**. 그래서 **별도 통화 + 사용처 제한**으로 잠식 최소화.

## 4. 매출 영향과 완충 레버 (사용자 우려 반영)
- 우려: CP로 인강을 사면 그만큼 **현금 매출↓** 는 불가피.
- 완충 레버(정책값은 [DEC]):
  1. **사용처 = 한계비용 낮은 디지털 재화 한정**(인강 VOD·자료). 인강은 1회 제작 후 추가 판매 원가≈0 → 마진 방어.
  2. **양도 수수료(소각)**: 자녀 양도 시 X% 를 소각(sink) → 포인트 인플레 억제 + 순환에서 가치 회수.
  3. **결제 시 사용 상한**: 인강 결제 금액의 **최대 N%까지만** CP로(예: 30%). 완전 무료 구매 방지, 현금 매출 일부 보존.
  4. **적립 상한·소멸**: 주/월 적립 상한 + 유효기간(예: 6개월) → 무한 적립·투기 방지.
  5. **채택 게이트**: 답변 "양"이 아니라 **채택된 답변만** 적립 → 품질 유지·남발 차단.

## 5. 적립·양도·사용 규칙 (v1 초안)
- **적립**: `커뮤니티 답변 채택` 시 답변자 CP += 보상. 리그 tier로 보상률 차등(고 tier = 소폭↑). 주간 상한.
- **양도**: 본인 CP → **승인된 연결 자녀(guardian_student_link)에게만**. 양도액의 수수료% 소각, 나머지 자녀 지갑 적립. 감사 로그 필수.
- **사용(차감)**: 인강/자료 결제 화면에서 "CP 사용"(결제액의 N% 한도). 상담·과외·크레딧 충전엔 **사용 불가**.
- **현금화 불가**·환불 불가·기간제.

## 6. 데이터·API 스케치 (크레딧과 완전 분리)
```
reward_point_account   account_id(pk), balance, lifetime_earned, updated_at
reward_point_ledger    id, account_id, delta, reason(accept|transfer_out|transfer_in|redeem|fee_burn|expire),
                       ref_id, created_at            ← 전건 감사·부정 추적
```
```
POST /rewards/transfer            연결 자녀에게 양도(수수료 소각·audit)
GET  /rewards/me                  내 CP 잔액·원장
(내부) 채택 훅 → grantOnAccept(answerId)      적립
(내부) 인강/자료 결제 → redeemPoints(orderId, amount, capPct)   사용
(내부) 만료 배치(월) → expire
```
- 크레딧(`credit_account`)과 **테이블·잔액·정산 완전 분리** — 상호 환전 금지.

## 7. 기존 자산 재사용 (신규 최소화)
- 커뮤니티 답변·**채택(accept)**·리그 tier: `qna` 모듈 — 적립 트리거 그대로.
- **guardian_student_link**(승인 연결) + `guardian.service.chargeChild` 배관: 양도 대상·이체 패턴 재사용.
- **직거래 방지 필터(C1)**: 보상 노린 사적 거래 유도 차단.
- 인강/자료 구매: `lecture`·`material`·`entitlement` 모듈에 CP 결제 옵션 주입.

## 8. 정책 결정 필요 [DEC] (미결 — 값 확정 후 본 문서 갱신)
- ㉓ **명칭**(기여 포인트/야누스 포인트 등) + 심볼.
- ㉔ **적립률·주간 상한·tier 차등**(예: 채택 1건 = ?CP).
- ㉕ **양도 수수료율**(예: 10~20%) · 자녀 외 양도 허용 여부(기본: 자녀 한정).
- ㉖ **사용처 범위**(인강·자료만 vs 굿즈·이벤트 포함) · **결제 시 사용 상한%**.
- ㉗ **유효기간**(예: 6개월) · 소멸 정책.
- ㉘ **세무·전자금융 검토**: CP가 현금성으로 해석되지 않도록(비환불·플랫폼 내·자녀 한정) 법무 확인.

## 9. 리스크·가드레일
- **오정보 확산**: 입시 답변 오류 → 채택 게이트 + 신고·모더레이션 + (선택)선생님 검증 배지.
- **어뷰징**: 자문자답·품앗이 채택 → 동일 IP/관계 감지, 채택률·이상탐지, 수수료 소각이 순환 이득 억제.
- **형평성 논란**: 고학력 지역 유리 → CP는 "사용처 제한 소액 보상"으로 포지셔닝(등급·랭킹은 명예 위주).
- **매출 잠식**: §4 레버로 상한·소각·현금상한 관리. 도입 후 인강 현금매출 vs CP사용 **모니터링 지표** 필수.

## 10. 단계 로드맵
- **v1(최소)**: reward_point 원장 + 채택 적립 + 자녀 양도(수수료) + 인강 결제 시 CP 부분사용(상한%). 학부모 화면에 CP 지갑·양도 카드.
- **v2**: 만료 배치·이상탐지·관리자 대시보드(적립/사용/소각/현금영향), tier 보상 차등.
- **v3**: 사용처 확장·이벤트·시즌 정산.

> 착수 전제: 크레딧 경제(N23~25 가격 정책)와 함께 검토 — CP 사용 상한%·수수료율이 유료 매출 곡선에 직접 영향.
