# 야누스 커뮤니티 답변자 신뢰·능력 표시 + 답변 타게팅 — 기능 기획서

> 생성 2026-07-22 · 문서 서열 4(기능 기획서). 발단: 커뮤니티 Q&A에서 "누구에게 답을 받을지"를 학생이 성향대로 고를 수 있게 하자는 아이디어(3턴 브레인스토밍).
> 짝 문서: `docs/30_features/야누스_지식기여_리워드포인트_기획_2026-07-22.md`(CP, N32) — **능력 신호의 연료**. Decision-Register **N33**.
> 방향 확정(사용자, 7/22): ①답변 대상 선택 옵션 ②학생증·성적표 인증(신뢰 축) ③과목·설명방식 오각형(능력 축) ④**일정 표본 이상일 때만 능력치 공개** ⑤**답변받은 질문자가 능력치를 재평가**.

---

## 1. 배경·문제
- 현재 커뮤니티 답변은 **로그인 전원 무차별**(`qna-community.ts` `canAnswerCommunity` — 미숨김·미해결·본인 아님이면 누구나). 답변자를 **성적대·과목·성향으로 구분할 축이 아예 없다.**
- 학생마다 원하는 답변자가 다르다(성향의 차이): 전과목 골고루 잘하는 사람 vs **특정 과목만 괴물처럼 잘하는 또래**, vs 정확한 **멘토/선생님**.
- 하지만 답변자가 **소수일 때 대상을 좁히면 질문이 굶는다**(무응답 부작용). → 표본·밀도에 연동된 **소프트 설계**가 필수.

## 1-1. 핵심 설계 의도 (North Star)
> **그냥 질문에 답하는 것보다, 리그 Q&A로 "내공"을 쌓은 쪽이 더 많이 선택받고 더 많이 번다.**
- 플라이휠: **리그(내공 축적)** → **타게팅에서 선택받음(수요 집중)** → **CP·수익(보상)** → 다시 리그 참여 동기. 세 문서(본 문서·N32·리그)가 이 한 바퀴를 구현한다.
- 설계의 모든 선택은 이 방향으로 정렬: 능력 신호는 **실적으로만** 오르고(§4·§5-2), 선택 옵션은 능력 상위를 **우선 노출**(§6), 보상은 **채택·재평가에 연동**(N32).
- ⚠ 동반 위험 = **승자독식**: 상위 소수에 질문이 쏠려 신인이 굶으면 공급이 마른다. → **신인 보호 가드레일**(§6-4)로 균형: 우선 노출 후 전체 개방(소프트), 신인 슬롯·"새 답변자" 라벨로 초기 노출 보장.

## 2. 세 겹 구조 (한 눈에)
```
① 답변 타게팅 (학생이 성향대로 답변 대상 선택)
     └ 필요 신호 ─┬ 축 A · 신뢰(인증 provenance)   증빙 기반·정적
                 └ 축 B · 능력(과목/설명방식 오각형)  실적·재평가 기반·동적
                        └ 연료 = CP 과목별 적립(N32) + 리그(과목별 확장)
공통 원칙: ▸일정 표본 이상만 공개  ▸답변받은 질문자가 재평가  ▸PII 비보관
```

## 3. 축 A — 신뢰(인증) : 증빙 기반·정적
학원찾기 provenance 3등급(`academy-finder/provenance.ts`)과 본인확인 어댑터(`guardian-consent/identity-verify.provider.ts`, stub)를 **답변자 프로필에 재사용**.

| 등급 | 근거 | 부담 | 배지 |
|---|---|---|---|
| 미인증 | 없음 | 0 | (없음) |
| **자기신고(claimed)** | "수학 1등급" 등 스스로 입력 | 낮음 — 대다수 | `자기신고` |
| **검증(verified ✓)** | 학생증·성적표 제출·검수(또는 발급기관 연동) | 높음 — 소수 프리미엄 | `검증 ✓` |

**가드레일(반드시)**
- ⚠ **수능·모의고사 성적표 = 민감 PII + 미성년 성적** → CLAUDE.md §4 위반 금지. **원본 이미지는 저장하지 않고, 검증 후 "등급 플래그"만** 남긴다(제출물은 검수 후 파기 or 비영구 처리).
- ⚠ **위조 리스크**: 성적표는 조작이 쉬움. 발급기관 연동/사람 검수 전엔 verified 신뢰를 과대표시하지 않는다.
- **강제하지 않는다**: 대다수는 claimed + 축 B(실적)로 신뢰를 얻고, verified는 소수 상위 신호로만.

## 4. 축 B — 능력(오각형) : 실적·재평가 기반·동적
자기신고가 아니라 **쌓인 실적과 수신자 평가에서 산출**되는 신호(→ 부풀리기 방지 내장).

- **과목 오각형** (예: 국·영·수·탐1·탐2): 과목별 **채택 실적**에서 자동 산출. CP를 과목 단위로 적립(N32)하면 신호가 공짜로 딸려 나온다.
- **설명방식 오각형** (예: 정확·친절·논리·속도·눈높이): **질문자의 재평가(§5)**에서 산출 — *현재 이 데이터 없음, 재평가 UI로 신설*.

## 5. 공통 메커니즘 (사용자 확정 2건)
### 5-1. 공개 게이트 — 일정 표본 이상만 노출
- 학원 코호트의 **n≥5** 원칙 재사용. 축(과목/설명 차원)별 **표본 미달이면 그 축은 "데이터 쌓는 중"으로 흐리게**, 오각형 전체도 **최소 건수 전엔 미표시**.
- 효과: 1건 만점 → 만점 오각형 같은 **거짓 레이더 차단**, 소수 구간의 무응답 부작용 완화(좁힐 옵션 자체가 표본 있을 때만 뜬다).

### 5-2. 재평가 루프 — 답변받은 질문자가 능력치를 다시 평가
- 채택/답변 수령 시 질문자가 **설명방식 축별 간이 평가**(정확·친절·논리·속도·눈높이) → 이 값이 축 B(설명방식 오각형)의 **유일한 데이터 원천**.
- **채택 실적**(과목 오각형) + **수신자 재평가**(설명방식 오각형)의 이원 구조 → 자기신고로 못 올린다.
- 재평가는 **소수 축·간단하게**(별 1~5 or 이모지), 응답률이 신호 품질을 좌우하므로 채택 흐름에 자연스럽게 붙인다.

## 6. 답변 타게팅 규칙 (소프트·부작용 방지)
질문 작성 시 **답변 대상 옵션**(기본=전체). 잠그지 않고 **우선 노출 후 자동 완화**.
1. **소프트 우선권**: 선택 대상에게 먼저 노출·알림(우선 X시간) → 이후 **자동 전체 개방**. 굶기지 않는다.
2. **밀도 게이트**: 해당 과목에 자격 답변자 **N명 이상일 때만** 좁힌 옵션 노출. 소수면 `전체`만.
3. **성향 선택지(안)**: `전체`(기본) / `멘토·선생님` / `이 과목 강자`(과목 오각형 상위) / `또래 학생`.
4. **신인 보호(승자독식 방지)**: 우선 노출은 상위에 주되 **신인 슬롯**(초기 답변 N건까지 "새 답변자" 라벨로 노출 보장) + 전체 개방 폴백 상존 → 상위 쏠림으로 공급이 마르지 않게. 내공 우대(North Star)와 신인 유입을 동시에.

## 7. 데이터·API 스케치 (신규 최소화)
```
answerer_credential   account_id, subject, claimed_grade, verify_tier(none|claimed|verified),
                      verified_at, ref(비영구 검수 참조)      ← 원본 성적표 비보관
answerer_subject_stat account_id, subject, authored, accepted, accept_rate   ← 과목 오각형(집계)
answer_rating         answer_id, rater_id(질문자), axis(accuracy|kindness|logic|speed|level),
                      score, created_at                       ← 설명방식 오각형(재평가 원천)
qna_question(+col)    answer_audience(all|mentor|subject_ace|peer), audience_until  ← 타게팅
```
```
POST /qna/community/:id/answers/:aid/rate   답변 수령자 재평가(축별)
GET  /qna/answerers/:id/profile             신뢰 배지 + 오각형(표본 게이트 반영)
(내부) 채택 훅 → answerer_subject_stat 갱신 + CP 과목별 적립(N32)
(내부) 타게팅 만료 배치 → audience_until 지난 질문 전체 개방
```
- 표시 계층은 **전부 게이트 통과분만** 반환(n<임계면 축/오각형 숨김).

## 8. 기존 자산 재사용
- **provenance 3등급 라벨**(`academy-finder/provenance.ts`) → 신뢰 배지.
- **IdentityVerifyProvider**(stub) → 성적표·학생증 검증 어댑터 뒤로.
- **리그**(`qna-league.ts`) — 현재 **과목 무관 통합 실적** → **과목별로 확장**(answerer_subject_stat)해야 "과목 강자" 성립. N27(리그 수치)과 함께.
- **커뮤니티 채택/신고/CP 적립**(qna, N32) → 재평가·적립 트리거 재사용.

## 9. 정책 결정 필요 [DEC]
- ㉙ **공개 표본 임계값**(오각형 전체·축별 n≥? — 기본 5 후보).
- ㉚ **오각형 축 정의**(과목 세트 / 설명방식 5축 명칭).
- ㉛ **인증 범위·검수 방식**(자기신고 허용선, verified 검수 주체·발급기관 연동 여부, 제출물 파기 정책).
- ㉜ **타게팅 옵션 세트·우선 노출 시간(X)·밀도 게이트 N**.
- ㉝ **재평가 응답 유도**(채택 필수 여부·리워드 연동 여부).
- ㉞ **보상 모델 갈래**(§9-1): A=CP 기본 / B=현금성 시상(옵션·정산·세무 별도 결정) / 하이브리드. 대상(미성년 제외 여부)·자격·지급 방식.

## 9-1. 보상 모델 갈래 (옵션 — 미결)
North Star("더 선택받고 **더 번다**")의 "번다"를 무엇으로 실현할지 두 갈래. 기본은 A, B는 옵션으로 열어만 둔다.

| | **갈래 A · CP 비현금(기본)** | **갈래 B · 현금성 보상(옵션)** |
|---|---|---|
| 보상 | 기여 포인트 CP(콘텐츠·인강 전용, N32) | 상위 답변자에게 현금성 정산(선생님 share 유사) |
| 매출 영향 | 핵심 유료 매출 방어(잠식 최소) | **직접 비용** — 답변당/채택당 지급 |
| 걸림돌 | 낮음(플랫폼 내 통화) | **정산·세무·전자금융** + 원천징수·사업소득/기타소득 판정 |
| 대상 | 학생·학부모 누구나 | 미성년 학생에 현금 지급 = 노동·세무 이슈 → 사실상 **성인 멘토/선생님 한정** 필요 |

- ⚠ 갈래 B는 **정산 축을 건드림** → 기존 정산·급여 파이프는 세션 규칙상 읽기전용(무개입). 도입 시 **별도 정산 결정·법무 검토**가 선행이며 본 문서 범위 밖의 결정으로 승격.
- 현실적 조합: **평시 = CP(A)**, **시즌 리그 상위 소수 = 현금성 시상(B)** 의 하이브리드가 매출 방어와 동기 부여를 함께 잡는 후보. 값·자격은 ㉞에서.

## 10. 리스크·가드레일
- **PII/미성년 성적**: 원본 비보관·플래그화(§3). 법무·개인정보 검토 필수.
- **거짓 레이더(small-n)**: §5-1 표본 게이트로 차단.
- **형평성**: 고성적·고학력 유리 → 능력치는 "성향 매칭 보조"로 포지셔닝, 답변 접근을 하드 차단하지 않음(전체 개방 폴백 상존).
- **어뷰징**(자문자답·품앗이 평가): 관계·IP 감지 + 재평가 이상탐지 + CP 수수료 소각(N32)로 순환 이득 억제.

## 11. 로드맵
- **v1**: 축 A 자기신고 배지 + 축 B 과목 오각형(채택 실적) + 재평가 UI(설명방식) + 표본 게이트. 타게팅은 `전체/멘토`만.
- **v2**: verified 인증 파이프(검수·비보관) + `과목 강자/또래` 타게팅 + 밀도 게이트.
- **v3**: 리그 과목별 확장·시즌·발급기관 연동 검토.

> 착수 전제: N32(CP 과목별 적립)와 동반 — 능력 신호의 연료이자, 착수 순서상 CP 적립이 먼저 서면 과목 오각형이 공짜로 선다.
