# 클로드 코드 지시서 — 디자인 시안 통합·기존 코드 절충 (2026-07-07)

> 위치: `00_docs/20_exec/` · 실행계획서 v2의 W2(티어 빌드)·W3(실라우트 이식·브랜드 마감)에 흡수되는 작업.
> 사용법: 아래 "■ 세션 프롬프트"를 클로드 코드에 순서대로 붙여넣는다(세션 1개 = 스텝 1개). 스텝 0 완료 전 스텝 1~3 착수 금지.

## A. 배경 — 무엇과 무엇이 겹치는가

| 영역 | 기존 코드(검증됨) | 신규 디자인 시안 | 충돌 성격 |
|---|---|---|---|
| 배치표 | `배치표_DDD_v2/tools/gen_jeongmil.cjs` → v22 정적 HTML(입력 3모드·토글·gbias·신뢰도·다년추세·janus_score 연동) | "야누스 배치표" 시안: 동일 기능의 새 UI + **신규 요소**(무료 티어 게이팅 UI·포트폴리오 가나다 조합·배치 맵/스펙트럼·온보딩·컨설턴트 콘솔·미리보기 티어 토글) | **로직 재구현 위험** — 표현만 바꿔야 함 |
| 랜딩/관문 홈 | `야누스_사이트/index.html`(의도분류·LLM 훅·커리큘럼 카드) + 마케팅 사이트(W3 이식 예정) | "야누스 랜딩" 시안: 관문 히어로 4방향 + 론칭 랜딩("근거 4종·블랙박스가 아닙니다" 섹션·신호등 카피) | 로직(분류·훅) vs 표현(신규) 분리 필요 |
| 브랜드/토큰 | apps/web 구 스타일(구 브랜드 잔재) | "브랜드 가이드" 시안: 로고 락업·여백(문턱 바)·오용 금지·컬러 의미·타이포(Pretendard/IBM Plex Mono) 규범 | 전면 교체 대상 — 단일 토큰 소스 필요 |

## B. 절충 원칙 4 (모든 스텝의 상위 규칙)

1. **로직·데이터 파이프는 기존 우선, 비주얼은 신규 우선.** 검증된 계산·연동(3모드 환산, gbias, relTier, janus_score, LLM 훅)은 절대 재작성하지 않고, 표현 계층(HTML/CSS 템플릿)만 교체한다.
2. **번들 HTML 직접 이식 금지.** 클로드 디자인 산출물은 JS 번들(개당 ~3MB)이므로 코드로 복사하지 않는다 — 시각 참조 + 토큰 수치 추출용. 구현은 기존 스택(생성기 템플릿·apps/web)에 새로 작성.
3. **기능 패리티 통과 전 구버전 삭제 금지.** 신 UI는 병행 산출(`_v23` 등)로 만들고, 패리티 체크리스트 전 항목 통과 후에만 기본값 전환. 롤백 경로 유지.
4. **시안의 신규 기능은 이번 작업에서 만들지 않는다.** 포트폴리오 조합·배치 맵·온보딩·컨설턴트 콘솔은 백로그로 분리해 [DEC] 후 주차 배치(스텝 4). 이번 범위 = 리스킨 + 티어 UI(W2와 결합)까지만.

## C. 클로드 코드 폴더 연결 방법 (권장 구성)

1. **기본: 모노레포 루트에서 실행.** `cd ~/janus/10_platform && claude` — 클로드 코드는 실행한 작업 디렉토리를 기준으로 파일을 보고, 그 경로의 CLAUDE.md를 읽는다. `00_docs`를 W1 계획대로 repo의 `docs/`로 편입해 두면 기획·지시서가 별도 연결 없이 항상 접근된다(가장 깔끔한 해법).
2. **repo 밖 폴더는 --add-dir.** 시안 번들(40_workbench/design)이나 janus-data처럼 repo 밖 폴더가 필요한 세션은 시작 시 `claude --add-dir ~/janus/40_workbench/design`, 또는 세션 중 `/add-dir <경로>`로 추가한다. 매번 쓰는 조합은 `.claude/settings.json`의 `additionalDirectories`로 고정할 수 있다.
3. **20_data는 상시 등록하지 말 것.** 데이터 폴더는 필요한 세션에서만 add-dir로 열어 실수(경로 하드코딩·커밋 유출)를 구조적으로 줄인다. CLAUDE.md에 "데이터는 JANUS_DATA_DIR ENV 참조, 경로 하드코딩 금지" 규칙 명시.
4. CLAUDE.md 갱신: 세션 리추얼(현황 로드→체크 갱신→커밋), 한글 파일 패치 규칙, 본 지시서 위치를 추가해 모든 세션이 같은 규칙에서 출발하게 한다.
