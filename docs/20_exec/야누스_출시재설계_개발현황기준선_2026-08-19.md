**따라서 "11월 중순 오픈"은 세 가지 중 하나로 갈린다. 재설계안이 어느 쪽인지 명시되어야 한다:**

| 해석 | 실제 시점 | 배치표에 들어가는 성적 | 개발 함의 |
|---|---|---|---|
| ⓐ 수능 직후 **가채점 배치표** | 11/19 저녁 ~ 11/20 | 학생 자가 입력(가채점 원점수) | **가장 빠른 트래픽**. 표준점수 미확정 → 예측 오차 큼, 면책 고지 강화 필요 |

> **개발측 권고: ⓒ.** 본부 D-022도 같은 구조를 3단 파도로 부른다 — **11/19 가채점(리허설) → 12/11 실채점(피크) → 2027-01-04~07 정시 원서(결제 전환)**. 정점에 서비스가 처음 열리면 장애를 실사용자와 함께 겪으므로, 11월 중순 오픈은 "정점 3주 전 리허설 기간 확보"로 봐야 값이 산다.

## 4. 구조적 장애물 — 재설계안이 무엇을 쓰든 먼저 걸리는 것

### ① 브랜치가 갈라져 있어 "우리가 한 것"이 한 곳에 없다 ★최우선

| 브랜치 | 최신 마이그 | 최대 O | 최종 커밋 |
|---|---|---|---|
| `feat/consulting-intake` (**트렁크**) | 0106 | **O212** | 08-09 |
| `claude/connection-status-check-tm8we0` (데모, 현재 세션 위치) | 0106 | O184 | 08-12 |
| `feat/school-record-guard` | 0090 | O96 | 07-24 |
| `feat/planner-domain` | 0048 | O43 | 07-24 |
| `recovered-n33-pentagon` | 0090 | O99 | 07-24 |
| 그 외 원격 브랜치 | — | — | 총 **24개** |

트렁크와 데모 브랜치는 **Decision-Register가 갈려 있다**(O185~O212가 데모 브랜치에 없음). 미병합 브랜치에 완성된 기능(생기부 가드 콘솔·플래너 도메인·N33 오각형)이 잠겨 있다.
→ **재설계 착수 전 "브랜치 수렴 작업"이 0주차 과제로 필요.** 이걸 안 하면 재설계안의 "완료/미완료" 판정 자체가 틀린다.

**★ 2026-08-19 추가 발견 — 수렴이 급한 구체적 이유 3가지**

| # | 트렁크에 없는 것 | 영향 |
|---|---|---|
| 1 | **무료판 배포 가드의 질량 기반 판정**(레드팀 위음성 수정 · 사전 압축 밀수 차단) | 트렁크 `tier_build.py` 는 질량 언급 **0건**, 데모 브랜치는 18건. **트렁크에서 빌드하면 레드팀이 뚫은 이름 기반 구버전 가드가 돈다** — 무료판 공개 배포 경로의 실질 위험 |
| 2 | **마케팅 랜딩·서비스 소개 재작성**(O184) | 트렁크판 `marketing/src/index.html` 은 구버전. A층 표기 전환도 여기만 적용 불가였다 |
| 3 | **`packages/nav`** (트렁크에만 있음 — 방향이 반대) | 데모 브랜치가 트렁크보다 뒤처진 부분. 양방향으로 갈려 있어 한쪽 머지로는 안 끝난다 |

> 즉 **트렁크와 데모 브랜치는 서로가 서로에게 없는 것을 갖고 있다.** 수렴은 "데모를 트렁크에 넣기"가 아니라 **양방향 정합**이다.

### ② 무료 배치표 배포의 선행 3건 (2026-08-08 실측, 미해소)

| 선행 | 상태 | 안 되면 |
|---|---|---|
| 마스터 HTML 센티넬 태깅 | ❌ 마스터 5종 전부 `JANUS-TIER` 0건 | `tier_verify.py`가 "제거 0건"을 잡아 **검증 실패 → 배포 불가** |
| janus-public 저장소 + 무료판 골격 | ❌ `30_public/`에 README 하나, git 저장소 아님 | Pages가 배포할 원천이 없음 |
| 입시 캘린더 공고 대조 | ❌ 9건 전부 `provisional` | O210이 정한 **공개 배포 조건 위반** |

첫 줄이 핵심 — **정시배치표 마스터 자체가 아직 티어 파이프라인에 물리지 않았다.** 11월 산출물을 그대로 넣는다 해도 태깅 규약을 마스터 생성기(`gen_jeongmil.cjs`) 쪽에 심어야 한다. **이건 배치표 독립 트랙 몫이라 이 세션이 혼자 못 끝낸다.**

### ③ 오리진이 이 맥이다

현재 공개 경로는 명명된 터널 A안 — **맥이 꺼지거나 잠들면 전부 죽는다**. 12월 원서 3주를 맥 오리진으로 넘길지 여부는 재설계안이 답해야 할 인프라 결정(§2-3 클라우드 전환 트리거).

### ④ 공개된 얼굴이 0개다

`ianuspath.com` apex·www에 DNS 레코드가 없고, 데모는 전부 Access 명단제 뒤에 있다. **"도메인이 있다"가 "공개된 서비스가 있다"는 아니다.**

### 7-3. 임계경로 — 코드가 아니라 **외부 리드타임**이 결정한다

유료가 확정된 이상, 가장 긴 사슬은 개발이 아니라 행정·심사다. 그리고 **한 곳에서 순환한다**:

```
사업자등록
  └→ PG 가입 신청 → 구매안전서비스 이용확인증 발급
        └→ 통신판매업 신고(구매안전서비스 확인증 필요)
              └→ PG 심사 ← ⚠ 심사는 "실제 열려 있는 사이트"를 본다
                    (약관·환불규정·사업자정보·가격 표시)
                    └→ 계약·키 발급
                          └→ real-pg.provider 구현 + 웹훅 검증 + 환불 v1
                                └→ 실카드 소액 충전→결제→환불 왕복 E2E
```

**순환 지점**: PG 심사가 공개 사이트를 요구하는데, **지금 `ianuspath.com`에 외부인이 볼 수 있는 페이지가 0개**다(전부 Cloudflare Access 뒤).
→ **해소책**: apex·www 마케팅 랜딩은 Cloudflare Pages 정적이라 **맥·클라우드 전환과 무관하게 먼저 열 수 있다.** 여기에 사업자정보·약관·환불·가격 표시를 얹으면 심사 요건을 만족시키면서 클라우드 전환을 기다리지 않아도 된다.

> ⚠ 각 단계 소요는 통상 며칠~2주 수준이나 **정확한 리드타임은 토스페이먼츠·관할 구청에 직접 확인해야 한다.** 아래 역산은 확인 전 잠정치다.

### 8-3. ★발견 1 — 드라이런은 통과하고 수능 당일에 죽는다

지시서 §4 세션 A 완료 기준은 **`--mode dry-run` 30분 완주**다. 그런데:

| 대상 | `JANUS-TIER` 센티넬 |
|---|---|
| `ops/placement/fixtures/master_sample.html` (드라이런이 쓰는 것) | **5건 있음** |
| 실제 마스터 5종 (11/19에 쓸 것) | **0건** (2026-08-08 실측, §4-②) |

`tier_verify.py`는 "제거 대상 0건인데 통과"를 막는 `require_stripping` 게이트를 갖고 있다(O201). 따라서 **픽스처로는 4단계를 통과하고, 실마스터로는 4단계에서 비-0 종료한다.** 드라이런 30분 완주가 당일 성공을 전혀 보장하지 못한다.

이건 O211이 기록한 함정("단언이 0건 실행돼도 전체 통과로 나온다")과 **같은 형태의 재발**이다.

**조치 제안 — 세션 A 완료 기준에 2건 추가:**
- [ ] **센티넬 부재 마스터로 음성 대조** — 센티넬을 지운 픽스처를 넣으면 파이프라인이 **비-0으로 죽는지** 확인(죽어야 정상). 죽지 않으면 게이트가 꺼진 것이다.
- [ ] `pipeline_run.sh`에 **0단계 선검사** 추가 — `grep -c "JANUS-TIER" <마스터>`가 0이면 **빌드 전에** 즉시 중단하고 "마스터 센티넬 미태깅" 사유를 출력. 19:30에 4단계까지 갔다가 죽으면 남은 시간이 없다.

> 근본 해소는 **마스터 센티넬 태깅**(배치표 독립 트랙 몫, §4-②)이며 이 세션이 대신할 수 없다. 지시서에 이 선행이 빠져 있다 — **파이프라인이 완성돼도 태깅 없이는 11/19에 배치표가 나오지 않는다.**

### 8-4. 발견 2 — P3의 `janus_score`는 DB 테이블이 아니다

지시서 §3 세션 B는 "`janus_score`에 `estimation_mode` 컬럼 추가 (마이그레이션)"이라고 쓰지만:

- **DB 저장 모델은 `score_report` / `score_item`** (prisma:117·139). `janus_score`라는 테이블은 없다.
- **`janus_score`는 C1 접합계약의 키·이벤트 이름**이고 **O43으로 v22 키가 동결**돼 있다(변경 금지, 하위호환 확장만). 접합계약 19테스트가 위반을 자동 차단한다.

또 지시서 예시의 **`POST /api/v1/scores/input`은 존재하지 않는다.** 실제 입력 라우트는 `POST /scores/manual` · `/scores/excel` · `/scores/ocr` · `/scores/me`.

→ 세션 B는 착수 전에 **두 가지를 분리해 결정**해야 한다:
1. **DB 컬럼** — `score_report`에 `estimation_mode` 추가 (마이그레이션 `0107` 또는 이후)
2. **계약 필드** — 배치표 엔진이 "이건 가채점 추정치"임을 알아야 면책 문구를 띄우므로 `janus_score` 페이로드에도 실려야 한다. 이건 **C1 계약 확장**이라 하위호환 추가 필드로만 가능하고, 핸드오프 §②의 절차(플랫폼 트랙 먼저 반영 + Register 기록)를 밟아야 한다.

### 8-5. 발견 3 — 번호 충돌 2건

**① N48이 두 뜻으로 쓰이고 있다.**

| 출처 | N48의 뜻 |
|---|---|
| 본부 W2 문서·파이프라인 지시서 | "어디가 저작권 확인 보류, **통과 가정 하 개발 선행**" |
| 코드세션 트리(데모 브랜치) + `야누스_도메인주소_배치도_2026-08-12.md` | "**무료 배치표 주소** — www 하위 경로 vs 별도 호스트" (N49 = api 호스트 분리) |
| 본부 Decision-Register §2-3 예약표 | "N48~ 미예약 — 자유" |

원인은 §4-①과 같다 — **데모 브랜치가 트렁크에 합류하지 않아 본부가 N48·N49 사용을 못 봤다.** D-015 규칙상 N 정본은 본부 문서지만, 코드세션 쪽 N48은 이미 문서에 박혀 있다. **어느 쪽을 재번호할지 사용자 판정 필요.**
⚠ 2026-08-19 대화에서 사용자가 "이번 주 결정"이라고 한 N48은 **도메인 주소 쪽**이었다 — 본부 자료의 N48과 다른 안건이다.

**② O 번호 블록 예약표가 낡았다.**
데모 브랜치 예약표는 "O191~ 자유"라고 하지만, **트렁크는 이미 O191~O202·O210~O212를 썼다.** 지시서 §7대로 O를 등재할 때 O191을 쓰면 충돌한다.
→ **이 워크스트림은 `O213~O225` 를 예약**하고 시작한다(O203~O209는 트렁크 갭이라 회피).
