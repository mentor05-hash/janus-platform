신규 스텝3 스펙 `src/modules/guard/school-record-guard-step3.spec.ts` — **12/12 통과**(실 DB, 서비스 수동 결선). 케이스:

- 토글: ① 기본값 비활성(off, 저장행 없음) ② 본사 마스터 수동 on→off ③ 비-본사(centerId 보유) 변경 거부
- 컨설팅 게이트: ④ 토글 ON → 신규 생기부(`student_record`) 업로드 **거부**(`SR_CONSULTING_DISABLED`, `consulting_document` 0행) ⑤ 토글 ON이어도 **성적표(`transcript`) 통과**(생기부만 차단) ⑥ 토글 OFF → 신규 생기부 업로드 **허용**
- 통계: ⑦ 차단 통계 `byReason` 에 `CONSULTING_UPLOAD_DISABLED` 집계 + `bySurface` 에 `consulting_intake`
- 이의: ⑧ 접수(open) → 큐 노출(openCount) → 처리(resolved, resolvedAt 기록)
- 예약(시간 조작): ⑨ 시행 이전 `now` → 미발화(`before-target`, off 유지) ⑩ 시행 이후 `now` → 1회 자동 활성(`scheduler`, `autoActivatedAt` 기록) ⑪ 재발화 → `already-auto-activated`(중복 없음) ⑫ 자동 활성 후 수동 off → 스케줄러 **재점화 안 함**(수동 결정 존중)

## 3. 시간 조작(예약 발화) 실측 로그

`runScheduledActivation(now)` 에 시각을 주입해 발화를 확인(공지 `runDue` 패턴). 로그:
```
WARN [SchoolRecordGuardPolicyService] 컨설팅 신규 생기부 업로드 자동 비활성화 발화(법령 시행):
     target=2026-07-28T15:00:00.000Z  now=2026-07-29T03:00:00.000Z
```
- `target=2026-07-28T15:00:00Z` = **2026-07-29 00:00 KST**(제25조의2 시행) — 기본값(ENV `SR_CONSULTING_ACTIVATION_AT` 로 조정 가능).
- `now=2026-07-29T03:00:00Z`(=12:00 KST, 시행 이후) → **활성 발화**. 동일 `now` 재호출 시 `autoActivatedAt` 마커로 **미발화**(멱등). 시행 이전 `now` 는 발화하지 않음.

## 4. 토글 on/off 동작 실측 (요약)

| 상태 | 컨설팅 `student_record` 신규 업로드 | 성적표/기존분 |
|---|---|---|
| 토글 OFF(기본, 7/29 이전) | 허용(정책 게이트 통과) | 허용 |
| 토글 ON(수동 or 7/29 자동) | **거부** 422 `SR_CONSULTING_DISABLED`(§4-d), `consulting_document` 미생성 | **영향 없음**(허용) |

- 수동 on/off 는 본사 마스터관리자만(그 외 admin·hr 는 열람). 변경은 감사 로그 `guard.sr.consulting_upload_toggle`.
- 값은 `system_setting` 에 두고 **요청 시 조회** → 재시작 없이 즉시 반영(가드 ENV 정책의 생성자 캐시와 대비).

## 5. 무취급(§1-2) 준수

- 신규 표 `school_record_block_event`·`school_record_appeal`(migrations/0090)은 **메타데이터만** 저장: 사유 코드·표면·단계·시각·행위자 id/role, 이의는 신고자 본인 문장(note). **파일명·추출텍스트·원본 미저장**(파일명이 PII를 담을 수 있어 DB 영속에서 제외 — 기존 로그보다 보수적).
- 접합: 내용 감지 가드(`assertUploadAllowed`)는 차단 시 사유/표면만 기록 후 예외. 컨설팅 정책 게이트는 `CONSULTING_UPLOAD_DISABLED`(stage=policy, surface=consulting_intake) 기록.
