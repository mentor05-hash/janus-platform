# 야누스 인프라 설정 체크리스트 — 녹음 파이프라인 개통 (2026-07-20)

> 용도: **본인(운영자)이 직접 수행할 외부 인프라 설정**의 단계별 절차. 코드는 전부 준비돼 있고(R1~R5 완료),
> 이 문서의 설정만 하면 파이프라인이 켜진다. 모든 값은 ENV/system_setting — 코드 수정 불필요.
> 시크릿은 repo에 절대 커밋 금지(§CLAUDE.md 4) — Mac의 셸 환경변수 또는 `.env`(gitignore됨)로만 주입.

## 0. 전체 그림 — 무엇을 설정하면 무엇이 켜지나

| 설정 | 켜지는 것 | 미설정 시 |
|---|---|---|
| LIVEKIT_URL/API_KEY/API_SECRET + MEDIA_PROVIDER=livekit | 화상·음성 실통화 | mock(개발용) |
| LIVEKIT_EGRESS_S3 + LiveKit 콘솔 webhook | 녹음 저장·완료 통지(R1) | 녹음 시작 시 에러 → 녹음 없음 |
| STT_PROVIDER(+키) | 전사(R2) | mock 전사(더미 텍스트) |
| LLM_PROVIDER=claude + ANTHROPIC_API_KEY | 실 요약 생성(R3) | mock 휴리스틱 요약 |
| system_setting `consult_recording` | 기능 플래그(동의 UI·파이프라인 게이트) | **전부 OFF(기본)** |

docker-compose.full.yml에 위 ENV 패스스루가 전부 들어가 있다(미설정 시 기존 동작 그대로).
적용 방법은 공통: Mac에서 ENV 지정 후 `COMPOSE_PROJECT_NAME=itall-mentoring docker compose -f docker-compose.full.yml up -d api`.

## 1. LiveKit API 키 로테이션 (기존 키가 대화 로그 등에 노출됐을 가능성 대비)

1. https://cloud.livekit.io → 프로젝트 → Settings → **Keys** → `Create key` (새 키 발급).
2. 새 `API Key`/`API Secret`을 Mac ENV로 교체: `LIVEKIT_API_KEY=...` `LIVEKIT_API_SECRET=...`
3. api 재기동 후 화상 상담 1건 실측(토큰 발급 → 입장).
4. 정상 확인되면 콘솔에서 **구 키 Revoke**. (룸 토큰은 API가 발급하므로 서버 ENV만 바꾸면 됨 — 웹·모바일 변경 없음)
   ⚠ webhook 서명도 API Secret 기반이므로, 콘솔 webhook 설정(§3)에서 **signing key를 새 키로** 지정할 것.

## 2. S3 버킷 준비 (오디오 저장 + 30일 자동 파기)

권장: AWS S3(또는 R2 등 S3 호환 — endpoint 지정).

1. 버킷 생성(예: `janus-consult-audio`), 퍼블릭 차단 ON.
2. IAM 사용자 생성 — 권한: 해당 버킷 `s3:PutObject`(egress 업로드용) + API 서버가 원본 재생을 쓰면 `s3:GetObject`.
3. **Lifecycle 규칙**: prefix `consult-audio/` → **30일 후 Expire(삭제)**.
   앱 크론이 아니라 S3 lifecycle이 파기 주체(무인 원칙) — system_setting `retentionDays`(기본 30)와 일치시킬 것.
4. ENV 주입(JSON 한 줄):
   `LIVEKIT_EGRESS_S3='{"access_key":"AKIA...","secret":"...","bucket":"janus-consult-audio","region":"ap-northeast-2"}'`
   (S3 호환 스토리지는 `"endpoint":"https://..."` 추가)

## 3. LiveKit 콘솔 webhook 등록 (egress 완료 통지)

1. 콘솔 → Settings → **Webhooks** → `Add endpoint`.
2. URL: `https://<API 공개 주소>/api/v1/media/egress-webhook`
   ⚠ LiveKit Cloud가 접근할 수 있는 **공개 https 주소**여야 한다. 로컬 개발은 터널(예: cloudflared) 주소로.
3. Signing key: §1의 **현재 사용 중인 API 키** 선택 — 서버가 `LIVEKIT_API_SECRET`으로 서명(JWT+본문 sha256)을 검증한다.
4. 이벤트: egress 관련(egress_ended 포함)만 있으면 충분. 전체 전송이어도 무해(서버가 무관 이벤트 무시).

## 4. STT 엔진 (본부 확정 대기 — §미결1)

- 현재 코드: `STT_PROVIDER=whisper` + `OPENAI_API_KEY=sk-...` (모델 변경은 `STT_WHISPER_MODEL`, 기본 whisper-1)로 즉시 가동.
- 본부 권고안(RTZR·비교조사 문서 참조)으로 확정되면 어댑터 1개 추가 개발 필요 — 확정되면 알려줄 것(개발 세션에서 추가).
- ⚠ 미성년 음성 외부 API 전송은 **위탁 이슈(본부 확인 필요)** — 확정 전 STT는 mock 유지 권장.
  또한 `sttRequiresGuardianConsent: true`(기본)면 보호자 동의(consent_guardian_at) 없는 녹음은 STT를 건너뛴다(O86).

## 5. 요약 LLM

- `LLM_PROVIDER=claude` + `ANTHROPIC_API_KEY=sk-ant-...` → 실 요약(가드레일 프롬프트 내장).
- 미설정 시 mock 휴리스틱 요약(파이프라인 검증용으로는 충분).

## 6. 기능 플래그 ON (최종 스위치 — system_setting)

기본은 전부 OFF. DB에서 한 번만 실행(api 컨테이너 경유 예시):

```sql
INSERT INTO system_setting(key, value) VALUES (
  'consult_recording',
  '{"enabled": true, "sttEnabled": true, "retentionDays": 30, "policyVersion": "v1", "sttRequiresGuardianConsent": true}'
) ON CONFLICT (key) DO UPDATE SET value = EXCLUDED.value;
```

- `enabled` — 동의 UI·녹음 시작 게이트(서버 차단). `sttEnabled` — 전사·요약 파이프라인.
- `sttRequiresGuardianConsent`는 본부 확정(2026-07-19)이므로 **끄지 말 것**.
- 되돌리기: `"enabled": false`로 UPDATE(즉시 반영, 재기동 불필요).

## 7. 개통 검증 순서 (완료 기준 = 실측)

1. §1~3만 설정(STT·LLM은 mock 유지) + §6 플래그 ON.
2. 데모 계정으로 화상 상담 → 양측 동의 체크 → 녹음 배지 확인 → 종료.
3. 확인: S3에 `consult-audio/{bookingId}-….ogg` 생성 / consult_recording 레코드 status=stored.
4. (sttEnabled면) consult_transcript 생성 → consult_report draft → 선생님 검수함에 표시 → 발송 → 학생 열람(웹·모바일 마이>상담 리포트).
5. 철회 실측: 녹음 중 철회 → egress 중단 + S3 파일 미잔존.
6. 전부 통과 후 STT·LLM 실키 투입(§4·5) 재검증.
