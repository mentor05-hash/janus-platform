> 규칙: 결정 발생 즉시 기록(세션 리추얼 ④). 미결(N)은 주간 리뷰에서 강제 처리 — "미결정 적체"가 1인 체제 최대 리스크(실행계획서 §6).

## 번호 예약 (동시 세션 충돌 방지 · O129부터 적용)

여러 세션이 각자 브랜치에서 동시에 결정을 기록하면서 **같은 O 번호를 세 번 연속 재배정**하는 일이 있었다
(O124~O126 → O127 → O128). 원인은 "다음 번호"를 **머지되지 않은 남의 브랜치**에서 알아내야 했던 것이다.
브랜치가 갈라져 있는 한 최신 번호는 어디에도 하나로 존재하지 않는다.

**규칙**: 번호를 쓰기 전에 아래 표에 **블록을 먼저 예약**한다. 예약 없이 쓰지 않는다.
블록을 다 쓰면 연장하지 말고 **새 행을 추가**한다(연장하면 남의 블록과 겹친다).
표 밖의 번호는 미예약이며, 쓰려면 예약 행부터 추가한다.

| 블록 | 예약 | 용도 | 상태 |
|---|---|---|---|
| O129~O148 · N38~N42 | 보호자 연결·권한 정합 워크스트림 | O124~O128 후속(N37 백엔드 @Roles 정렬 등) | 예약 |
| O149~O168 · N43~N47 | 플래너·학생 태스크 워크스트림 | 그룹⑤ 계열 | 예약 |
| O169~ · N48~ | — | 미예약(선점 시 이 표에 행 추가) | 자유 |

> 예약은 **선점이 아니라 통보**다. 다른 세션이 이미 쓴 번호를 예약해서는 안 되므로,
> 예약 전에 `git branch -a` 전 브랜치의 Decision-Register 최대 번호를 확인한다.
> 2026-07-26 확인 시점 전 브랜치 최대 = **O128 / N37**.
