# 야누스 DB 리네임 마이그레이션 런북 (itall → janus)

> 2026-07-22 · 결정 O90. `itall`(DB/유저/비번)→`janus`, `itall-mentoring`(compose 프로젝트/볼륨)→`janus-platform`.
> **백업 우선 안전 절차.** 컨테이너에서 dump→복원→102테이블·행수 일치·Prisma 연결까지 **리허설 검증 완료**.
> 이 코드(리네임 반영본)를 pull 한 기기에서 **1회 실행**. 데이터는 삭제되지 않으며, 검증 후 구 볼륨을 지운다.

---

## 0. 전제
- 기존 데이터는 볼륨 `itall-mentoring_pgdata`(+ storage 볼륨)에 그대로 있음.
- 새 코드는 compose 프로젝트 `janus-platform`·DB `janus` 를 기대 → 그냥 올리면 **빈 janus 볼륨**이 생김.
- 그래서 **① 구 스택에서 백업 → ② 새 janus 스택 기동 → ③ 복원 → ④ 검증 → ⑤ 구 볼륨 정리** 순으로 진행.

## 1. 백업 (구 itall 스택에서) — 가장 중요
```bash
cd ~/janus/10_platform/janus-platform     # 각자 repo 경로
mkdir -p ~/janus-migrate

# 구 스택이 떠 있어야 함(구 코드 기준). 안 떠 있으면 구 프로젝트명으로 기동:
COMPOSE_PROJECT_NAME=itall-mentoring docker compose -f docker-compose.full.yml up -d postgres

# DB 덤프(롤 의존 제거 옵션 필수 — 새 janus 유저로 복원 가능하게)
COMPOSE_PROJECT_NAME=itall-mentoring docker compose -f docker-compose.full.yml exec -T postgres \
  pg_dump -U itall -d itall --no-owner --no-acl | gzip > ~/janus-migrate/itall-db.sql.gz

# (선택) 업로드 파일 볼륨도 백업
docker run --rm -v itall-mentoring_storage:/d -v ~/janus-migrate:/b alpine tar czf /b/storage.tgz -C /d . 2>/dev/null || true
docker run --rm -v itall-mentoring_rooms_storage:/d -v ~/janus-migrate:/b alpine tar czf /b/rooms_storage.tgz -C /d . 2>/dev/null || true

ls -lh ~/janus-migrate/    # itall-db.sql.gz 존재·크기 확인 (0바이트 아니어야 함)
```

## 2. 구 스택 중지 (데이터 볼륨은 삭제하지 않음)
```bash
COMPOSE_PROJECT_NAME=itall-mentoring docker compose -f docker-compose.full.yml down
# ⚠ 절대 -v(--volumes) 붙이지 말 것 — 아직 구 데이터 필요.
```

## 3. 새 janus 스택 기동 (빈 janus DB 생성)
```bash
git pull        # 리네임 반영 코드
# 새 코드는 프로젝트명이 디렉터리(janus-platform) 기본값 → 별도 지정 불필요
docker compose -f docker-compose.full.yml up -d postgres
docker compose -f docker-compose.full.yml exec -T postgres pg_isready -U janus -d janus   # accepting 확인
```

## 4. 복원 (janus DB로)
```bash
gunzip -c ~/janus-migrate/itall-db.sql.gz | \
  docker compose -f docker-compose.full.yml exec -T postgres psql -U janus -d janus
```
> `--no-owner --no-acl` 로 덤프했으므로 janus 유저로 그대로 복원됨(리허설에서 에러 0 확인).

(선택) 업로드 볼륨 복원:
```bash
docker run --rm -v janus-platform_storage:/d -v ~/janus-migrate:/b alpine sh -c "cd /d && tar xzf /b/storage.tgz" 2>/dev/null || true
docker run --rm -v janus-platform_rooms_storage:/d -v ~/janus-migrate:/b alpine sh -c "cd /d && tar xzf /b/rooms_storage.tgz" 2>/dev/null || true
```

## 5. 검증 (구/신 데이터 일치 확인)
```bash
docker compose -f docker-compose.full.yml exec -T postgres psql -U janus -d janus -tA \
  -c "SELECT 'tables', count(*) FROM information_schema.tables WHERE table_schema='public';"
docker compose -f docker-compose.full.yml exec -T postgres psql -U janus -d janus -tA \
  -c "SELECT 'account', count(*) FROM account;"
```
- 리허설 기준값: **테이블 102개**, account 등 행수 = 백업 전과 동일해야 함.
- 전체 스택 올리고 앱 로그인(데모 계정)·데이터 노출까지 확인:
```bash
docker compose -f docker-compose.full.yml up -d
# web :8080 접속 → 로그인 → 학생/선생님/예약 데이터 보이면 성공
```

## 6. 구 볼륨 정리 (검증 완료 후에만)
```bash
docker volume rm itall-mentoring_pgdata itall-mentoring_storage itall-mentoring_rooms_storage 2>/dev/null || true
# ~/janus-migrate 백업은 며칠 보관 후 삭제 권장
```

---

## 롤백 (문제 시)
- 새 janus 스택 내리고(`docker compose -f docker-compose.full.yml down`, **-v 금지**), 구 코드로 되돌린 뒤
  `COMPOSE_PROJECT_NAME=itall-mentoring docker compose ... up` → 구 볼륨 그대로 복귀.
- 구 볼륨은 6단계 전까지 손대지 않으므로 언제든 복귀 가능.

## 유지된 식별자(리네임 대상 아님 — 별개)
- Expo `app.json owner: "itall"` — EAS 빌드 계정. 변경 시 Expo 조직 재설정 필요(별도 결정).
- `@mentoring/*` 패키지 스코프 — 전 import 경로 영향(별개 작업).
- `com.example.mentoring` 번들ID — 스토어 재등록 영향(O47 유지).
