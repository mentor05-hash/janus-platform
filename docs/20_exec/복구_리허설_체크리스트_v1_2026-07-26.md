# 복구 리허설 체크리스트 v1 (2026-07-26)

> 위치 `docs/20_exec/` · 백로그 **B006**. 관련: `ops/backup-db.sh`·`ops/backup-offsite.sh`·`ops/restore-db.sh`.
> **전제**: "백업이 있다"와 "복원된다"는 다른 사실이다. 복원해 본 적 없는 백업은 백업이 아니다.
> **주기**: 주 1회(일요일 주간 리뷰에 포함). 결제·PII 가 실제로 들어오는 W9 이후에는 건너뛰지 않는다.

## 0. 판정 규칙

- 각 단계의 `증빙` 칸을 채워야 그 회차가 통과다. 빈 칸이 있으면 미실시로 본다.
- **운영 DB 에 복원하지 않는다.** 반드시 별도 DB(`RESTORE_DB=itall_restore_test`)로 복원한다.
- 실패 시 그 자리에서 원인을 기록하고, 다음 리허설까지 방치하지 않는다(백업이 깨진 채로 한 주를 보내면 그 주의 데이터가 사라진다).

## 1. 리허설 절차

| # | 단계 | 명령 / 확인 | 통과 기준 | 증빙 |
|---|---|---|---|---|
| 1 | 최신 백업 존재 | `ls -1t ~/itall-backups/itall-*.sql.gz \| head -3` | 최신 파일이 **24시간 이내**, 크기가 0이 아님 | 파일명·크기·타임스탬프 |
| 2 | 오프사이트 사본 존재 | `aws s3 ls s3://$S3_BUCKET/$S3_PREFIX/ --endpoint-url $S3_ENDPOINT \| tail -3` | 최신 원격 파일이 24시간 이내 (R2 미개설이면 `해당없음` — B014) | 목록 출력 |
| 3 | 원격 → 로컬 복호 | `aws s3 cp s3://…/<파일> - \| gpg --batch --passphrase-fd 0 -d > /tmp/r.sql.gz` | 복호 성공 + `gunzip -t /tmp/r.sql.gz` 통과 | 명령 결과 |
| 4 | 별도 DB 로 복원 | `RESTORE_DB=itall_restore_test ./ops/restore-db.sh <파일> --yes` | 스크립트가 검증 카운트를 출력하고 종료코드 0 | 카운트 출력 |
| 5 | 데이터 실재 확인 | 4단계 출력의 `accounts`·`bookings`·`credit_accounts` | 셋 다 **0이 아님** | 숫자 3개 |
| 6 | 최신성 확인 | `SELECT max(created_at) FROM booking;` (복원 DB) | 백업 시각과 **1일 이내** 차이 — 오래된 덤프를 복원하고 성공으로 착각하는 것을 막는다 | 시각 |
| 7 | 앱 기동 확인 | 복원 DB 를 `DATABASE_URL` 로 지정해 API 기동 → `/health` | 200 응답 + 로그인 1회 성공 | 응답·캡처 |
| 8 | 정리 | `DROP DATABASE itall_restore_test;` + `/tmp/r.sql.gz` 삭제 | 리허설 DB·복호 파일이 남지 않음 (평문 덤프 방치 = PII 노출) | 확인 메모 |

## 3. 실패 시 대응

| 증상 | 원인 후보 | 조치 |
|---|---|---|
| 1단계 최신 백업이 24h 초과 | 크론 미등록·컨테이너명 변경·디스크 가득 | 크론 확인 → `PG_CONTAINER` ENV 확인 → 디스크 여유 확보 |
| 3단계 복호 실패 | 암구호 불일치·업로드 중 손상 | 암구호 보관처 확인. 손상이면 그 회차 백업 폐기 후 즉시 재백업 |
| 5단계 카운트 0 | 덤프가 빈 DB 를 떴다(마이그레이션 전·잘못된 DB명) | `PGDATABASE` 확인 → 즉시 재백업 후 재리허설 |
| 6단계 시각이 오래됨 | 로테이션이 최신을 지웠거나 백업이 며칠째 실패 | 백업 로그 확인. `KEEP` 값 재검토 |
| 7단계 기동 실패 | 스키마 버전 불일치 | `./ops/migrate.sh status` 로 미적용 마이그레이션 확인 |

## 4. 아직 안 된 것

- **오프사이트(R2) 미개설** — B014·B015 선행. 그때까지 백업은 **같은 기기 로컬에만** 존재한다. 기기 고장·도난 시 전량 소실이라는 뜻이며, 이 상태로 결제·PII 를 받지 않는다.
- **암구호 보관처 미정** — `BACKUP_PASSPHRASE` 를 어디에 두는지 정해야 한다(1Password 등). 암구호를 잃으면 백업 전량이 복호 불가다. 기기와 같은 곳에만 두면 오프사이트의 의미가 없다.
- **크론 미등록** — `backup-db.sh`(03시)·`backup-offsite.sh`(04시) 등록 필요.
