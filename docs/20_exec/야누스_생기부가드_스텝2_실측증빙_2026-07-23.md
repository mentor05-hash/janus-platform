## 1. 접합 지점 (저장 "이전" 가드 호출)

Q&A·상담채팅·화이트보드·성적표 업로드 바이트는 모두 **storage 모듈 초크포인트**로 수렴한다. 이 두 지점 + OCR + 승격 이관부에 가드를 접합했다.

| 경로 | 접합 지점 | 동작 |
|---|---|---|
| Q&A 첨부·채팅 이미지·화이트보드 PNG·성적표 업로드 | `FilesService.upload()` — `storage.put` 이전 | 파일명 + (PDF)텍스트 판정, 감지 시 예외 |
| Q&A/화이트보드 PDF 배경 | `FilesService.rasterizePdf()` — 저장·렌더 이전 | `pdftotext` 추출 → 키워드 판정 |
| 성적표 OCR | `ScoresService.ocr()` — LLM 호출 이전 | 비전 분류(§5 3단, forceVision) — 성적표 허용·생기부 차단 |
| 상담 승격(에스컬레이션) 이관 | `QnaService.filterEscalationAttachments()` | 저장 바이트 재판정, 감지 파일은 이관 목록에서 제외 |

- 공용 판정: `@mentoring/guard-school-record`(스텝1) — 서비스 어댑터 `SchoolRecordGuardService`가 PDF 텍스트 추출(poppler `pdftotext`, stdin→stdout, 임시파일 없음)·정책 해석·비전 어댑터를 담당. 판정 자체는 순수 모듈이 수행(바이트→boolean+사유).
- 차단 응답: `422` + `{ error:{ code:'SR_KEYWORD'|'SR_FILENAME'|'SR_VISION'|'SR_UNSURE', message:<§4-b> } }`.
- 무취급: 추출 텍스트는 지역 스코프에서만 훑고 폐기. 로그는 **사유 코드 + 파일명만**(내용·추출텍스트 무기록).

## 3. E2E — 실 스택(docker full: api+web+postgres+poppler, `LLM_PROVIDER=none`→mock)

로그인 `paid01`(학생), 모의 PDF는 세션에서 직접 생성(한글 TTF 임베드 → `pdftotext` 추출 확인).
`pdftotext` 추출 검증: 생기부 PDF에서 서식 키워드 5종 추출(`학교생활세부사항기록부`·`인적·학적사항`·`창의적 체험활동상황`·`세부능력 및 특기사항`·`행동특성 및 종합의견`), 성적표 PDF는 0종.

### ① 모의 생기부 PDF → 차단 + 미기록
```
POST /api/v1/files/pdf-page  (mock_생기부.pdf)  → HTTP 422
  { "error": { "code": "SR_KEYWORD", "message": "첨부하신 파일에서 학교생활기록부로 판단되는 …
                                                  저장되지 않고 즉시 삭제되었습니다. …" } }
POST /api/v1/files           (mock_생기부.pdf)  → HTTP 422  code=SR_KEYWORD   (제네릭 경로도 차단)
```
미기록 실측: `stored_file` 행 수 **18 → 20**. 통과한 성적표 PDF 1건이 원본+PNG로 정확히 **+2**행 생성 → 차단된 생기부 업로드 2건은 **0행**(가드가 `storage.put`·`stored_file.create` 이전에 예외).
- `SELECT count(*) FROM stored_file WHERE filename LIKE '%생기부%'` → **0**
- `/data/storage/uploads` 신규 파일: 성적표 2건뿐(생기부 흔적 없음)
- API 로그: `WARN SchoolRecordGuardService 생기부 감지·차단: reason=SR_KEYWORD stage=keyword name=mock_…pdf` — **내용·추출텍스트 무기록**(사유코드+파일명만)

### ② 모의 성적통지표 PDF → 정상 통과
```
POST /api/v1/files/pdf-page  (mock_성적표.pdf)  → HTTP 201
  { "data": { "id":"b4be0f12-…", "pdfId":"af94c577-…", "page":1, "pageCount":1 } }   (정상 저장)
```

### ③ 상담 승격 이관 필터
`filterEscalationAttachments([풀이.png, 생기부.pdf])` → `[풀이.png]`(생기부 제외). 승격 시 `booking.createAssigned({ …, attachments })`로 통과분만 상담 예약 payload에 복제. (단위 테스트 실측 — HTTP 승격은 슬롯·답변 선행 필요로 단위 레벨로 검증.)

## 4. 고지 UI 캡처 (실 웹)

- **§4-a 상시 안내** — Q&A 질문작성 "문제 이미지" 영역 하단에 렌더:
  > 📋 **학교생활기록부(생기부)는 업로드할 수 없습니다.** 관련 법령(제25조의2, 2026. 7. 29. 시행)에 따라 학생 동의가 있어도 생활기록부를 제공받을 수 없으며, 포함된 파일은 자동 차단·삭제되고 저장되지 않습니다.
  - 삽입 위치(6곳): `StudentQnaPage`(Q&A) · `ChatPanel`/`RoomChatPanel`(상담 채팅) · `WhiteboardPanel`/`RoomWhiteboardPanel`(화이트보드 배경) · `AdminScoresPage`(성적표 OCR). 단일 출처 컴포넌트 `SchoolRecordUploadNotice`.
- **§4-b 차단 모달** — api 클라이언트가 SR_* 응답 시 전역 이벤트(`janus:school-record-blocked`) 발생 → 앱 루트 `SchoolRecordBlockModal` 렌더(§4-b 전문 + ①직접입력/②성적표 대안 + 문의 경로). SR_UNSURE는 이의 경로 강조.
  - HTTP E2E(§3-①)에서 실제 422 SR_KEYWORD 응답을 확인했고, 모달은 동일 이벤트로 실 컴포넌트 렌더를 캡처.
