# 야누스 고정 주소 배포 계획 (2026-08-06)

> 지금의 체험 링크는 cloudflared **quick tunnel** — 맥이 켜져 있고 프로세스가 살아있는 동안만 유효하고,
> 재실행할 때마다 주소가 바뀐다. 이걸 고정 주소로 올리는 세 갈래를 비교하고, 각각의 전제·비용·소요·산출물을 정리한다.
> ⚠ **이 계획은 §2-0·§3 까지 실행 완료(2026-08-08)** — 도메인 `ianuspath.com` 확보 후 A안(명명된 터널)
> 개통. 운영 정보는 `docs/접속_주소_정리.md`. 아래는 결정 근거와 남은 경로(B·C안) 참고용으로 유지한다.
>
> 전제(작성 시점): **도메인 미보유**(2026-08-06 — Cloudflare 유료 플랜은 있으나 등록 도메인 없음).
> 고정 호스트명은 **자기 도메인이 있어야** 만들어진다 — §2-0 이 첫 관문이다.
> 계정 가입·도메인 구매·결제는 사람이 직접 한다(대행 불가).

## 0. 요약 — 권장

**①도메인 확보 → ②A안(명명된 터널) → 필요해지면 B안.** 도메인만 생기면 A안은 30분이고 인프라 비용이 0원이며,
지금 스택을 한 줄도 안 고친다. "맥이 켜져 있어야 한다"가 견딜 수 있는 제약인지가 그다음 갈림길이다.

도메인을 지금 사고 싶지 않다면 **Tailscale Funnel**로 도메인 없이 고정 주소를 얻는 우회로가 있다(§2-0-B).
주소 모양이 `janus-mac.<테일넷>.ts.net` 처럼 길고 브랜드가 안 실리지만, 무료이고 오늘 바로 된다.

- 보여줄 상대가 정해져 있고 약속 잡고 보는 데모 → **A안으로 충분**
- 아무 때나 눌러볼 수 있어야 함(투자자·제휴사에 링크 뿌림) → **B안**
- 실제 회원이 가입해서 쓰기 시작 → **C안**(그때는 데모 링크가 아니라 서비스다)

⚠ 어느 경로든 **고정·기억하기 쉬운 주소 + 원터치 마스터관리자 로그인**의 조합은 지금의 임시 난수 주소보다 훨씬 위험하다.
§6-1의 접근 게이트 결정을 먼저 하고 주소를 올릴 것.

## 1. 지금 상태 — 무엇이 고정이 아닌가

| 구성 | 지금 | 고정 주소에서 달라지는 점 |
|---|---|---|
| 웹 콘솔 :8080 | quick tunnel(난수 주소) | 고정 호스트명 |
| 모바일 웹 :8090 | 별도 quick tunnel | 서브도메인 하나로 |
| 실시간 룸 :3100 | 별도 quick tunnel + `ROOMS_PUBLIC_URL` 매번 주입 | 고정 → `.env` 에 영구 기재 |
| API :3000 | web/mobile nginx 가 `/api` 프록시(터널 불필요) | 동일 — 그대로 |
| DB·데이터 | 맥의 docker 볼륨(`janus-platform_pgdata`), 데모 16계정 | A안 동일 / B·C안은 이전 필요 |
| 배치표 데이터 | 맥의 `20_data/placement-hub` 읽기전용 마운트 | A안 동일 / B·C안은 §6-3 참조 |

터널 3개를 따로 띄우는 지금 방식은 명명된 터널 하나의 **ingress 규칙**으로 합쳐진다 — 프로세스도 1개로 준다.

## 2-0. 첫 관문 — 고정 호스트명을 어디서 얻나

**Cloudflare 유료 플랜을 결제해도 도메인은 안 따라온다.** Cloudflare 의 유료 상품(Pro·Workers Paid·Zero Trust 등)은
"내 도메인에 얹는 기능"이지 도메인 자체가 아니다. `cloudflared tunnel route dns` 는 **내 계정에 등록된 zone(도메인)**
에만 레코드를 만들 수 있어서, 도메인 없이는 A안·B안·C안 전부 시작이 안 된다.

### A. 도메인 구매 (권장 — 브랜드 주소)
| 경로 | 특징 |
|---|---|
| **Cloudflare Registrar** | 원가 판매(마크업 없음, `.com` 연 $10 내외). **등록 즉시 내 계정 zone 이 되므로 네임서버 이전 절차가 없다** — 이미 Cloudflare 를 쓰는 지금 가장 마찰이 적다. `.kr`·`.co.kr` 은 취급하지 않는다 |
| 국내 등록기관(가비아·후이즈 등) | `.kr` 계열 가능. 대신 구매 후 **네임서버를 Cloudflare 로 변경**하는 단계가 추가된다(전파 수 시간) |

> 이름 후보를 정할 때: 데모는 `demo.<도메인>` 서브도메인으로 붙일 것이므로 apex 는 나중에 마케팅/랜딩에 쓸 수 있게 남겨둔다.
> 구매·결제는 직접 하셔야 한다 — 도메인이 생기면 §3 절차가 그대로 돌아간다.

### B. 도메인 없이 — Tailscale Funnel (우회로)
Tailscale 계정을 만들면 `<머신>.<테일넷>.ts.net` 형태의 **고정 HTTPS 주소**를 무료로 준다. 인증서도 자동.
```bash
brew install tailscale && sudo tailscale up      # 계정 로그인(직접)
tailscale funnel --bg 8080                       # 웹 콘솔을 공개 고정 주소로
```
- 장점: 도메인·비용 0, 오늘 바로. 맥에서 서빙하는 건 A안과 동일
- 단점: 주소가 길고 브랜드가 안 실림 · 포트마다 경로/주소 배분 규칙이 Cloudflare ingress 보다 뻣뻣함 ·
  Cloudflare Access(§6-1) 대신 Tailscale 쪽 접근제어를 따로 봐야 함
- **결과(2026-08-08): 실제로 이 경로로 먼저 띄웠고, 도메인 확보 후 철거했다.** 기록만 남긴다 —
  도메인이 없거나 급할 때 30분이면 되는 우회로라는 점은 유효하다.

### C. 못 쓰는 것 — 오해 방지
- `*.trycloudflare.com`(지금 쓰는 quick tunnel): 고정 불가. 실행할 때마다 난수
- `*.workers.dev` / `*.pages.dev`: 고정 주소는 맞지만 **엣지에서 도는 정적·서버리스 전용** — 맥의 docker 스택(API·DB·WebSocket)을 여기에 못 얹는다. 프런트만 올리고 API 는 따로 공개해야 하는데, 그러면 API 쪽에 결국 도메인이 필요하다
- DuckDNS 같은 무료 서브도메인: 남의 도메인의 서브도메인이라 Cloudflare zone 으로 등록할 수 없다 → 명명된 터널에 못 씀

## 3. A안 — 명명된 터널 (도메인 확보 후 30분)

quick tunnel 과 달리 **계정에 등록된 터널**이라 주소가 고정되고, 하나의 터널이 여러 호스트명을 나눠 받는다.

### 3-1. 호스트명 설계
| 호스트명 | 대상 | 비고 |
|---|---|---|
| `demo.<도메인>` | localhost:8080 | 웹 콘솔 — 체험 입구 `/demo` 가 여기 |
| `m.demo.<도메인>` | localhost:8090 | 모바일 웹(학생·학부모) |
| `rooms.demo.<도메인>` | localhost:3100 | 실시간 룸(WebSocket) |

### 3-2. 절차
```bash
cloudflared tunnel login                      # 브라우저에서 도메인 선택 → 인증서 저장
cloudflared tunnel create janus-demo          # 터널 생성 → UUID·자격증명 json 발급
cloudflared tunnel route dns janus-demo demo.<도메인>
cloudflared tunnel route dns janus-demo m.demo.<도메인>
cloudflared tunnel route dns janus-demo rooms.demo.<도메인>
```

`~/.cloudflared/config.yml`:
```yaml
tunnel: janus-demo
credentials-file: /Users/mentor05daum.net/.cloudflared/<UUID>.json
ingress:
  - hostname: demo.<도메인>
    service: http://localhost:8080
  - hostname: m.demo.<도메인>
    service: http://localhost:8090
  - hostname: rooms.demo.<도메인>
    service: http://localhost:3100
  - service: http_status:404          # 매칭 안 되면 404 (필수 — 마지막 규칙)
```

```bash
cloudflared tunnel run janus-demo     # 확인용 포그라운드 실행
```

### 3-3. 룸 주소 영구 기재
주소가 고정되므로 매번 주입하던 걸 루트 `.env` 로 옮긴다:
```
ROOMS_PUBLIC_URL=https://rooms.demo.<도메인>
```
→ `docker compose -f docker-compose.full.yml up -d api` 만 하면 반영. `ops/demo-public-link.sh` 의
터널 개통 단계는 A안 적용 후 불필요해진다(스택 기동 + 프런트 최신화 단계만 남김).

### 3-4. 자동 시작(launchd)
맥 재부팅·로그인 후 터널이 저절로 살아나게. `~/Library/LaunchAgents/com.janus.tunnel.plist`:
```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>com.janus.tunnel</string>
  <key>ProgramArguments</key>
  <array>
    <string>/opt/homebrew/bin/cloudflared</string>
    <string>tunnel</string><string>run</string><string>janus-demo</string>
  </array>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
  <key>StandardOutPath</key><string>/tmp/janus-tunnel.log</string>
  <key>StandardErrorPath</key><string>/tmp/janus-tunnel.err</string>
</dict></plist>
```
```bash
launchctl load ~/Library/LaunchAgents/com.janus.tunnel.plist
```
docker 스택도 같이 살아나야 하므로 Docker Desktop 의 "로그인 시 시작" + compose `restart: unless-stopped` 를 같이 건다.

### 3-5. 남는 제약
- **맥이 자거나 꺼지면 링크가 죽는다.** `caffeinate -dims` 로 잠자기를 막을 수 있으나 노트북 상시 가동은 현실적이지 않다.
- 맥의 업로드 대역폭·네트워크 상태가 그대로 체감 속도가 된다.
- 저작권 데이터는 맥 밖으로 안 나간다(§6-3 부담 없음) — A안의 큰 장점.

## 4. B안 — 클라우드 VM 상시 데모

지금 compose 스택을 VM 1대에 그대로 올린다. **코드·이미지 변경 없음**, 데모 데이터·데모 모드 유지.

### 4-1. 사양·비용 감각
- api·web·mobile·rooms·postgres·redis 6컨테이너 → **2 vCPU / 4GB RAM / 40GB SSD** 이상 권장
- 후보: Hetzner CX22급(월 €4~5) · AWS Lightsail(월 $10~12) · Oracle Cloud Always Free(무료지만 가용성·리전 제약)
- 리전은 한국 접속이면 서울/도쿄. Hetzner 는 유럽뿐이라 체감 지연이 붙는다 — 데모 용도면 감수 가능.

### 4-2. 절차 개요
1. VM 생성 → docker·docker compose 설치, ssh 키만 허용(비밀번호 로그인 차단)
2. repo 배포(private repo deploy key 또는 이미지 레지스트리 푸시)
3. `.env` 작성 — **`JWT_SECRET`·`JWT_REFRESH_SECRET`·`ROOMS_JWT_SECRET`·`ROOMS_API_KEY`·DB 비밀번호를 로컬 상수에서 교체**
   (`openssl rand -hex 32`). 로컬 `dev-*-please-change` 값을 그대로 올리면 안 된다.
4. 데모 시드 이관 — 로컬 `ops/backup-db.sh` → VM 에서 `ops/restore-db.sh`
5. 프런트 빌드: 데모 유지면 `VITE_DEMO_MODE=true` / `EXPO_PUBLIC_DEMO_MODE=true` 로 빌드
6. 공개: VM 에도 cloudflared 를 띄워 A안과 같은 터널 구성(포트를 인터넷에 직접 노출하지 않는 게 안전)
   또는 VM 앞에 nginx + Let's Encrypt. **터널 방식 권장** — 방화벽에 인바운드 구멍이 안 뚫린다.
7. 백업: `ops/backup-db.sh` 를 cron 에 걸고 VM 스냅샷 주기 설정

### 4-3. 결정해야 할 것
- **저작권 데이터를 VM 에 올릴 것인가**(§6-3). 안 올리면 배치표 허브는 '준비 중'으로 보인다.
- 데모 DB 를 아무나 쓰게 둘 것인가 — 상시 공개면 낙서·스팸이 쌓인다. 주기적 리셋(주 1회 시드 복원) 권장.

## 5. C안 — 프로덕션 배포

이미 문서가 있다. 새로 쓸 게 아니라 그 체크리스트를 실행하는 일이다.
- 절차: [ops/DEPLOY.md](../../ops/DEPLOY.md) — provider 스위치(PG·스토리지·Zoom·LLM), 마이그레이션 러너, 헬스체크
- 출시 차단 항목: [docs/백엔드_프로덕션_준비.md](../백엔드_프로덕션_준비.md) — HTTPS 고정 도메인, 데모 모드 차단,
  JWT 시크릿 교체, 관리형 PostgreSQL, CORS 제한, 푸시 자격증명, 법무(방침·탈퇴·환불)

**여기서는 체험 링크의 '원터치 로그인'이 사라진다**(`VITE_DEMO_MODE` 미설정이 출시 차단 항목). 데모와 실서비스를
같은 주소에 둘 수 없으므로, C안으로 갈 때도 **데모는 별도 호스트명으로 A/B안을 유지**하는 구성이 현실적이다.

## 6. 공통 선결 과제 (경로 무관)

### 6-1. 접근 게이트 — 고정 주소로 올리기 **전에** 결정
난수 주소가 사라지면 "아무도 모를 것"이라는 방어가 없어진다. `/demo` 는 마스터관리자까지 원터치로 내준다.

| 안 | 내용 | 평가 |
|---|---|---|
| **Cloudflare Access** | Zero Trust → Access → Self-hosted 앱으로 `demo.*` 를 감싸고 이메일 허용목록 또는 일회용 PIN | **권장.** 50명까지 무료. 링크는 공유하되 아는 사람만 통과. 앱 코드 변경 0 |
| `/demo` 로스터 축소 | 카드에서 `master01`·`hq01`·`admin01` 제거, 학생·학부모·선생님만 | 간단하지만 관리자 화면 시연이 막힌다 |
| 그대로 | 방어 없음 | 짧은 시연 후 바로 닫는 경우만 |

> Access 적용 시 확인할 것: 모바일 호스트(`m.demo.*`)에서 같은 출처 `/api` 요청이 `CF_Authorization` 쿠키를
> 물고 가는지, 룸 WebSocket(`rooms.demo.*`)이 Access 뒤에서 붙는지 — 개통 후 1회 실측 필요.

### 6-2. 시크릿 교체
지금 스택은 전부 로컬 상수다 — `dev-jwt-secret-please-change`, `dev-refresh-secret-please-change`,
`dev-rooms-secret-change`, `dev-rooms-api-key`, DB `janus_local_pw`. A안(맥에서 서빙)이라도 주소가 고정·상시가 되면
교체하는 게 맞다. B·C안은 필수.

### 6-3. 저작권 데이터 이전 (B·C안에서만 발생)
CLAUDE.md §4 — `20_data` 는 로컬 전용, git remote 금지. VM 으로 옮기려면:
- **git 경유 금지.** `rsync -avz -e ssh` 로 `placement-hub/` 하위만 전송(지금 컨테이너에 붙이는 범위와 동일)
- VM 디스크 암호화·접근 통제 확인, 스냅샷도 같은 등급으로 취급
- 옮기지 않는 선택지도 유효 — 허브는 '준비 중'으로 두고 나머지 기능만 데모

### 6-4. 씬-슬라이스 데이터 미비 (기존 숙제)
`placement-hub/slices/` 에 `jeongsi-2027.json`(4행 샘플) 하나뿐이라 허브 검색 탭이 항상 비어 있고,
실열람이 전체표(티켓) 경로로만 이뤄진다. O76 이 설계한 "전체 파일 대신 검색 행만" 방어가 데이터 미비로
작동하지 않는 상태 — **상시 공개(B안) 전에는 반드시 채워야 한다.** 데이터 트랙 과제.
